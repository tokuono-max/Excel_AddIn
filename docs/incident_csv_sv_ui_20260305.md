# 不具合事例記録：CSV保存(svc_csv_sv) UI 周り

**対象機能**: CSV保存（Qt UI サーバ方式）  
**記録日**: 2026-03-05  
**目的**: 複数発生した不具合の事象・メカニズム・修正方法を記録し、今後の開発に活用する。

---

## 不具合事例一覧

### 事例1：保存画面が常に Excel の前面に表示されない／Excel と親子関係にない

| 項目 | 内容 |
|------|------|
| **１．不具合事象** | 「名前を付けてCSVを保存」ダイアログが、Excel の背面に隠れたり、タスクバーで Excel と別扱いになったりする。Excel を操作している最中に保存ダイアログが他のウィンドウの裏に回ってしまう。 |
| **２．不具合のメカニズム** | 保存ダイアログを `QFileDialog.getSaveFileName(None, ...)` で表示しており、親ウィジェットを渡していなかった。このため OS 上で Excel とのオーナー／親子関係がなく、Z オーダーやタスクバーが Excel と連動しない。 |
| **３．不具合修正方法** | csv_ld と同様に、Excel の HWND をオーナーにした `QWidget` を `_set_owner_hwnd` で作成し、`getSaveFileName(parent_widget, ...)` の親に渡すように変更。これによりダイアログが Excel の子となり、前面表示・タスクバーが Excel にまとまる。 |

### 事例2：保存画面のタイトルにアイコンがない

| 項目 | 内容 |
|------|------|
| **１．不具合事象** | 保存ダイアログのタイトルバーにアプリケーションアイコンが表示されない。CSV読込で発生したのと同じ事象。 |
| **２．不具合のメカニズム** | 親を渡していない（`None`）ため、ネイティブの保存ダイアログが Excel と紐付かず、タイトルバーに Excel のアイコンが継承されない。 |
| **３．不具合修正方法** | 事例1と同一の対応。Excel をオーナーにした `QWidget` を親に渡すことで、ネイティブダイアログが Excel の子となり、タイトルバーに Excel のアイコンが表示される。 |

### 事例3：保存画面表示中に Excel の操作が無効になっていない

| 項目 | 内容 |
|------|------|
| **１．不具合事象** | 保存先選択ダイアログを出しているあいだ、Excel のセル編集やクリックなどができてしまう。キャンセル時にも操作を有効に戻す必要がある。 |
| **２．不具合のメカニズム** | 保存ダイアログ表示中に Excel の子ウィンドウを `EnableWindow(False)` する処理がなく、csv_ld のファイル選択で実施している `enable_excel_window` によるロックを csv_sv では行っていなかった。 |
| **３．不具合修正方法** | ダイアログ表示直前に `enable_excel_window(ph, False)` を呼び、`getSaveFileName` を `try` で囲み、`finally` 内で `enable_excel_window(ph, True)` を呼ぶようにした。OK／キャンセルいずれでも Excel を必ず有効に戻す。 |

### 事例4：保存時の初期フォルダが直近で使ったフォルダにならない

| 項目 | 内容 |
|------|------|
| **１．不具合事象** | ファイル読込やファイル保存で直近使ったフォルダを「基準フォルダ」として、次回の保存時にも最初に開くフォルダにしたいが、そのような仕組みがなく、毎回既定の場所から開いていた。 |
| **２．不具合のメカニズム** | 保存ダイアログの初期ディレクトリを保存する／読み出す仕組みがなく、`getSaveFileName` には初期ディレクトリを渡していなかった。csv_ld と csv_sv で「直近フォルダ」を共有する共通の仕組みも未整備だった。 |
| **３．不具合修正方法** | `ipc_file` に `get_last_folder()` / `set_last_folder(dir_path)` を追加し、IPC ルート配下の `last_folder.txt` に直近フォルダを保存。csv_sv のリクエストに `initial_dir`: `get_last_folder()` を付け、保存完了時に `set_last_folder(os.path.dirname(path))` で更新。csv_ld も同様に `initial_dir` を渡し、ファイル選択後に `set_last_folder` で更新し、両機能で基準フォルダを共有。 |

### 事例5：進捗バーの分母が総数でない（工程ごとに 100% になる）

| 項目 | 内容 |
|------|------|
| **１．不具合事象** | 進捗表示で「データ読込中」が 100%、続く「ファイル保存中」も 100% となり、全体の進み具合が分かりにくい。分母を総行数にした一続きの進捗にしたい。 |
| **２．不具合のメカニズム** | 工程1（データ読込）では `done`/`total` を 0 や読込行数で更新し、工程2（ファイル保存）では `done`/`total` を保存行数で 100% にしていた。このため工程ごとに「その工程内の 100%」となり、全体としての総数（分母）が統一されていなかった。 |
| **３．不具合修正方法** | 進捗の `total` を常に総行数（`val_total`）に統一。工程1では `done` = 読込済み行数、`pct` = 0～50%（読込完了で 50%）。工程2では `done`/`total` = 総行数、`pct` = 50 から完了時に 100。`_read_matrix_safe` 内の進捗更新でも `pct` を `min(50, int(done*50/total_rows))` とし、全体を 0→50→100% の1本のバーで表示するようにした。 |

### 事例6：保存終了（進捗画面閉じ）時に Excel に戻り操作有効にされない

| 項目 | 内容 |
|------|------|
| **１．不具合事象** | 進捗画面を表示している間や、完了後に進捗画面を閉じたあとでも、Excel が操作できない状態のままになる、または意図どおり有効に戻らない。 |
| **２．不具合のメカニズム** | 進捗ダイアログ表示時に Excel を無効化する `excel_lock` を csv_sv では指定しておらず、また進捗ダイアログの `closeEvent` や `_close_after_done` で `enable_excel_window(True)` が呼ばれるのは `excel_lock` が True のときのみ。csv_sv は `excel_lock` を渡していなかったため、閉じたあとの Excel 再有効化が行われていなかった（あるいは、進捗表示中に Excel を無効化したい場合に無効化されていなかった）。 |
| **３．不具合修正方法** | 進捗 UI のリクエスト `req_dict` に `"excel_lock": True` を追加。`ProgressDialog` は既存仕様で、`excel_lock` が True のとき表示時に `enable_excel_window(False)`、閉じる際（ユーザー閉じ／完了後閉じ）に `enable_excel_window(True)` を実行するため、進捗画面を閉じると同時に Excel が操作可能になる。 |

### 事例7：進捗画面が他アプリの前面に表示される

| 項目 | 内容 |
|------|------|
| **１．不具合事象** | 進捗画面が「常に最前面」となり、他のアプリ（ブラウザやメールなど）の上にも表示されてしまう。前面表示は Excel の前だけでよい。 |
| **２．不具合のメカニズム** | `config/ui_csv_sv.json` の `SCREENS.PROGRESS.WINDOW.TOPMOST` が `true` のため、`ProgressDialog` に `Qt.WindowStaysOnTopHint` が付与され、すべてのアプリの前面に表示されていた。 |
| **３．不具合修正方法** | `ui_csv_sv.json` の `SCREENS.PROGRESS.WINDOW.TOPMOST` を **false** に変更。これにより最前面ヒントは付かず、進捗画面は Excel を親にした表示・中央配置のまま Excel の前には出るが、他アプリに切り替えた場合はその背後に回る。 |

### 事例8：進捗画面が Excel の中央から右にずれて表示される

| 項目 | 内容 |
|------|------|
| **１．不具合事象** | 進捗画面が Excel ウィンドウの中央ではなく、右にずれた位置に表示される。以前は中央に表示されていた。また、表示後に中央へ移動する様子が目立ち、気になる。 |
| **２．不具合のメカニズム** | (1) **座標系の混在**: Excel の矩形は Win32 `GetWindowRect`（物理ピクセル）、Qt の `move()` は論理ピクセル。マルチモニタや DPI スケールで解釈が異なり右にずれる。(2) **プロセス間の DPI 認識差**: Excel と自プロセスで DPI 認識が異なると、`GetWindowRect` と `SetWindowPos` の座標解釈が揃わない。(3) **枠サイズ**: トップレベルでは `move()` が枠の左上基準なのに、中央計算で `width()`/`height()`（クライアント）を使っていたためずれが生じた。(4) **×ボタン非表示**: SHOW_CLOSE_BUTTON: false で枠の見た目が変わり、ずれが目立った可能性。 |
| **３．不具合修正方法** | (1) **物理ピクセル統一**: `center_on_rect` でダイアログの HWND が取れるときは、`GetWindowRect` で実サイズを取得し、`SetWindowPos` で配置。Qt の `move()` は使わず Win32 のみで座標を統一。(2) **DPI コンテキスト**: `center_on_excel` 実行時に `SetThreadDpiAwarenessContext(PER_MONITOR_AWARE_V2)` でスレッドを物理ピクセルに合わせ、Excel 矩形取得・配置をその中で実行。マルチモニタ＋混在 DPI でずれ防止。(3) **移動が見えないように**: CENTER_ON_EXCEL が true の進捗は、初回 `setWindowOpacity(0)` で透明表示→表示後 150ms で `center_on_excel`→`setWindowOpacity(1)` で不透明化。ユーザーには中央にいきなり表示されたように見える。 |

## 今後の開発への活用ポイント

- **ファイルダイアログの親子・前面・アイコン**: 保存／読込どちらも、Excel をオーナーにした `QWidget` を `_set_owner_hwnd` で作り、`getSaveFileName` / `getOpenFileName` の親に渡すと、Excel の前面・タスクバー連動・タイトルバーアイコンが期待どおりになる。
- **ファイルダイアログ表示中の Excel ロック**: 表示前に `enable_excel_window(ph, False)`、`finally` で `enable_excel_window(ph, True)` を必ず実行する。
- **基準フォルダの共有**: 読込・保存で「直近使ったフォルダ」を共有する場合は、IPC 配下のファイルなどに保存し、`initial_dir` としてダイアログに渡す。選択／保存後にそのフォルダを更新する。
- **進捗の分母の統一**: 複数工程でも分母を総数（総行数など）に揃え、pct で 0～50～100% のように一続きのバーにすると分かりやすい。
- **進捗閉じ時の Excel 再有効化**: 進捗表示中に Excel を無効にしている場合は、進捗リクエストに `excel_lock: True` を付け、閉じたときに確実に `enable_excel_window(True)` が呼ばれるようにする。
- **TOPMOST の使い分け**: 前面表示を「Excel の前だけ」にしたい場合は `TOPMOST: false` とし、他アプリの上には出さないようにする。
- **進捗の Excel 中央表示**: マルチモニタ・DPI 混在では Win32 の座標と Qt の論理ピクセルがずれる。`SetThreadDpiAwarenessContext(PER_MONITOR_AWARE_V2)` で物理ピクセルに揃え、`GetWindowRect`＋`SetWindowPos` で配置。中央へ「移動する瞬間」が気になる場合は、初回は opacity 0 で表示し、配置後に opacity 1 にすると見え方でごまかせる。
