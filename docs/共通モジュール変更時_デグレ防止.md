# 共通モジュール変更時のデグレ防止

**対象**: 共通モジュール（ui_common, core_cst, ipc_file, ui_win 等）の変更・追加時  
**作成日**: 2026-03-06  
**目的**: 共通モジュールを変更した際に、他機能・他モジュールへ影響がないかを確認する手順を明文化し、デグレを防止する。

---

## 1. 共通モジュールの変更時に行うこと

**共通モジュールに変更や追加を加えた場合は、他モジュールで問題が起きていないかの確認が必須である。**

- 変更後、**本ドキュメントの「確認対象一覧」**に従い、影響し得るモジュール・機能の動作を確認する。
- 必要に応じて、該当機能の仕様書・検証手順（verification_*.md）に沿ってテストする。
- 不具合事例（incident_*.md）で類似事象が報告されていないかも参照する。

---

## 2. 共通モジュールと主な利用先

以下のモジュールは複数機能から参照されるため、変更時は**確認対象一覧**で列挙したモジュールの動作確認を行うこと。

| 共通モジュール | 主な役割 | 主な利用先 |
|----------------|----------|------------|
| **ui_qt.ui_common** | ウィンドウ設定適用（apply_window_config）、進捗ダイアログ（create_progress_dialog）、オーナー設定（_set_owner_hwnd）、設定読込（_get_*_config）等 | ui_csv_ld, ui_csv_sv, ui_csv_sp, ui_csv_mg, ui_dupli, ui_row_dl, ui_col_dl, ui_dt_ymd, ui_dt_hm |
| **core.core_cst** | 設定ファイル読込（get_ui_config_from_file_required） | 各 ui_*.py（csv_ld, csv_sv, csv_sp, csv_mg, dupli, row_dl, col_dl, dt_ymd, dt_hm） |
| **ui_qt.ipc_file** | IPC 用 pickle の読込・書込（read_pickle, write_pickle）、パス取得（get_request_dir, get_ipc_root 等） | ui_server, svc_csv_ld, svc_csv_sv, svc_csv_sp, svc_csv_mg, svc_dupli, svc_row_dl, svc_col_dl, svc_dt_ymd, svc_dt_hm |
| **ui_qt.ui_win** | Excel ウィンドウの有効/無効（enable_excel_window）、前面表示等 | ui_csv_ld, ui_csv_sv, ui_csv_sp, ui_csv_mg, ui_dupli, ui_row_dl, ui_col_dl, ui_dt_ymd, ui_dt_hm |
| **ui_qt.ui_server** | リクエスト受付・create_dialog のディスパッチ・結果返却 | 全 UI 機能（csv_ld, csv_sv, csv_sp, csv_mg, dupli, row_dl, col_dl, dt_ymd, dt_hm） |
| **svc.svc_host** | UI サーバ起動（ensure_ui_server） | 各 svc_csv_*.py, svc_dupli, svc_row_dl, svc_col_dl, svc_dt_ymd, svc_dt_hm |

## 3. 確認対象一覧（デグレ確認チェックリスト）

共通モジュールを変更した場合、以下を最低限確認する。

| 変更した共通モジュール | 確認対象（動作確認を推奨する機能） |
|------------------------|------------------------------------|
| **ui_common** | CSV読込（csv_ld）・CSV保存（csv_sv）・CSV分割（csv_sp）・CSV結合（csv_mg）・重複チェック（dupli）・空白行削除（row_dl）・空白列削除（col_dl）・日付変換（dt_ymd）・日付・時刻変換（dt_hm）の各画面表示・進捗・完了・ワーニング。ウィンドウの親子関係・タスクバー・中央配置・枠残り。 |
| **core_cst** | 各機能の画面を開く操作（設定読込が行われるため）。設定ファイル削除・不正 JSON 時のエラー表示。 |
| **ipc_file** | 各機能の UI サーバ経由の画面表示・結果のやり取り（ファイル選択・保存先・分割結果等）。進捗のポーリング。 |
| **ui_win** | 各画面表示中の Excel 操作の無効/有効。画面を閉じた後の Excel 操作の復帰。 |
| **ui_server** | 各機能のリクエスト処理（create_dialog の呼び分け・結果の返し方）。モーダル/モデルレスの違い。重複チェック（dupli）・空白行削除（row_dl）・空白列削除（col_dl）・日付変換（dt_ymd）・日付・時刻変換（dt_hm）の進捗・完了表示。 |
| **svc_host** | 各機能の初回起動時（UI サーバの起動）。 |

- 上記の「確認対象」は、**その共通モジュールを参照しているすべての呼び出し元**を意識して確認する。
- 不具合事例（**docs/incident_csv_ld_ui_20260305.md**, **docs/incident_csv_sv_ui_20260305.md** 等）に記載された事象が再発していないかもあわせて確認する。

---

## 4. 確認の記録

- 共通モジュールを変更した際は、**どのモジュールを変更したか**と**確認した機能・結果**を、コミットメッセージやチケット・仕様書の「変更履歴」等に残すことを推奨する。
- 不具合が再発した場合は、**不具合事例**（incident_*.md）に追記する。

---

## 5. 表示フォーマット変更時の注意（デグレ防止）

**セルやラベルに「表示用フォーマット」（桁区切りカンマ、日付書式等）を入れた場合、その値をあとから読み取って数値・日付に戻す処理を必ず合わせて修正する。**

- **事例**: 分割画面の「分割開始行・終了行」を桁区切り（`1,234`）で表示するようにしたが、範囲を集計する `_collect_ranges_from_table()` で `int(cell.text())` のままにしていたため、1000行以上で `ValueError` となり「有効な分割範囲がありません」となるデグレが発生した。
- **対策**: 表示にフォーマットをかけた場合、**その値を読み取るすべての箇所**で、フォーマットを外してから解析する（例: `.replace(",", "")` のうえで `int()`）。表示を変えたら「どこでその値を読んでいるか」を検索し、読取側を必ず修正する。
- **確認**: 同様のパターン（`setText` で書式付き表示 → 別処理で `.text()` を取得して数値化）が他にないか、grep 等で確認する。
