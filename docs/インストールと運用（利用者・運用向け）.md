## 0. 製品方針（決定・2026-04-18）

**付録 A**（旧 `UpDate.md`）のたたき台と突き合わせ、**第1版の前提**として次を決定した。

| 項目 | 決定内容 |
|------|-----------|
| **インストールの優先** | **薄いインストーラ**を **第1版で優先**（メール配布・共有の `current` 等からローカル `{app}` へ取り込む。早期検証）。**`installer\CSV_Tool.iss`** のように **ステージングを丸ごと `{app}` へ展開する形**は **後続または併用**（ビルド検証・別経路の配布用）。 |
| **ユーザー環境（配布既定）** | インストール完了時に **`HKCU\Environment`** へ **`HC_INSTALL_ROOT`**（**ユーザーが確定した `{app}` の絶対パス**。既定パスから変更されても追従。§1.3）と **`HC_PACKAGED_DEPLOYMENT=1`** を書く。通常起動の Excel で **環境変数経由の配布モード**が既定になる（§1.4）。 |
| **アンインストール** | インストール時に書き込んだ **`HC_INSTALL_ROOT` / `HC_PACKAGED_DEPLOYMENT` を `HKCU\Environment` から削除**する（Inno の **`[Registry]`** で `uninsdeletevalue` 等。値の除去＝当該レジストリエントリの削除。§1.3）。 |
| **更新カタログ（第1版）** | 共有側の案内ファイルは **`catalog.json` のみ**を正とする（§4）。`version.txt` 単体のみの最小運用は第1版では採用しない。 |
| **ローカル版（いま入っている版）** | **`{app}\VERSION.txt` を第一**とする。無い・読めないとき **Inno が登録するアンインストール情報の `DisplayVersion` 等（レジストリ）をフォールバック**する。優先順位は実装で固定し、ブレないようにする。 |
| **「後で」（通知のスヌーズ）** | **永続スヌーズは行わない**（日時・回数をレジストリや `%AppData%` に保存しない）。「後で」は **当該セッションでダイアログを閉じる**程度とし、**次回アドイン起動時やリボンからの手動チェック**で再度 `catalog.json` と比較する。 |
| **版チェックの実装** | **Python（`hc_main`）中心**。`catalog.json` の取得・版比較・通知判定は **同一モジュール／関数**に寄せ、**アドイン起動時**と**リボンからの明示実行**の両方から呼ぶ（**付録 A** F-2 と整合）。 |
| **更新適用の分離** | **初回は `bin + config + bootstrap` をインストーラで一括導入**。以後は **`config` をサイレント更新（失敗時のみ通知）**、**`bin` は UI で「今すぐ／後で」**を選ばせる。`bin` の「今すぐ」は **Excel 終了後に適用**。 |
| **正本の管理単位** | 配置先 `{app}` は 1 本のままにしつつ、**共有正本と更新パッケージは `bin` / `config` を分離管理**する（§2・§4.2）。 |

### 0.1 インストール・版情報の要約（運用イメージ）

**薄いインストーラの目標形** … **（フォルダまたは URL から）本体アーカイブを取得 → インストール先 `{app}` に展開 → `HKCU\Environment` の `HC_*` と `xlwings.conf` 等**、という流れで問題ない。

**現状の実装（`installer\CSV_Tool_Setup.iss`）** … コンパイル時に固定した **`SHAREPAYLOAD`（配布ルート）**にある **`catalog.json`** を読み、**`bin.full` / `config.payload` / `bootstrap.full`** が指す zip を順に展開して `{app}` へ導入する。**`HKCU\Environment` に `HC_DEPLOY_ROOT` も書く**（§1.5）。`catalog.json` が取得できない場合や、いずれかの payload 解決に失敗した場合は通知してインストールを中断する。**各 zip の参照一覧**は **§4.0.1**。

**バージョンアップ通知** … **`core.packaged_update`** が **アドイン起動時**（配布モード時）と **リボン「更新確認」**（`RunPython`）で **`catalog.json` と `{app}\VERSION.txt` を照合**し、**新しい版があれば通知**する。**`config`** はサイレント適用。**`bin`** は「今すぐ」選択時、**すべての Excel 終了後**に **バックグラウンド**で反映する。**`catalog.bin.patch`**（`release\diff.bat` が生成する差分 zip）が **インストール版と `from_min_version` / `from_max_version` の範囲**に合えば優先し、`manifest.json`（`bsdiff4-manifest-v1`）がある場合は **bsdiff 展開 → マージ適用**、無い場合は **従来マージ**で後方互換を維持する。patch が使えない／失敗時は **`catalog.bin.full`** のフル zip（`release\pack.bat` / `release\full.bat` のレイアウト: **`app\bin\`**・**`VERSION.txt`**・任意 **`addin\`**）へ **フォールバック**する。失敗時は **`{app}\logs\hc_update.log`** と MessageBox。§1.5・§3・§4.0・§5。

**版情報の置き場（通知を成立させるために）**

| 側 | 内容 |
|----|------|
| **配布側（インストール元）** | **`catalog.json` の `latest_version`** 等。zip 運用なら **zip 内のツリーに `VERSION.txt` を含める**など、**「最新がいくつか」が分かる**こと。 |
| **インストール先** | **`{app}\VERSION.txt` を第一**、無ければ **Inno `DisplayVersion` 等（レジストリ）**（§0 表）。**両側そろわないと**「最新と比較して通知」ができない。 |

**バージョンが「決まる」タイミング**

- **`VERSION.txt`** … **そのリリースのステージング／zip 内容が固まったとき**（現在は `dist\CSV_Tool\app\bin` 集約を前提）。正本を共有に出す作業と同じタイミングでよい。
- **`catalog.json` の `latest_version`** … **共有に載せる／更新するとき**に、上記と**同じ製品版**へ揃える。
- **Inno の `AppVersion`** … **インストーラをコンパイルするとき**の表示用メタ情報（`#define MyAppVersion`）。実運用の「アプリと機能」表示は、インストール時と `bin` 適用後に **`catalog.bin.latest_version` を 3 桁化（`X.Y.Z.W -> X.Y.Z`）して `DisplayVersion` へ同期**する。

**運用の一文** … **更新判定は 4 桁版（`VERSION.txt` / `catalog.json`）を正として維持し、表示版のみ 3 桁（`DisplayVersion`）に正規化**する。

| **完了判定** | `app\bin\hc_main.exe` 存在 + `HC_*` 設定 + `xlwings.conf` 生成 | 版更新後の再起動で新バージョン反映（ログ確認可） |

**運用チェック（推奨）**

- **版整合**: `VERSION.txt` と `catalog.json.latest_version` の 4 桁版を揃える（更新判定の正本）。
- **表示版の扱い**: Windows の「アプリと機能」は `catalog.set_version`（`X.Y.Z.N`）を優先して `DisplayVersion` に使う。`set_version` が無い旧 catalog は `bin.latest_version`（3桁）+ `config.latest_version`（1桁）で合成する。
- **表示版の確認（レジストリ）**: `DisplayVersion` は通常 `HKLM\Software\Microsoft\Windows\CurrentVersion\Uninstall\{B5E8C4A2-1D3F-4E6B-9C0D-1A2B3C4D5E6F}_is1`（環境により `WOW6432Node` / `HKCU` 側）で確認できる。`reg query` や PowerShell `Get-ItemProperty` で値が `X.Y.Z` になっていることを確認する。
- **成果物整合**: `dist\CSV_Tool` は `app\bin` 集約を前提に、配布正本（`current`/zip）の不足物を事前チェックする。
- **ロールバック**: `vX.Y.Z` スナップショット、または full zip を最低 1 世代保持する。
- **失敗時導線**: ユーザー向けには短いメッセージ、詳細は `{app}\logs\hc_update.log` に集約する。

## 1. 薄いインストーラと共有上の正本

**目的**: メールでは **容量の小さいブートストラップ（Inno Setup 等のセットアップ EXE）** だけを配り、**数百 MB 級の本体**は社内 **共有フォルダ（UNC）** に置いてインストール時に取り込む。

| 役割 | 典型の置き場所 | 内容 |
|------|----------------|------|
| **正本（大きい）** | `\\fileserver\releases\CSV_Tool\...` 等 | 現在は **`app\bin\` 集約**を中心に配布。必要に応じて `config\`・`addin\`・`VERSION.txt` を同梱し、`xlwings.conf` はインストール先で再生成。 |
| **薄いインストーラ** | メール添付・社内ポータル | 共有配布ルートの `catalog.json` から初回導入 zip を決定し、ローカル（例: `C:\Program Files\Excel_Addin\CSV_Tool`）へ展開。`HC_INSTALL_ROOT` / `HC_PACKAGED_DEPLOYMENT`、`xlwings.conf` 生成、アンインストール登録 |

### 1.1 Inno Setup 側で行うこと（概念）

- **薄いインストーラ（テンプレート）** … リポジトリの **`installer\CSV_Tool_Setup.iss`**。共有配布ルートの **`catalog.json`** を読み、初回導入用 full zip を `{app}` へ展開する。`catalog.json` が取得できない場合は通知して中断する。**`HKCU\Environment`** の **`HC_INSTALL_ROOT`** / **`HC_PACKAGED_DEPLOYMENT`**、**`xlwings.conf` の `{app}` 向け再生成**、アンインストール時の **`{app}` 削除**（`[UninstallDelete]`）まで含む。**コンパイル手順（開発者向け）**は **`docs\インストーラ化（開発者向け）.md` §2** を参照。Inno の **ISCC**（**`/DSHAREPAYLOAD=...`**）でもよい。**管理者＋HKCU** 時の注意は Inno の **UsedUserAreasWarning**（`.iss` 先頭コメント参照）。
- **環境変数の反映タイミング** … `CSV_Tool_Setup.iss` は `ChangesEnvironment=yes` で環境変数変更通知を送る。通常は「Excel を終了→再起動」で反映されるが、端末状態によっては再サインインが必要な場合がある。
- 共有上のファイルを **`{app}` 以下へ再帰コピー**（または共有に **単一 zip** を置き、インストーラが展開してから配置）。
- ハードリンク化済みの正本を配る場合は、**コピー先のボリューム内でのみリンク関係が維持**される点に注意する（別ボリュームへ移すと通常コピーになる）。
- **`HC_INSTALL_ROOT`** を **確定後の `{app}`**（ウィザードでユーザーが選んだルート）に、**`HC_PACKAGED_DEPLOYMENT=1`** を **`HKCU\Environment`** に書く（**§0**・**§1.3**）。マシン全体（HKLM）は本製品の既定では使わない。詳細は `docs\environment_variables.md`。
- **アンインストール時**に、上記 **`HC_*` を `HKCU\Environment` から削除**する（§0・§1.3）。
- ルートの **`config\*.json`**（`ui_*.json`、`svc_warmup.json` 等）は **`HC_INSTALL_ROOT\config\`** に置けば **`core_cst.resolve_config_file_path`** により **最優先で読まれる**（各 `app\...\config\` はフォールバック。**`docs\Exe化（開発者向け）.md` セクション 2.7**）。
- **`xlwings.conf`** を **`{app}` 基準の絶対パス**で生成（短寿命ランナーの `INTERPRETER_WIN` 等。**`docs\Exe化（開発者向け）.md` セクション 7.1**）。
- **`AppId` を固定**し、同一製品として **再実行＝上書き更新**できるようにする。
- 共有にアクセスできない場合は **明示的なエラー**（VPN・ドライブ割当・権限の案内）。

### 1.1.1 インストーラ EXE のビルド（開発者向け）

**`CSV_Tool_Setup.exe` のコンパイル**・埋め込みパス・検証チェックリストは **`docs\インストーラ化（開発者向け）.md` §2** に記載する。

### 1.1.2 インストール完了後の利用開始（エンドユーザー向け）

**「Excel のアドイン設定だけで即利用」に限らない**ことがある。手順書では次をセットで案内するとよい。

| 手順 | 理由 |
|------|------|
| **インストール完了後、起動中の Excel があれば終了し、Excel を開き直す** | `HC_*` は **`HKCU\Environment`** に書かれる。**すでに起動していた Excel** は古い環境ブロックのままのことがあり、`HC_INSTALL_ROOT` が見えず更新確認や常駐経路が期待どおり動かない（§1.3・§1.4 と同趣旨。実装のメッセージ例は `core.packaged_update`）。 |
| **`{app}\addin\` の xlam を Excel の「アドイン」から追加し、有効化する** | 薄いインストーラは **catalog が指す full zip を展開するだけ**。**Excel に COM アドインとして登録する操作**は別（正本に `addin\` が無い場合は別途配布する）。配置例は `docs\Exe化（開発者向け）.md` **セクション 2.7** 等。 |
| **マクロの信頼・信頼できる場所** | 組織のグループポリシー次第。**ブロックされたままではリボンや `RunPython` が動かない**。必要なら社内手順に明記。 |
| **`catalog.json` への到達** | **更新確認・config の zip 適用**に必要。**本体 EXE の存在と `HC_*`** が揃っていれば常駐起動の土台はあるが、**オフラインでは起動時チェックは黙ってスキップ**（ログのみ。§1.5）。 |

### 1.2 権限とアクセス文脈（重要）

- セットアップを **管理者として実行**すると、**昇格したプロセスからはユーザーの mapped drive が見えない**ことがある。UNC（`\\server\share\...`）を使うか、**管理者不要の per-user インストール**にして共有と同じユーザー文脈で読む、のいずれかを運用で決める。

#### 1.2.1 「管理者権限を使うか」をユーザーに選ばせる場合

- Inno Setup では、`[Setup]` の **`PrivilegesRequiredOverridesAllowed=dialog`** を使うと、ウィザードで **インストールモード（all users / current user）** を選ばせる構成にできる。
- これは **UAC ダイアログそのもの**ではない。UAC は Windows 側の昇格確認であり、必要になったタイミングで OS が表示する。
- つまり体験としては、**(1) Inno のモード選択** → **(2) 必要時のみ Windows の UAC 確認**、の 2 段階になる。
- 既定を `C:\Program Files\...` にする運用では、通常は **管理者権限が必要**になりやすい。`current user` を選べる設計にする場合は、インストール先既定値や書き込み先（`HKCU` / `HKLM`）を併せて整合させる。
- 1 本のインストーラで両モードを許可する場合、`{app}` と `HC_INSTALL_ROOT` の一致、アンインストール時の `HC_*` 削除、共有アクセス経路（UNC）をモード別に確認する。

### 1.3 インストール先の既定値とユーザー変更（`{app}` 連動）

**ウィザードで既定パスを示し、ユーザーが変更できるか**

- **できる。** Inno Setup では **`[Setup]` の `DefaultDirName`** で **初期のインストール先**を定め、**ディレクトリ選択ページ**でユーザーが別フォルダに変えられる（**`DisableDirPage=yes`** にしない限り）。
- パスを **固定したい**運用だけ、ディレクトリページを無効化する等で制限する。

**ユーザーがインストール先を変えたときに連動すべきもの**

最終的なインストールルートは Inno の **`{app}`**（ユーザーが確定したパス）である。**ビルドマシン上の絶対パスをそのまま残さない**こと。

| 対象 | 方針 |
|------|------|
| **`[Files]` の `DestDir: "{app}"`** | 追加対応は不要。**ファイルは常に確定後の `{app}` 配下**へ展開される。 |
| **`HKCU\Environment` の `HC_INSTALL_ROOT`** | **`{app}` を展開した絶対パス**を書く（`[Registry]` で `ExpandConstant('{app}')` 等）。ユーザーがパスを変えれば **書き込まれる値もそのパスに一致**する。 |
| **`xlwings.conf`** | **`INTERPRETER_WIN` 等、`{app}` 配下の EXE を指す行はすべて**、インストール時に **`{app}` 基準で生成または置換**する（`[INI]`、`[Code]`、またはテンプレ＋後処理）。ステージングからコピーする場合も **インストール完了時の `{app}`** で上書きする。 |
| **その他 `{app}` 依存の絶対パス** | ショートカット・カスタムコマンド等も **`{app}` 定数**で統一し、**手作業の固定パスを混ぜない**。 |

**運用上の注意**

- **`HC_INSTALL_ROOT` を常に実際の `{app}` と一致**させれば、`core_cst.resolve_config_file_path`（`config\` の正本）とも齟齬が出にくい。
- **`HKCU\Environment` を更新した直後**、**起動済みの Excel** は古い環境のままのことがある。**インストール完了後に Excel を一度終了してから**使い始める案内があるとよい（§1.4 の環境ブロックの話と同趣旨）。
- **アンインストール**では、**当該インストールで書いた `HC_*` だけ**を削除し、別パスへ再インストールしたときに **古い `HC_INSTALL_ROOT` が残る**事故を防ぐ（Inno の `uninsdeletevalue` 等）。

### 1.4 環境変数・レジストリと配布／開発の切替

**仕組み（Windows）**

- **永続のユーザー環境変数**（コントロールパネルや `setx`、PowerShell の `SetEnvironmentVariable(..., "User")` で設定したもの）は、多くの場合 **レジストリ `HKCU\Environment`** に保存される。
- ログオン後、エクスプローラーなど **ユーザーのシェルから起動するプロセス**は、その情報を含んだ **環境ブロック**を引き継ぐ（厳密にはプロセス生成時に親からマージされるが、**「ユーザー環境がプロセスの環境変数として載る」**と理解すればよい）。
- **Excel や xlwings／Python はレジストリのキーを直接読んでモードを切り替えているわけではない。** 参照するのは **そのプロセスに渡っている環境変数**（`HC_INSTALL_ROOT`、`HC_PACKAGED_DEPLOYMENT` 等。VBA の `Environ`、Python の **`os.environ`** と同じ源）。

**インストーラでできること**

- Inno Setup の **`[Registry]`** 等で **`HKCU\Environment`**（または方針に応じてマシン環境）に **`HC_INSTALL_ROOT`** / **`HC_PACKAGED_DEPLOYMENT`** を書く、というのが **配布先で「特別なバッチなしで配布モード」にする一般的なやり方**のひとつ。
- **環境変数を恒久的にユーザーへ付けたい**とき、Windows 標準の保存先は上記のとおり **レジストリとセット**になることが多い（「環境変数だけ触り、レジストリは触らない」は **セッション限定の `set`** なら可能だが、**ログオフ後も残す**なら通常は HKCU\Environment 等を経由する）。

**現状のリポジトリ**

- **`installer\CSV_Tool.iss`**（フルパッケージを `{app}` に展開）は、**現時点では `HKCU\Environment` への `HC_*` 書き込み・アンインストール時の削除を含まない**。**§0** の方針に合わせ、**薄いインストーラの Inno スクリプト**および **`CSV_Tool.iss` の両方**で、順次 **`[Registry]`** 等による追記・削除を入れる想定（本節は挙動の説明）。

**一覧: 永続設定 × Excel の起動方法 → 実質どちらのモードか**

以下では **配布モード**を「`HC_PACKAGED_DEPLOYMENT` が真として解釈され、かつ `HC_INSTALL_ROOT` がインストール先ルートを指す」とし、**開発モード**を「上記が効かない、または開発用バッチでセッション上クリアされリポジトリ／venv 側が使われる」とざっくり呼ぶ（`xlwings.conf` も絡む。詳細は **`docs\Exe化（開発者向け）.md`**）。

| 永続のユーザー環境（例: インストーラが `HKCU\Environment` に書いたか） | Excel の起動方法 | 実質のイメージ |
|------------------------------------------------------------------------|------------------|----------------|
| **書いていない**（`HC_*` なし） | スタートメニュー等、**環境をいじらない**経路 | **開発／既定寄り**（配布用 `HC_*` が無いため EXE 常駐経路に乗りにくい） |
| **書いていない** | **`tools\dev\start_excel_dev.bat`** 等で `HC_*` をクリアした **同じ CMD から** Excel | **開発** |
| **書いていない** | **`start_excel_packaged_test.bat`** 等で `HC_*` をセットした **同じ CMD から** Excel | **配布（試験）**（ルートはバッチの指定次第） |
| **配布用 `HC_*` を書いた** | スタートメニュー等、**環境をいじらない**経路 | **配布** |
| **配布用 `HC_*` を書いた** | **開発用バッチ**でクリアした **同じ CMD から** Excel | **開発**（**その起動だけ**親プロセスの環境が優先される） |
| **配布用 `HC_*` を書いた** | **配布試験用バッチ**で再度セットした **同じ CMD から** Excel | **配布**（試験用パスを明示できる） |

**補足**

- 切替の本体は **「CMD であること」ではなく「Excel を起動する親プロセスの環境ブロック」**である。PowerShell で `$env:HC_...` を整えてから Excel を起動しても同じ考え方。
- **レジストリでユーザー環境を変えた直後**は、**すでに起動中の Excel** は古い環境のまま。**Excel をいったん終了してから**開き直すと新しい値が反映されやすい。
- **開発PCでインストーラを試す**場合: インストーラが `HKCU\Environment` に配布用を書けば **通常起動は配布**、**`start_excel_dev.bat` 経由**なら **そのセッションは開発**に戻せる。

### 1.5 配布ルート `HC_DEPLOY_ROOT` と `catalog.json`（実装済み・2026-04-17）

**`catalog.json` は配布先 PC に常駐インストールしない。** 共有（NAS）または開発 PC 上の **配布ツリー直下**に置き、Python が **都度読みにいく**。

| **相対パス（§4.0・§4.1 の zip 等）** | `catalog.json` 内の **`relative_path` は `catalog.json` と同じフォルダを基準**とする想定でよい（一般的な運用）。各キーの意味は **§4.0**。 |

**更新の適用（ファイル上書き）** … 本モジュールは **通知まで**。Excel 終了後の **薄いインストーラ再実行**や zip 展開は **別タスク**（§3・§4.1）。

## 3. 更新の自動検知と操作者への通知（「今／後で」）

**方針**: 専用の常駐アップデータを最初から作らず、**アドイン起動時およびリボンからの手動**で共有の **`catalog.json`** を読み、ローカル版と比較する（**§0**）。比較・判定は **Python（`hc_main`）に集約**する。

| 項目 | 第1版の前提（§0 と整合） |
|------|---------------------------|
| **カタログ** | 共有ルートの **`catalog.json` のみ**（§4） |
| **ローカル版** | **`installed_bin_version` / `installed_config_version` を分離管理**（実体は `{app}` 配下の版情報ファイル、または既存 `VERSION.txt` + 補助情報） |
| **初回導入** | **UI ありインストーラで `bin + config + bootstrap` を一括導入** |
| **config 更新** | **サイレント適用**（原則通知なし）。**失敗時のみ通知 + ログ** |
| **bin 更新** | **UI で「今すぐ／後で」**。「はい」で **`bin.patch`（条件一致時）または `bin.full`** を検証のうえ **Excel 全終了後**に **`app\bin`** / **`addin`** を自動反映（PowerShell ワーカー。**差分はファイルマージ**、削除は含めない） |
| **「後で」** | **永続スヌーズは行わない**（§0）。ダイアログを閉じるのみで、**次回起動／手動チェックで再判定** |

### 3.1 実装の置き場所

- **版チェックの本体**は **Python（`hc_main`）**。`catalog.json` 取得・版比較・分岐は **同一コード**とする。
- **呼び出し経路**は **アドイン読み込み時（起動時）に一度**、および **リボンからの明示操作**（**§0**）。
- **ユーザーへの通知**は **VBA `MsgBox`**、**Qt／`ui_server` のダイアログ**等、既存 UI に合わせてよいが、**判定ロジックは VBA に複製しない**（Python 結果を表示する形を推奨）。
- **共有にアクセスできない**とき: **起動時の自動チェック**は **メッセージなし**でスキップ（ログのみ）。**リボンからの手動**では **一言メッセージ＋ログ**（§1.5）。

### 3.2 注意（ファイルロック）

- `CSV_Tool.xlam` や EXE が実行中のまま上書きすると失敗しうる。**「今」更新は Excel 終了後**を必須にする。

### 3.3 運用ルール（初回 / config / bin）

| 区分 | 更新方式 | ユーザー体験 | 失敗時 |
|------|----------|--------------|--------|
| **初回** | 薄いインストーラで `bin + config + bootstrap` 導入 | ウィザード操作（保存先選択可） | エラー表示して中断 |
| **config VerUp** | `catalog.json` 判定後にサイレント上書き | **経路により異なる**（§3.3.1） | 通知あり + ログ (`{app}\logs\hc_update.log`) |
| **bin VerUp** | `catalog.json` 判定後に UI で選択 | 「今すぐ / 後で」選択 | 通知あり + ログ |

#### 3.3.1 config 更新: 比較に使う版・トリガ・UI（実装に準拠）

**何を見て「config を上げるか」判定するか**

- **ローカル**: **`{app}\config\VERSION.txt` の先頭 1 行**（インストール済み config 版。無い場合は未設定扱いで更新対象になり得る）。
- **共有側**: **`catalog.json` の `config.latest_version`**（SemVer 比較）。**`config.payload`**（zip の相対パス・任意で `sha256`）で実体を取得し、`{app}\config\` へ atomic 上書き後、**`config\VERSION.txt` を新版に更新**（実装: `core.packaged_update._try_apply_config_update`）。
- **互換**: **`config.min_bin_version`** があるとき、**`{app}\VERSION.txt`（bin 版）がそれ未満**なら config は適用せずエラー文字列を返す（ログ＋メッセージ）。

**いつ動くか（トリガ）**

1. **起動時（自動）** … Excel 読み込み後、**`svc.svc_host`** がブリッジ登録まで済ませたあと **`maybe_check_updates_on_startup()`** を呼ぶ。**配布モード**（`packaged_spawn_requested()` が真）のときのみ。**`HC_UPDATE_CHECK_AT_STARTUP`** が **`0` / `false`（空は偽とみなす実装）** なら **呼ばない**。
2. **リボン「更新確認」（手動）** … VBA から **`check_for_updates_interactive('ribbon')`**。

**ユーザーに見える UI（config に限る）**

| 経路 | config **適用成功**時 | config **失敗**時 |
|------|-------------------------|---------------------|
| **起動時** | **ダイアログなし**（サイレント） | **警告の MessageBox**（「config の自動更新に失敗…」） |
| **リボン「更新確認」** | **情報ダイアログ**（「config を更新しました」＋新版） | **警告の MessageBox** |

**bin にも新しい版がある場合** … 上記のあと **`needs_bin_update`** なら **「今すぐ／後で」の Yes/No** と案内（起動時・リボン共通で bin 側のみ追加 UI）。

**補足**

- §3.1・上表の「config は成功時通知なし」は **起動時経路を主に指す**。リボン経路では **成功時も明示通知**する（運用で利用者に伝わりやすくするため）。
- **オフライン**時の扱い（起動時はメッセージなし等）は **§1.5** の表どおり。

**判定順（推奨）**

1. `catalog.json` を取得  
2. `config` の互換性を確認（例: `min_bin_version`）  
3. `config` 更新が必要ならサイレント適用  
4. `bin` 更新が必要なら「今すぐ / 後で」を表示  
5. 「今すぐ」（はい）選択時は **バックグラウンドワーカー**が **EXCEL プロセス終了を待機**したあと、**`bin.patch`（条件一致時）または `bin.full` zip** を展開し **`{app}\app\bin`**（および **`addin\`**）を更新。**差分**のときは **マージコピー**、**フル**のときは従来どおり **mirror**。**`VERSION.txt`** は **`bin.latest_version`** で揃える（**§4.0**）

### 3.4 運用決定事項（2026-05-09）

更新運用に関する追加合意を以下で固定する。実装・運用・サポートで解釈を揃えること。

| 項目 | 決定内容 |
|------|-----------|
| **更新時のモード** | **初回インストールで確定したモード（Current user / All users）を継承**する。更新処理中にモード変更は行わない。 |
| **モード識別の保存先** | Uninstall キー（`{AppId}_is1`）配下の独自値 **`InstallScope`**（`current` / `all`）を参照する。**書き込みは通常側のみ**（`Software\Microsoft\Windows\CurrentVersion\Uninstall\{AppId}_is1`）。**`Software\WOW6432Node\...` 配下には書き込まない**。書き込みタイミングは Inno の Uninstall キー再生成（`Saving uninstall information.`）の後（インストーラ `[Code]` の `ssPostInstall` で `WriteInstallScopeToUninstallKey` が実行）。新規レジストリキーは追加しない。 |
| **DisplayName（プログラムと機能）** | インストールモードで切替: Current user → **`CSV Tool (User)`**、All users → **`CSV Tool (All User)`**。プログラムと機能の表示名で初回モードを判別できる。 |
| **再インストール時の残骸掃除** | インストーラ起動時（`[Code]` の `ssInstall`）に **反対モードの `_is1` キーと `HC_*` 環境変数を削除**する（`CleanupCrossModeRemnants`）。Current user 起動時の HKLM 残骸は **権限不足のため警告ログのみ**でスキップ（モード切替時は先にアンインストール推奨）。 |
| **モード変更の手段** | モード変更が必要な場合は **再インストールのみ**。アップグレード経路での切替は対象外。 |
| **操作者の操作量** | **最小化方針**とし、必要情報のみ通知する。通常は自動判定・自動適用（config）を優先し、判断が必要な場面（bin 適用可否、UAC 等）のみ操作を求める。 |
| **`config.min_bin_version` の扱い** | 互換下限として使用する。**ローカル bin 版が下限未満なら config 更新を適用しない**（bin 更新を優先）。 |
| **full zip バックアップ** | 更新時に復旧用 full zip を **`{HC_INSTALL_ROOT}\update\archive\full\`** へ保存する。命名は **版ベース単一保持**（`full_prev_<version>.zip`）。 |
| **更新成功の定義（バックアップ整理）** | **`bin + bootstrap` の双方成功**を更新成功とみなし、その時点で古いバックアップを削除する。 |
| **初回インストール時のバックアップ** | 初回は戻し元が無いため、**バックアップ作成は不要**。バックアップ運用は初回後の最初の更新から開始する。 |
| **復旧方式** | **半自動**を採用する。復旧候補の特定・案内は自動化し、最終実行は操作者確認を経て行う。完全自動ロールバックは現時点で採用しない。 |
| **UAC 拒否時の扱い** | 昇格を拒否した場合は **今回の適用を defer** し、次回起動時に再確認する（非昇格継続はしない）。 |
| **起動時チェックの排他** | 起動時に `pending` がある場合は **予約適用のみ実行**し、同一起動内で通常バージョンチェックは実行しない。`defer` 時も同様に通常チェックは再開しない。 |

補足:

- `catalog.json` 解決順（`HC_CATALOG_PATH` → `config\catalog_path.txt` → `HC_DEPLOY_ROOT\catalog.json`）は変更しない。
- 詳細な実装ハンドオフは **`docs\agent_handoff_更新運用方針_20260509.md`** を参照。
- 受け入れテスト最小セットは **uac-strict-7**（Current/All、`min_bin_version`、半自動復旧、Program Files+UAC、patch→full、起動時排他/defer 抑止）。

## 4. `catalog.json` のフィールド例（参考）

### 4.0 運用参照: 各フィールドの意味（スキーマ v3 中心）

本リポジトリで **更新確認・config のサイレント適用・bin の「今すぐ」適用**に使うのは、共有ルートの **`catalog.json`**（UTF-8、BOM なし推奨）。**相対パス**（`*.relative_path`）は原則 **`catalog.json` の親フォルダ**を基準とする（**§1.5**）。JSON の雛形は **`installer\catalog.sample.json`**。

**実装の正**: **`core.packaged_update`**（Python）。**薄いインストーラ**（`installer\CSV_Tool_Setup.iss`）は初回 zip 解決で **`bin` / `config` / `bootstrap`** のキーを参照する（下表）。

#### ルート（トップレベル）

| キー | 意味 |
|------|------|
| `schema_version` | マニフェスト形式の世代（将来の互換用）。現行の運用例では **3**。 |
| `bin` | 実行バイナリ一式（`app\bin` 等）の最新版案内と **フル zip**。**更新判定の主対象**。 |
| `config` | 設定パッケージの案内と zip。**サイレント適用**（**§3.3**）。 |
| `latest_version` / `latest` | **`bin` オブジェクトが無い旧・フラット形**向け。Python 側はルートのいずれかを bin 版として読む **互換**がある。 |

#### `bin`

| キー | 意味 |
|------|------|
| `latest_version` | 共有が案内する **最新製品版**（SemVer）。`{app}\VERSION.txt` と比較する。**更新確認では事実上必須**（無いとエラー扱い）。 |
| `min_supported_version` | 雛形に例示あり。**現行の `packaged_update` では未参照**（運用メモ・将来用の余地）。 |
| `release_notes_url` | リリースノート URL の意図。**現行の `packaged_update` では未参照**。 |
| `full` | **フル zip** の指定。「今すぐ」経路では **`bin.patch` が使えない場合**（範囲外・欠損・sha256 不一致など）に **フォールバック**して適用する。 |
| `full.relative_path` | zip へのパス（相対または絶対）。 |
| `full.sha256` | 任意。指定時は zip の SHA256 を展開前に検証。**空なら検証スキップ**。 |
| `patch` | **差分 zip**（`release\diff.bat` / `make_diff_zip.py`）。**`from_min_version` ≤ インストール bin 版 ≤ `from_max_version`**（いずれか省略時はその側の境界なし）のとき **優先適用**。`manifest.json`（`bsdiff4-manifest-v1`）がある場合、`.exe/.dll/.pyd` は bsdiff パッチから復元し、それ以外は copy でマージする。manifest が無い旧 patch zip は従来方式でマージ（後方互換）。**`{app}\VERSION.txt`** は適用後 **`bin.latest_version`** の 1 行で更新。**削除ファイルは差分に含めない**（要削除時はフル zip で配布）。分岐の詳細は **§4.1**。 |

#### `config`

| キー | 意味 |
|------|------|
| `latest_version` | 設定パッケージの論理版。`{app}\config\VERSION.txt` と比較し、新しい場合に適用候補。 |
| `min_bin_version` | この config を適用するために必要な **ローカル bin の最低版**。未満なら config は適用されない（**§3.3.1**）。 |
| `payload` | 設定 zip のブロック。 |
| `payload.relative_path` | config zip へのパス。 |
| `payload.sha256` | 任意。指定時は zip を検証。 |

#### 薄いインストーラのみ: `bootstrap`

`CSV_Tool_Setup.iss` は初回導入で **`bootstrap.full.relative_path`** を必須として参照し、`bootstrap` payload を `{app}` へ展開する。

### 4.0.1 zip 種別と参照優先（運用一覧）

**`catalog.json` 内のキーの記載順では優先は決まらない。** 次のとおり **実装が参照するキー**で決まる。なお **どの `catalog.json` を読むか**は **§1.5**（`HC_CATALOG_PATH` → `config\catalog_path.txt` → `{HC_DEPLOY_ROOT}\catalog.json`）の順。

#### 優先ラダー（最上位＝1 から順に試すイメージ）

**初回・bin 更新・config 更新は別々の判定**であり、更新経路の優先は経路内で決まる（同じ端末でもタイミングで当たる経路が違う）。

| 経路 | 順位 | いつ採用するか（イメージ） | 典型 zip | `catalog.json` の参照 |
|------|------|---------------------------|----------|------------------------|
| **初回**（薄い Inno） | **1**（必須） | 常に参照 | `bin_*_full.zip` | `bin.full.relative_path` |
| 初回 | **2**（必須） | 常に参照 | `cfg_*.zip` | `config.payload.relative_path` |
| 初回 | **3**（必須） | 常に参照 | `bootstrap_*_full.zip` | `bootstrap.full.relative_path` |
| **bin 更新**（Python） | **1**（最上位） | `bin.patch` の範囲・ファイル・sha256 が有効 | `bin_*_*_d.zip` | `bin.patch` |
| bin 更新 | **2** | 1 が使えないときフォールバック | `bin_*_full.zip` | `bin.full` |
| **config 更新**（Python） | **1**（唯一） | config に更新があり互換 OK | `cfg_*.zip` | `config.payload.relative_path` |

**差分 zip** は **bin 更新の順位 1 専用**（初回 Inno では使わない）。

#### 記号での短縮表記（`→` は下位優先へのフォールバック）

- **初回（薄い Inno）**: `bin_*_full.zip`（`bin.full`） + `cfg_*.zip`（`config.payload`） + `bootstrap_*_full.zip`（`bootstrap.full`）
- **更新（bin）**: `bin_*_*_d.zip`（`bin.patch`） **→** `bin_*_full.zip`（`bin.full`）
- **更新（config）**: `cfg_*.zip`（`config.payload`）のみ（独立経路）
- **上記以外**: 当該経路で参照しなければ実質未使用（`catalog.json` が指さないファイルは採用されない）

#### 初回インストール（`CSV_Tool_Setup.exe`）

**展開する zip は 3 本**（**次表**の `relative_path` を `catalog.json` の親フォルダから解決）。差分 zip（`bin_*_*_d.zip`）は **初回展開では参照しない**。

| 優先 | `catalog.json` の参照 | 典型ファイル名 |
|------|----------------------|----------------|
| 1 | `bin.full.relative_path` | `bin_*_full.zip` |
| 2 | `config.payload.relative_path` | `cfg_*.zip` |
| 3 | `bootstrap.full.relative_path` | `bootstrap_*_full.zip` |

#### インストール後の更新（`core.packaged_update`）

| 経路 | 優先 | 参照 | 典型ファイル名 |
|------|------|------|----------------|
| **bin**（「今すぐ」等） | 1 | `bin.patch`（`from_*` 範囲・ファイル・sha256 が有効なとき） | `bin_*_*_d.zip` |
| | 2 | `bin.full` | `bin_*_full.zip` |
| **config**（サイレント） | 1（唯一） | `config.payload.relative_path` | `cfg_*.zip` |

**`bootstrap.full` が指す `full_*.zip` は、インストール後の bin 自動更新では参照しない**（初回 Inno 専用）。

#### zip ファイル種別 × 利用経路（早見）

| zip の例 | 薄い Inno（初回） | bin 更新 | config 更新 |
|----------|-------------------|----------|-------------|
| `bin_*_full.zip` | 採用可（必須） | 採用可（フル／フォールバック） | 参照しない |
| `bootstrap_*_full.zip` | 採用可（必須） | 参照しない | 参照しない |
| `bin_*_*_d.zip` | 参照しない | 採用可（`bin.patch`、条件付き） | 参照しない |
| `cfg_*.zip` | 採用可（必須） | 参照しない | 採用可（`config.payload`） |

### 4.1 初回（フル）と更新（差分 zip）の分岐

**方針**: **初回インストール**は **フル**（セクション 5 相当のツリー全体）。**更新**は原則 **差分 zip**（変更・追加ファイルのみ）を `{app}` に上書き展開し、**転送量と共有 I/O を抑える**。条件不成立時は **フルにフォールバック**する。

#### 分岐表（実装の優先順位イメージ）

| 順 | 条件 | 採用する成果物 | 備考 |
|----|------|----------------|------|
| 1 | **`{app}` が無い／`hc_main.exe` が無い／`VERSION.txt` も読めず版不明** | **フル** | **初回**扱い。フォルダ `robocopy`（現行 `CSV_Tool_Setup.iss`）または **フル zip 展開**（将来実装）。 |
| 2 | **インストール済み** かつ **`latest_version` > installed** かつ **`catalog.patch`（差分 zip）あり** かつ **installed が `patch.from_min_version` 以上**（任意で **`patch.from_max_version` 以下**） | **差分 zip** | `{app}` へ **上書き展開**。**Excel 終了後**に実行（§3.2）。**削除ファイル**は zip 差分に含めない限り残る（後述）。 |
| 3 | 上記以外で **`latest_version` > installed**（例: installed が差分の下限未満、`min_supported` 未満、**差分エントリなし**） | **フル** | **丸ごと差し替え**推奨（既存 `{app}` バックアップは運用で検討）。 |
| 4 | **`catalog` が読めない／オフライン** | **なし**（スキップ） | §3 のとおり黙ってスキップまたはメッセージのみ。 |

**補足ルール（推奨）**

- **差分 zip の中身**は **`{app}` ルートからの相対パス**（例: `app\bin\hc_main.exe`）と一致させ、**zip 内に余計な親フォルダを挟まない**。
- **ファイル削除**が必要なリリースは **差分ではなくフル**にするか、**別途「削除リスト」**をマニフェストで渡す（未実装ならフルへ）。
- **リンク構造（ジャンクション／ハードリンク）を大きく変える**リリースは **フル**を推奨。
- **SHA256**: `patch` / `full` の各 **`sha256`** に **期待ハッシュ**を載せ、展開前に検証する（§5 と整合）。

#### `catalog.json` 拡張例（フル zip／差分 zip 併用）

既存の `latest_version` 等に加え、**共有ルートからの相対パス**で **zip を指す**（UNC ルートはコードまたは別設定で固定でもよい）。

```json
{
  "schema_version": 2,
  "latest_version": "1.5.0",
  "min_supported_version": "1.4.0",
  "release_notes_url": "https://intranet.example/releases/1.5.0",
  "full": {
    "relative_path": "releases/CSV_Tool_1.5.0_full.zip",
    "sha256": "<64桁hex>"
  },
  "patch": {
    "relative_path": "releases/CSV_Tool_1.4.x_to_1.5.0_delta.zip",
    "sha256": "<64桁hex>",
    "from_min_version": "1.4.0",
    "from_max_version": "1.4.99"
  },
  "folder_current_relative": "current"
}
```

| フィールド | 意味 |
|------------|------|
| `full` | **フル**成果物（**zip 推奨**。フォルダ運用なら `folder_current_relative` のみでよい）。 |
| `full.relative_path` | `catalog.json` の親フォルダからの相対パス。 |
| `patch` | **差分 zip**。**`from_min_version` ≤ installed ≤ `from_max_version`**（`from_max_version` 省略時は上限なし）のときのみ採用。 |
| `folder_current_relative` | **初回／フルでフォルダ robocopy** する場合の `current` 相当（現行インストーラと整合）。zip フルに移行後は **`full` のみ**でもよい。 |

### 4.2 `bin` / `config` 分離運用の `catalog.json` 例

**各キーの意味**は **§4.0** を参照。

`catalog.json` は 1 本のまま、**更新対象を `bin` と `config` に分けて定義**する。  
運用の意図は次のとおり。

- **`config`**: サイレント適用（失敗時のみ通知）
- **`bin`**: 「今すぐ / 後で」UI を出し、今すぐ時は Excel 終了後に適用

```json
{
  "schema_version": 3,
  "bin": {
    "latest_version": "1.6.0",
    "full": {
      "relative_path": "releases/bin_1.6.0_full.zip",
      "sha256": "<64hex>"
    },
    "patch": {
      "relative_path": "releases/bin_1.5.x_to_1.6.0_delta.zip",
      "sha256": "<64hex>",
      "from_min_version": "1.5.0",
      "from_max_version": "1.5.99"
    }
  },
  "config": {
    "latest_version": "2026.04.20",
    "payload": {
      "relative_path": "releases/config_2026.04.20.zip",
      "sha256": "<64hex>"
    },
    "min_bin_version": "1.5.0"
  }
}
```

**補足**

- `config.min_bin_version` を満たさない場合は、`config` の自動適用を行わず `bin` 更新を優先する。
- `config` は差分でもフルでもよいが、途中破損回避のため **一時ファイル→置換（atomic）** を推奨する。
- 配置先は `{app}` のままでよく、**分離するのは正本管理と更新判定**である。

**zip の形式**: **汎用の zip でよい**（エクスプローラーの「送る」→圧縮、7-Zip、PowerShell の `Compress-Archive` 等）。専用フォーマットや自己解凍は不要。

**zip 作成時の注意**:

- **ルート構造**: zip を展開したあと、**インストール先（`HC_INSTALL_ROOT`）直下**に期待どおりのツリーが並ぶようにする。実装（フル zip の展開先）と **`catalog.json` の `relative_path`** が矛盾すると、二重フォルダや欠落の原因になる。
- **ジャンクション／リパースポイント**: 共有正本・成果物 zip では **原則使わない**。含める場合、展開環境によっては追従しない・壊れることがある。
- **パス長**: 深い階層では **MAX_PATH（約 260 文字）** に抵触しやすい。長いパス前提で運用する場合は、展開・コピー側の対応と合わせて設計する。
- **文字コード**: **`catalog.json` は UTF-8（BOM なし推奨）**。zip 内のパスに、環境によって問題になりうる文字が混ざっていないか確認する。

**実装メモ**: 現行 **`CSV_Tool_Setup.iss`** は **フォルダ `robocopy` のみ**。**zip 展開**は **更新処理**（Python／補助スクリプト／別 Inno）で行う想定。分岐判定は **`hc_main` 側の共通関数**に集約する（本書 **付録 A** §0）。

| F-2 | **版チェック**は **アドイン起動時**と**リボンからの手動**の 2 経路を用意し、**比較・判定・通知のロジックは共通化**する（同一関数／同一モジュールの呼び出し。実装は **Python（`hc_main`）** に寄せる。§0）。 |

### 付録A-3. 推奨アーキテクチャ（概要）

1. **版情報マニフェスト**（共有フォルダ上の小さなファイル）  
   - **本リポジトリ（第1版）**: **`catalog.json`**（フィールド例は **本書 §4**）。  
   - 一般的な別形として **付録 A-6** に **`version.json` 例**を残す（命名・キーは `catalog.json` と揃えるか実装でマッピングする）。

2. **現在版の取得**（ローカル）  
   - **本リポジトリ**: **`{app}\VERSION.txt` を優先**し、無い／読めない場合 **Inno のアンインストール登録に紐づく `DisplayVersion` 等（レジストリ）をフォールバック**（§0）。

3. **チェック処理（共通）**  
   - マニフェストを読み、現在版と比較（セマンティックバージョン推奨）。  
   - 共有にアクセスできない場合は「オフライン／権限エラー」として扱い、更新はスキップまたは再試行を案内。

4. **適用フェーズの分離**  
   - `config` 更新はサイレント適用（成功時は通知しない、失敗時のみ通知 + ログ）。  
   - `bin` 更新は UI で「今すぐ / 後で」を確認し、承認時のみ更新を実行する。

5. **セキュリティ（推奨）**  
   - 共有改ざん対策として、マニフェストにハッシュを記載し起動前に検証、またはコード署名の確認を検討する。

### 付録A-4. UpDate モジュールの配置（本体との関係）

**本リポジトリでの決定（§0）** … **版チェック（`catalog.json` 読取・比較・通知判定）は Python（`hc_main`）に実装**し、**Excel アドイン起動時**および**リボンからの明示**の両方から **同一 API を呼ぶ**。適用は **`config`（サイレント）** と **`bin`（今すぐ / 後で）** を分け、`bin` の「今すぐ」は **Excel 終了後**に実行する（ファイルロック回避。§5）。

---

**一般的な代替案**（別製品・別ポリシー向けの比較表）

| 置き場 | メリット | デメリット |
|--------|----------|------------|
| **1 段目 EXE に集約** | Excel がファイルを掴んでいないタイミングでチェック・起動しやすい。UpDate だけ差し替え配布しやすい。 | 本体と二重管理になりうるため、Inno／ビルドで版情報の整合を取る必要がある。 |
| **Excel／Python 本体プロセス内** | UI や設定と一体化しやすい。HTTP／JSON・版比較を Python に寄せられる（**本リポジトリはここを採用**）。 | **インストール中**に使用中ファイルのロックが起きうるため、**実際の上書きインストールは Excel 終了後**に行う。 |
| **共有 DLL や同梱ライブラリ** | ロジックの重複を減らせる。 | 起動主体と更新実行の責務を分離する設計が必要。 |

**参考パターン（本リポジトリ以外）**

- **起動時チェック**: 1 段目 EXE や起動前ランチャーで実行する構成もある。  
- **手動チェック**: 1 段目 EXE を `ShellExecute` してそこで完結させる構成もある。

### 付録A-5. 更新時の Excel の扱い

**基本方針**: **`bin` 更新の上書き前に Excel を終了**させる。`config` 更新は無停止適用を許容するが、読み込み中断や JSON 破損を避けるため **一時ファイル→置換（atomic）** を推奨する。

**推奨フロー**

1. `catalog.json` を読み、`config` / `bin` の更新要否を判定する。  
2. `config` が更新対象なら **サイレント適用**する（失敗時のみ通知）。  
3. `bin` が更新対象なら UI で「今すぐ / 後で」を確認する。  
4. 「今すぐ」の場合、**未保存の確認**・保存を促し、**Excel を終了**する。  
5. 更新処理（zip 展開または更新 EXE）で `bin` を適用し、必要に応じて **Excel を再起動**する。

**代替（要件が許す場合）**

- **次回起動時更新**: 共有からの取得だけ済ませ、Excel 終了時にバッチ／別 EXE をスケジュールしてインストール。  
- Excel 起動中の上書きは、Inno の **restartreplace** 等に依存する設計も可能だが、テストと運用コストが高め。

### 付録A-6. 版情報マニフェスト（フォーマット）

#### 付録A-6.1 推奨: `version.json`

- 比較は **Semantic Versioning 2.0.0**（`MAJOR.MINOR.PATCH`）を推奨。実装では既存の版比較ライブラリ（例: Python `packaging.version`）の利用を想定する。  
- UNC のルートはコードまたは設定で持ち、JSON 内のパスは **相対パス**とすると環境差し替えが容易。

**例（スキーマのたたき台）**:

```json
{
  "schema_version": 1,
  "latest_version": "2.3.0",
  "min_supported_version": "2.0.0",
  "release_notes_url": "https://intranet.example/releases/2.3.0",
  "force_update": false,
  "installers": {
    "full": {
      "relative_path": "releases/MyApp_Full_2.3.0.exe",
      "sha256": "<64文字の16進>"
    },
    "patch": {
      "from_min_version": "2.2.0",
      "relative_path": "releases/MyApp_Patch_2.2_to_2.3.exe",
      "sha256": "<64文字の16進>"
    }
  }
}
```

| フィールド | 必須 | 説明 |
|------------|------|------|
| `schema_version` | 推奨 | マニフェスト形式の版。将来の互換用。 |
| `latest_version` | 必須 | 最新リリースの版。 |
| `min_supported_version` | 任意 | これ未満はフル更新のみ等の分岐に利用。 |
| `release_notes_url` | 任意 | リリースノート。 |
| `force_update` | 任意 | 真なら次回起動時に強制案内などのポリシーと組み合わせ可能。 |
| `installers.full` | 必須に近い | フルインストーラ EXE。`sha256` は改ざん検知用（推奨）。 |
| `installers.patch` | 任意 | 差分（パッチ用 Inno EXE）。`from_min_version` で適用下限を指定。 |

フル／パッチのどちらを起動するかは **付録 A-7** に従い、**現在版に応じて 1 本に決める**。

#### 付録A-6.2 最小構成: `version.txt`

- 1 行に版文字列のみ（例: `2.3.0`）。  
- インストーラは命名規則で一意に決める（例: `MyApp_Setup_2.3.0.exe`）。拡張時に `version.json` へ移行する。

### 付録A-7. 差分更新とフル更新の併用（方針）

#### 付録A-7.1 `bin` / `config` の役割分離

| 区分 | 更新方式 | UI | Excel 終了 |
|------|----------|----|------------|
| **初回導入** | `bin + config + bootstrap` を一括導入 | あり | 導入時のみ通常手順 |
| **config VerUp** | サイレント上書き（atomic 推奨） | 成功時なし（失敗時のみ通知） | 不要 |
| **bin VerUp** | フル/差分 zip を適用 | 「今すぐ / 後で」 | 「今すぐ」のとき必須 |

| 方式 | 説明 | 備考 |
|------|------|------|
| **フル** | **初回**または条件不成立時。**フォルダ丸ごと**（`robocopy`）／**フル zip 展開**／**単一 Inno EXE** など | 現行の薄い Innoは **フォルダ `robocopy`**。zip フルは `catalog.json` の **`full`**（**本書 §4.1**）。 |
| **差分（zip）** | **更新**向け。**変更・追加ファイルのみ**の zip を `{app}` に上書き展開 | **分岐表・`catalog` スキーマ**は **本書 §4.1**。削除が要るリリースはフルへ。 |
| **差分（Inno EXE）** | 変更のみを含む**小さめのセットアップ EXE** を別成果物として置く | 代替案。bsdiff 等のバイナリ差分は運用コストが高いため推奨しない。 |

**`catalog.json` での役割分担（本リポジトリ）** … **`bin` / `config` 分離運用**のカタログ例は **本書 §4.2**。`bin` は **フル/差分判定**、`config` は **サイレント適用 + 互換条件（`min_bin_version`）** を持たせる。

**zip の形式・注意** … **汎用の zip でよい**（専用形式や自己解凍は不要）。**展開後のルート構造**、**ジャンクション／リパースポイント**、**パス長**、**`catalog.json` の UTF-8** などは **本書 §4.1** 本文に集約する。

**旧メモ（`version.json` 形式）**: **付録 A-6** の `installers.full` / `installers.patch`（EXE 指向）は **zip 版 `catalog.json` と併用せず**、どちらかに寄せるか実装で対応表を持つ。
