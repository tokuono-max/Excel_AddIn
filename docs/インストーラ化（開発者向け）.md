## 1. 対象となるスクリプト

| ファイル | 役割 |
|----------|------|
| **`installer\CSV_Tool_Setup.iss`** | **薄いインストーラ**本体。共有ルートの `catalog.json` から初回導入用 `full` zip を決定して `{app}` へ展開し、`HKCU\Environment` の `HC_*`、`xlwings.conf` を設定。`ChangesEnvironment=yes` により環境変数変更通知を送る。 |
| **`installer\build_csv_tool_setup.bat`** | **`CSV_Tool_Setup.iss`** を **ISCC** でコンパイルする推奨バッチ。 |
| **`installer\build_csv_tool.bat`** | **`CSV_Tool.iss`**（**正本同梱**）を **ISCC** でコンパイル。`..\dist\CSV_Tool` が無い場合はエラー終了。 |

## 2. `CSV_Tool_Setup.exe` のビルド手順

以下は **`installer\CSV_Tool_Setup.iss`** をコンパイルし、**`dist\CSV_Tool_Setup.exe`** を得る手順である。**スクリプト内の日本語コメント**や **`build_csv_tool_setup.bat` 先頭の REM** も参照するとよい。

### 2.1 何が EXE に埋め込まれるか（再ビルドが必要な変更）

| 変更したい内容 | 編集する場所 | 備考 |
|----------------|--------------|------|
| **配布ルート（catalog.json の場所）** | ① `installer\CSV_Tool_Setup.iss` の `#define SHAREPAYLOAD`、または ② ビルド時引数 `/DSHAREPAYLOAD=...` | インストール実行時に `catalog.json` と payload zip を解決する基準パス。`HC_DEPLOY_ROOT` は基本このパス（互換で `...\current` 指定時は親）になる。 |
| **既定のインストール先** | 同 `.iss` の `[Setup]` → **`DefaultDirName`** | ウィザードの初期表示。ユーザーが別フォルダを選ぶことは可能（`DisableDirPage` を有効にしない限り）。 |
| **製品表示バージョン** | 同 `.iss` の **`#define MyAppVersion`** | リポジトリの `VERSION.txt` と揃える。 |

上記いずれかを変えたら **必ず再コンパイル**する。実行中の EXE から共有パスを差し替えることはできない。

### 2.2 ビルド方法（推奨: バッチ）

1. **Inno Setup 6** をインストールする（`ISCC.exe` が `C:\Program Files (x86)\Inno Setup 6\` 等に存在すること）。
2. エクスプローラまたは `cmd` で **`installer`** フォルダに移動する。
3. 次のいずれかを実行する。

```bat
REM パターン A: .iss に書いた既定の SHAREPAYLOAD のままコンパイル
build_csv_tool_setup.bat

REM パターン B: ビルドのたびに共有パスだけ変える（.iss を編集しない）
build_csv_tool_setup.bat "\\fileserver\releases\CSV_Tool"
```

- **パターン B** は内部で `ISCC /DSHAREPAYLOAD="（第 1 引数）"` を付与する。**ローカル検証**では例えば `build_csv_tool_setup.bat "D:\work\release_payload"` のように **引用符付きの絶対パス**でもよい（互換で `...\current` も可）。
4. 成功時、**`dist\CSV_Tool_Setup.exe`** が生成される。

**トラブル**: `ISCC.exe not found` と出る場合は Inno Setup 6 のインストールパスを確認する。

### 2.3 ビルド方法（代替: ISCC を直接叩く）

カレントディレクトリを **`installer`** にしたうえで:

```bat
"C:\Program Files (x86)\Inno Setup 6\ISCC.exe" CSV_Tool_Setup.iss
"C:\Program Files (x86)\Inno Setup 6\ISCC.exe" /DSHAREPAYLOAD=\\server\share\CSV_Tool CSV_Tool_Setup.iss
```

### 2.4 スクリプト編集時の文字コード

`.iss` に **日本語コメント**を追加・編集する場合は **UTF-8** で保存する（Inno Setup **6.1 以降**では BOM なし UTF-8 も可。古い 6.0 系では **UTF-8 BOM** が安全な場合がある）。

### 2.5 配布までのチェックリスト（手順の流れ）

#### 2.5.0 リリース用バッチの引数早見表（1行表）

- `nuitka.bat [Mode]` : `Mode=full|bridge|svc|ui|runner`（省略時 `full`）
- `pack.bat [ReleaseVersion] [BinVersion] [ConfigVersion]` : 省略時は `VERSION.txt` 基準、未指定の `Bin/Config` は `ReleaseVersion` を使用
- `diff.bat [ReleaseVersion] [OldBinFullZip]` : 省略時は `ReleaseVersion=VERSION.txt`、`OldBinFullZip=dist\releases` から自動選択
- `cfg.bat <ReleaseVersion> [BinLatestVersion] [BaseBinFullZip]` : 第1引数必須、`BaseBinFullZip` 省略時は `dist\releases` から自動選択
- `full.bat [ReleaseVersion] [OldBinFullZip]` : `nuitka full -> pack -> diff` を順に実行（省略時は `VERSION.txt` と自動選択）

詳細は `release\README.txt` の「引数仕様（重要）」と「よく使う実行例」を参照。

1. **正本を準備する**（`release\pack.bat` / `release\full.bat`。詳細は **`Exe化（開発者向け）.md`**）
   - 共有またはローカル検証用に配布ルートを用意し、`catalog.json` と `catalog` が指す `full` zip を配置する。
   - `full` zip 展開後に `app\bin\hc_main.exe` が存在することを確認する。
2. **版情報を揃える**
   - `VERSION.txt`、`catalog.json` の bin 版、`CSV_Tool_Setup.iss` の `MyAppVersion` を同じ SemVer に合わせる。
3. **Inno Setup スクリプトを確認する**
   - **`DefaultDirName`**（既定は `{autopf}\Excel_Addin\CSV_Tool` → 多くの環境で `Program Files\Excel_Addin\CSV_Tool`）を確認。
   - 権限方針（`PrivilegesRequired` / `PrivilegesRequiredOverridesAllowed`）を運用に合わせる。
4. **`SHAREPAYLOAD` を決める**
   - 本番は UNC（例: `\\fileserver\releases\CSV_Tool`）を使用。
   - ローカル検証は `C:\...\release_payload` を使ってよい（**ビルド時**に `/DSHAREPAYLOAD` またはバッチ第 1 引数で渡すと `.iss` の既定を変えずに済む）。
5. **上記「ビルド方法」でコンパイルする**（`build_csv_tool_setup.bat` 推奨）。
6. **生成物を確認する**
   - `dist\` 配下に **`CSV_Tool_Setup.exe`** があること。
   - 実行前に SmartScreen／署名ポリシーに抵触しないか確認する。
7. **スモークテストを実施する**
   - 生成 EXE を実行し、インストール先を既定／変更の両方で確認する。
   - インストール後半で「catalog 読み取り→zip 展開→コピー」の進捗ページが表示されることを確認する。
   - 展開後に `app\bin\hc_main.exe` があること、`xlwings.conf` が `{app}` 基準で再生成されることを確認する。
8. **環境変数と更新導線を確認する**
   - `HKCU\Environment` に `HC_INSTALL_ROOT` / `HC_PACKAGED_DEPLOYMENT` / `HC_DEPLOY_ROOT` が設定されること。
   - `catalog.json` 参照・更新通知（起動時／リボン）の基本動作を確認する（**`インストールと運用`** §1.5・§3）。
9. **アンインストール検証を実施する**
   - アンインストール後に `HC_*` が削除されること、`{app}` の残置がないことを確認する。

**配布前チェック（最終）**

- 共有配布ルートの `catalog.json` と payload zip の内容が、実際に生成したインストーラの想定と一致している。
- `catalog.json` の版と同じ製品版を配布している。
- エラー時の案内（VPN/UNC/権限）とログ確認先（`{app}\logs\hc_update.log`）を手順書へ明記している。

## 3. 権限・UNC（ビルド検証時の注意）

- セットアップを **管理者として実行**すると、**昇格したプロセスからはユーザーの mapped drive が見えない**ことがある。UNC（`\\server\share\...`）を使うか、**管理者不要の per-user インストール**にして共有と同じユーザー文脈で読む、のいずれかを運用で決める（詳細は **`インストールと運用`** §1.2）。
