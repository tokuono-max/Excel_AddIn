## 1. 目的・スコープ

- 散在する Excel / CSV ファイルから、**特定の規則に従ってデータを抽出**し、**1つのマスターファイルへ統合・更新**するツールを開発する。
- ユーザーは「どのフォルダのどのファイルから、どの項目をどう取り、マスターのどこにどう書くか」を**シナリオとして定義**し、**保存・読込・実行**できることを要求する。編集・実行は**列単位（項目単位）**とする。**1項目（1列）をそろえるのに、複数ファイル（A, B, C 等）を参照することがある**。対象とするファイルはシナリオに設定した内容に従い決まる（走査は候補の収集に用いる。実行順は走査順とは一致しない）。

## 2. 機能要求概要

### 2.0 動作概要（統合パイプライン）

本ツールの実行は、次の**論理順序**で行う（中間表現・結合パイプラインの詳細は **§10.7** を参照）。

1. **主キー:** 項目一覧の**一番上**の行に対応するマスタ項目を**主キー（代表キー）**とする。フォルダ名／ファイル名からの書き込み先決定などで参照する既定のパス列の基準にも用いる（結合パス項目で別項目を選べる）。
2. **列生成（マスタ項目単位）:** 項目一覧の**上から順に**、各マスタ項目について「値列」と取得元を示す**パス情報列**を生成する。同一マスタ項目に複数シナリオがある場合は、取得結果を**縦方向に結合**し、対応するパス情報も同じ行数だけ付与する。
3. **全体結合:** 全マスタ項目の列生成が完了したら、ユーザーが登録した**結合キー（AND）**（メイン側の照合キー指定と整合する。**連携キーとは別**。複数項目選択時は **AND** で1組のキーとなる）に従い、内部の中間テーブル同士を結合し、**書込みモード**に沿ってマスター行への反映内容を確定する。
4. **出力:** 全体結合完了後、**アクティブシート**へヘッダ（マスタ項目名）を含めて書き出す（**本番は一括実行**がメイン画面からの出力経路。マスタ項目を段階的に確認する処理は **§3.1.3 デバッグ**で行い、デバッグでは本番マスタシートへは書き込まない）。

**補足（パス由来データの行対応）**

- フォルダ名から抽出した文字列は、主キーに紐づく**フォルダ名を含むパス情報**と一致する行の、当該マスタ項目列へ、書込みモードに従って書き込む。
- ファイル名から抽出した文字列は、主キーに紐づく**ファイル名を含むパス情報**と一致する行へ同様に書き込む。
- **結合パス項目 / 連携キー（フルパスで結合）:** 名前・パス文字列系では、詳細動作 **§3.2.3「連携キー（フルパスで結合）」** に従い、当該シナリオのフルパスと **連携項目** で指定したマスタ項目の列集合体内のフルパスが一致する行へ、本シナリオの値を関連付ける。本書・§2.0 補足でいう **結合パス項目** は、この **パス情報列との行対応** を指し、**UI 上の「連携項目」・「連携キー（フルパスで結合）」ブロック**と同一データ概念に対応する（実装・JSON の見出し語「結合パス／関連付け」はこれに相当し得る）。既定の基準項目は主キー（項目一覧先頭）。**§10.3.4** に従い実装する。

### 2.1 検索・ファイル特定

- 起点フォルダ（絶対パスまたは相対パス）を指定し、対象ファイルを収集する。
- 初期表示フォルダは `last_folder.txt` の記録値を採用し、ユーザーが変更した場合は同ファイルを更新する。
- 再帰走査の ON/OFF により、サブフォルダを含めるかどうかを指定できる。
- 対象とする拡張子は .xlsx, .xls, .csv（大文字小文字を区別しない）。
- ファイル名にキーワードを含むものに限定する、またはフォルダ内の全ファイルを対象とする、を選択できる。
- 一時ファイル（例: ~$ で始まるファイル）は自動的に除外する。

### 2.2 項目（マスター列）の定義方法

- **各項目（マスターの列）**は、次の**2種類の方法**のいずれかで取得・定義できる。
  - **アクティブシートの1行目から取得:** 現在アクティブな Excel シートの1行目（ヘッダ行）から項目名を読み取り、それをマスター列として使用する。
  - **ファイルから読込:** 項目一覧を定義したファイル（CSV / Excel 等）を読込み、その内容を項目として使用する。
- 読込んだ項目は**縦方向の一覧**で表示する。この一覧において次が行えること。
  - **項目名の変更:** 各項目の表示名・識別名をユーザーが編集できること。
  - **順番の変更:** 項目の並び順を変更できること。**連続選択**（複数行をまとめて移動）および**歯抜け選択**（飛び飛びに選択した複数行の一括移動）の両方に対応すること。
  - **順番変更時のシナリオ連動:** 項目の順番を変更した場合、**その項目に紐づくシナリオ（取得ソース・抽出ルール・書き込みモード等）も一緒に移動**すること。項目とシナリオの対応が崩れないこと。

### 2.3 データ抽出

- 各項目（マスターの列に対応）ごとに、**取得ソース**と**抽出ルール**を定義できる。
- **系統（取得ソースの大分類）**は次のいずれかである。
  - **セル座標系:** シート名とセル番地による絶対指定、または他項目を基準とした相対指定（オフセット）。繰り返し取得（値がなくなるまで縦/横に取得）に対応する。ファイル種別・シート名のフィルタ、終了区切り、正規化（トリム・全半角・日付形式等）は **§10.3** に従う（シナリオ編集 UI 上のファイル種別の扱いは **§3.1.2** と整合）。
  - **名前・パス文字列系:** フォルダ名またはファイル名（および必要に応じメタデータ）から、区切り文字・位置・正規表現等により値を抽出する。日付部分や識別子などを項目値として利用できること。**本シナリオ種別の主目的は、セル座標等で既に集約されたマスタ行を対象とし、不足しているセル値をパス由来で補うことである**（新規行をシナリオの書込みモードで追加する用途は想定しない。詳細動作 §3.2 参照）。
- **同一マスタ項目内の制約:** **セル座標系のシナリオ**と**名前・パス文字列系のシナリオ**を**同時には登録できない**（どちらか一方の系統のみ）。同一系統内では複数シナリオを登録でき、§2.0 のとおり縦結合される。
- **メタデータ（フルパス・フォルダ名・ファイル名の単純取得）**は、実装上はセル座標系または名前系のいずれかに含めて定義する（**§10.3** の分類に従う）。

### 2.4 データ書き込み・統合

- 抽出した値をマスターファイルに反映する際、シナリオごとに次の**書込みモード**を選択できる（最終行への反映ルールは **§10.4** に従う）。**本ツールでは次の2種のみとする**（名前から取得は既存集約行の補完が主目的のため、シナリオ単位の行追加・複製追加は不要）。
  - **空き上書き (Fill-in):** 対象セルが空の場合のみ書き込む。
  - **強制上書き (Overwrite):** 対象セルに既存の有無にかかわらず上書きする。
  - ~~**行追加 (Append)**~~ / ~~**複製追加 (Duplicate append)**~~：**シナリオ書込みモードとしては提供しない**（旧版の §10.4.3 記述は廃止。実装・JSON からも除外する）。
- **照合キー（結合キー）**を設定し、マスターの既存行とキー一致した場合は更新、一致しない場合は行追加またはスキップとする動作を選択できる。  
  **照合キー**とは、マスターの既存行と突き合わせるために使う、抽出データの**1つ以上の項目**（列）のこと。**内部の全体結合**において複数列を指定する場合、各列の値の組み合わせが **AND 条件の結合キー**となる（同一キー組で一意な行を識別する）。  
  **照合キーの指定方法:** ユーザーが文字列を直接入力するのではなく、**マスター列として定義済みの項目（縦一覧に表示されている項目）の中から、どれを照合に使うかを選択**する。複数項目を選んだ場合は、それらの組み合わせで1件の行を一意に識別する。  
  **用語の関係:** 本書の**照合キー**と、§2.0 の**結合キー（AND）**は、いずれも「定義済みマスタ項目の複数選択による**照合用キー**」であり、**同一 UI・同一データ**を指す（**連携キー・連携項目を含まない**）。文脈により「既存マスタ行との照合」または「中間テーブル間の JOIN」を強調する場合に使い分ける。  
  **列単位編集と照合キー:** 1項目（1列）をそろえるのに複数ファイル（A, B, C 等）を参照する場合、それらのファイル間で**行を揃えるために照合キー（結合キー）が必要**になる。そのため、複数ファイル参照を扱う本ツールでは**列単位で編集・実行**し、**結合キー**で行の対応づけを行う構成とする。
  **反復整合（確定）:** 1 ファイル内で主キーを N 件取得した場合、連携キー・結合キーも **同じ N 反復**で評価する。連携/結合の取得件数が不足する場合は**末尾値を再利用せず空欄**とする。行対応は `file_path + iter_index` の 1:1 を基本契約とする。
  **連携キー（セル座標系）:** **結合キーとは別のブロック**である（詳細動作 **§3.1.5**）。**主キー**と連動して、別セルから補助的に値を取得する。行/列移動オフセットは**連携キー定義の値（独自オフセット）**を用いる。未設定時は連携する値はない。**連携項目**に指定されたマスタ項目は、当該シナリオの登録・実行から除外し、データ集約画面の項目一覧では**該当行をグレイアウト**して選択不可とする。複数定義は **＋連携キー追加** により行う。
  **連携キー（名前・パス文字列系）:** **フルパスで結合**する指定（詳細動作 **§3.2.3**）。**連携項目**でマスタ項目を選び、列集合体内のフルパス一致により行位置を決める。**結合キー（AND）とは別概念**である。
  **連携キーと結合キーの関係:** **中間テーブル同士の JOIN・既存マスタ行との行一意性の照合に用いる AND キーは結合キー**である。**連携キー**は、(1) セル系では主値取得に付随する**補助セル値の取得**、(2) 名前系では **フルパスによる行の関連付け**を担う。**連携キーを結合キーの別名とみなさない。** 連携・結合の設定が同一代入先で競合する場合は、当該主値シナリオの**書込みモード**（**空き上書き / 強制上書きのいずれか**）に従って最終反映を決定する（詳細は §10.4）。

### 2.4.1 あふれ・結合失敗データ

- 結合データが存在しない、キーが取得できない、パス不一致などにより結合できなかった行・項目については、**別シートにイベントログ形式**で記録できるようにする（時刻・理由コード・シナリオ識別子・対象パス・取得できたキー範囲等）。ログのみとするか、マスターに空行＋フラグ列を付けるかは **§10.8** またはオプションで定義する。
- **運用方針（確定）:** 結合失敗・照合不一致などで**都度の問い合わせダイアログは出さない**。発生のたびに **§10.8 のイベントログ**へ追記し、**本番一括実行終了時**に操作者が結果を確認できるよう、**完了通知または実行サマリ表示に「結合エラー」等のタグ／件数（結合失敗の総数）**を含める（文言・キーは `config/ui_data_agg.json` の `MESSAGES` / `SCREENS.DONE` 等で定義してよい）。

### 2.5 実行制御・例外処理

- **一括実行**では、項目一覧の順に全ステップ（全項目）の処理が完了した時、またはデータ取得の終了判定値に達した時点で終了する。
- ファイルロック・型不一致・シート不在などの例外について、スキップ／リトライ／エラー停止などの方針を選択できる。
- **運用ログ:** 処理の主要イベントは core ログに **[DATA_AGG]** プレフィックスで出力する（**§8**）。

### 2.6 中間処理ライブラリ

- 内部の表形式データの結合・変換において、**Polars** が利用可能であれば優先的に用いる（Excel 入出力は OpenPyXL／csv 等と併用。I/O 境界は **§10.7.3**）。

## 3. UI 要求

シナリオ編集の**ブロック順・画面上の名称**（連携キー／結合キー／連携項目等）は **`データ集約機能詳細動作.txt` §3** を正とする（本節は要件・実装追補と JSON との対応を記す）。

### 3.1 画面レイアウト

- **メイン画面**には、項目一覧とシナリオの**要約**を表示する。詳細なシナリオ編集は行わない。
- **シナリオ編集はメイン画面とは別画面**で行う。編集画面で取得ソース・抽出ルール・書き込みモード等を設定し、**要約だけをメイン画面に表示**する。
- メイン画面の要約表示では、**縦軸に項目一覧**を配置し、**各項目（列）ごとのシナリオ要約**（参照するファイル・取得手順など）を確認できること。1項目が複数ファイルを参照する構成に対応する。
- メイン画面タブ1のシナリオ要約列は表示幅で字切れし得るため、**要約全文をツールチップで確認できる**こと（§11.2。シナリオ編集一覧の要約と同趣旨は §3.1.1）。
- 項目一覧は、§2.2 のとおり**アクティブシート1行目**または**ファイル読込**のいずれかで取得し、**縦表示**とする。表示後は項目名の変更・順番の変更（連続／歯抜け選択可）が行え、順番変更時は当該項目のシナリオも連動して移動すること。**シナリオの実行順は、この項目一覧の縦並び順（上から下）**とし、項目の並び替えにより実行順を制御できること（走査順とシナリオ・実行順は一致しない）。

### 3.1.1 シナリオ編集画面

- 編集対象のマスタ項目を **項目名：＊＊＊** のように表示する。
- **シナリオ一覧表**を表示し、行の追加・複製・削除および **ソース順の▲／▼**（評価順の入れ替え）ボタンを設ける。
- **取得ソース（シナリオ）削除とメイン画面の整合:** 一覧から取得ソースを削除したとき、**ダイアログを閉じなくても**メイン画面の当該項目のシナリオ要約等が**即時に更新**されること（**登録**ボタン押下時と同様に、親画面へ `sources` を反映する）。
- **元に戻す（1回限り・削除／登録の直前状態）:** **元に戻す**ボタンは**常時表示**とし、有効時のみ操作可能とする。保持するのは**単一世代**で、**直近の「削除」または「登録」のいずれかの直前**の `sources` 状態である（後から行った操作で上書き）。**元に戻す**実行後、または**キャンセル**（ダイアログを閉じる）で保持をクリアする。文言は `config/ui_data_agg.json` の **`SCREENS.SCENARIO_EDIT.BTN_UNDO_REMOVE_SOURCE`** で管理する（§12.4）。
- 各行に**種別**（セル座標から取得／名前から取得）と、設定内容の**要約（日本語）**を表示する。
- シナリオ一覧の要約は表示幅で字切れし得るため、**要約全文をツールチップで確認できる**こと。
- **種別**に応じて詳細パネルを切り替える。**セル座標から取得**は、ファイルフィルタ・シート条件・**主キー**・**連携キー**・**結合キー** の UI（詳細動作 **§3.1.2〜§3.1.6**、**§10.3**・**§3.1.2**）。**名前から取得**は、検索条件・文字列抽出・**連携キー（フルパスで結合）** の UI（詳細動作 **§3.2**、特に **§3.2.3**）。実装・JSON で **結合パス／関連付け** と表記するブロックは、**連携キー（フルパスで結合）** に対応する（§2.0 補足・§10.3.4）。
- 同一項目内で §2.3 の系統排他に反する組み合わせは、保存時または入力時に拒否する。

#### 3.1.2 シナリオ編集 UI（実装・設定の追補）

### 3.1.3 デバッグ画面 UI（確定案）

**本番 UI の正:** 画面文言・列見出し・タブ名・ボタン等は **`config/ui_data_agg.json` の `SCREENS.DEBUG`**、構築は **`ui_qt/ui_data_agg_debug.py`**（`ui_qt/ui_data_agg.py` から起動）。デバッグ実行は本番マスタに組み込まない（§3.2・画面一覧 No.12/13 と同一）。**実装モジュール・内蔵デモデータの扱いの詳細は §3.1.3.2 を正とする。**

- **起動:** メイン画面およびシナリオ編集から、**同一レイアウト**のデバッグウィンドウを開けること。**利用モードは起動元に固定**する（下表）。**ユーザー操作によるモード切替は行わない**（同一レイアウトでも、あくまで**どの画面から開いたかに紐づく利用文脈**として区別する。画面上部にモード名やヒントを**表示のみ**してよいが、コンボ等で他モードへ切り替える UI は設けない）。

| 起動元 | デバッグウィンドウのモード（固定） |
|--------|-------------------------------------|
| **データ集約メイン画面**の **デバッグ**（`BTN_DEBUG`） | **マスタ項目ステップ実行モード**（マスタ項目単位の想定） |
| **シナリオ編集**の **デバッグ**（実装キー例: `BTN_STEP_SCENARIO`。**画面表記は「デバッグ」**とし、「ステップ実行」とは名付けない §11.7） | **シナリオフェーズステップモード**（シナリオ単位・条件フェーズの想定） |

- **画面構成:** 左：登録シナリオ一覧**または**マスタ項目一覧（モード依存）＋条件ステップ表（番号・条件項目・設定）＋選択詳細。右：**タブ**「条件」「結果」「ログ」。下部：実行・スキップ・結果クリア・ログクリア・キャンセル。
- **条件タブ:** 列「番号／項目／設定」のツリー表示。**親「設定項目」行のみ全列を薄グレー**とし、子行は項目列をグレーにしない。第 3 列はシナリオ編集と同様、**行単位の説明**（データ上は `editor_lines` 相当の複数行）を想定する。
- **結果タブ:** **サマリー表**（先頭列「フェーズ」＋ファイルフィルタ・シート名・主キー・連携・結合キー等の指標列）と、**取得値グリッド**（フェーズ／ステップ列が右方向に増える）。**サマリー列見出しは 2 行相当のコンパクト表示**とし、横方向の字切れを避ける（専用ヘッダ描画を許容）。
- **サマリー表の指標セル:** 未設定・該当なしを表す内部プレースホルダ（実装上 `"-"` 等）は、**サマリー表上は空欄表示**とし、ログや永続データ・内部状態の表現は実装に従う（先頭列「フェーズ」はこの限りでない）。
- **ログタブ（ステップ単位・共通）:** 各 **実行／スキップ** のたびに **ステップ実行ログ**（フェーズ番号・条件ラベル・サマリ指標の要約等）を追記する。あわせて、§10.8 の **イベントログ** と**同一の意味・列項目**（時刻・理由コード・シナリオ識別・参照パス・キー値・詳細等）を満たす行を、**当該ステップで発生した分だけ**テキスト（JSON 行や区切り行を含めてよい）として追記する。これを **「イベントログシート相当」** と呼ぶ。**デバッグ中は既定で Excel の `DataAgg_EventLog` シートには書かず**、本タブに集約する（本番実行時のシート出力との役割分担は下記 §3.2・§10.8 と §10.10 Q1 を参照）。
- **結果タブとログタブの役割分担（両モード共通）:** **取得データの閲覧・サマリの主表示は結果タブ**とする。**ログタブ**は **実行履歴のテキスト**および **結合失敗等のイベント行**に用い、結果タブの表と同じ内容をログタブに重ねて載せることは**要求しない**（必要ならイベント詳細に JSON 等で要約する）。
- **表示上限（デバッグ用）:** フェーズ／ステップごとに取得値は最大 **MAX_VALUE_ROWS** 件（例: 50）で打ち切り。**条件スロット数上限 MAX_PHASE_SLOTS**（例: 16）は、上記 50 件制限とは**別定義**とする。
- **シナリオフェーズモード（シナリオ単位ステップ）:** 選択シナリオについて、ファイル・シート・主キー・**連携キー**・**結合キー**を**ステップ表示**し、**取得した値の確認は結果タブを主とする**（ログタブは上記「結果／ログの役割分担」に従う）。**本番のマスタシートへの書き込みおよび本番一括用の内部チャンクへの取り込みは行わない**（終了時に破棄してよい）。**取得ソースが登録されている実項目**については **`svc_data_agg_extract.extract_item_bundle`** により本番と同一経路で段階指標・値列を更新する（実装は `svc_data_agg_debug_run.scenario_debug_phase_result`）。**`live_items` が無い**ときは**空状態プレースホルダ**（実行ステップなし）のみ表示し、デモ用の固定シナリオは**同梱しない**。シナリオを切り替えても**別シナリオの結果・ログは保持**する（スナップショット）。**結果**のクリア：専用ボタン、**キャンセル**、**ウィンドウ閉鎖**。**ログ**のクリア：専用ボタンと**ウィンドウ閉鎖**のみ（**キャンセルではログを消さない**）。
- **マスタ項目ステップモード（デバッグ・マスタ項目単位）:** マスタ項目（および結合に必要な依存項目があればそれら）について、**本番一括と同一の抽出・項目横断結合ロジック**（`svc_data_agg_extract` / `svc_data_agg_pipeline` 等）で集約処理を行うが、**動作確認専用**である。**アクティブブックのマスタシート（本番マスター）へは一切書き込まない**。**集約結果の閲覧は結果タブを主とする**；イベント・実行ログは **ログタブ**（上記「結果／ログの役割分担」）。本番のマスタへ反映するのは **メインの一括実行のみ**とし、**メイン画面に「ステップ実行」ボタンは置かない**。結果サマリー・取得値は**セッションで積み重ね**（項目をまたいでもクリアしない既定）とする。
- **ウィンドウ終了:** シナリオフェーズモードでは、現在シナリオの状態を保存したうえでスナップショットを破棄してよい（プロセス終了前提）。

### 3.2 対象ファイル一覧と実行

- **対象ファイル一覧を、パス付きで別途リスト画面に表示**すること。対象ファイルは**シナリオに設定されているファイル**に基づき決まる（走査で得た候補から選ぶ、またはシナリオで指定したファイルを一覧表示する）。一覧の並び順はユーザーが編集可能とし、走査順と一致しない実行順に対応できること。
- **実施中も一覧を表示したまま**とし、**現在処理中の項目**および**その項目が参照しているファイル**が分かるようにすること（例: 処理中行のハイライトやインジケータ表示）。実行単位は項目（列）のため、表示は「どの項目を処理中か」を主とし、対象ファイル一覧ではその項目が参照するファイルを強調する等で対応する。
- **進捗表示:** 実行中は**進捗画面**を表示し、現在の処理フェーズ（走査・抽出・結合・書き込み等）が分かること。可能な範囲で **N/M 形式**（例: 項目 3/10、ファイル 12/50）のステップ表示を含める。
- 対象ファイル一覧での進捗表示（例: 処理済みファイル行の背景色をグレイにする）は**必須としない**。実施中と完了の区別は、設計・実装で判断する。
- 一覧画面に**確認ボタン**を設け、押下により実行モードを選択して開始できること。

**実行モード（2区分）**

| モード | 概要 |
|--------|------|
| **本番一括実行** | §2.0 のパイプラインを最後まで連続実行。結果は内部で組み立て、**終了時にマスター（アクティブシート）へ一括出力**。**メイン画面から起動する本番経路はこれのみ**とする。 |
| **デバッグ実行** | 本番マスタに**組み込まない**検証用。**シナリオフェーズモード**と**マスタ項目ステップモード**は **§3.1.3 の起動元表**で固定され、**同一ウィンドウ内でのモード切替は行わない**。 |

- **デバッグ・シナリオ単位（シナリオフェーズモード）:** §3.1.3 のとおり。**取得の主表示は結果タブ**（対象ファイル・取得値・連携キー・結合キーをステップ表示）。**本番マスター（Excel）へは書き込まない**。**ログタブ**にはステップ実行ログと **§10.8 相当のイベント行**のみ（結果表の重複表示は要求しない）。
- **デバッグ・マスタ項目単位（マスタ項目ステップモード）:** §3.1.3 のとおり。**本番一括と同一ロジック**で抽出・結合まで行うが**動作確認専用**。**アクティブマスタシートへは書き込まない**。集約結果の**主表示は結果タブ**、ログ・イベントは **ログタブ**（§3.1.3「結果／ログの役割分担」）。全体 JOIN を含めること。
- **マスタ項目ステップモードの実行単位（確定）:** 1 ステップは**1 マスタ項目内で完結**し、当該項目のシナリオに含まれる **主キー／連携キー／結合キーを同時取得**する。**マスタ項目間の引継ぎは行わない**。表示上のフェーズが分かれていても、対象ファイル・反復インデックス・基準座標の文脈は当該項目内で一貫して扱う。
- **フェーズ文脈引継ぎ（確定）:** フェーズ表示で段階実行する場合も、次フェーズは **主キーフェーズで通過したフィルタ済みファイルのみ**を対象とする。再走査で全件化しない。主キーから次フェーズへ渡す `iteration_contexts` は少なくとも `file_path` / `iter_index` / `base_cell` または `base_row, base_col` / `filter_snapshot`（通過ファイル集合）を保持する。
- **フェーズ反復評価（確定）:** シナリオフェーズ表示では、上記 `iteration_contexts` を用いて主キーの反復単位で連携キー・結合キーを評価する。`iter_index` が一致しない値は同一行へ代入しない（不足分は空欄）。

- **マスタ項目の段階確認の見せ方:** メインの本番ボタンではなく **デバッグ（マスタ項目ステップモード）** で、実行／スキップにより **結果タブ**（取得・集約の閲覧）と **ログタブ**（履歴・イベント）へ積み上げる。参照ファイルの強調等はデバッグ／タブ2の範囲で設計する。

### 3.3 シナリオの保存・読込・再利用

- 作成したシナリオを**任意の名前で保存**できること。
- 保存したシナリオファイルを**読込**し、**メイン画面に反映・表示**できること。読込後はメイン画面で内容を確認し、**編集**（シナリオ編集画面での変更および要約の再表示）が行えること。
- 読込んだシナリオについて、**一括実行**（本番）および**デバッグ**（検証）が行え、再利用できること。

## 4. 非機能要求

- **メモリ:** 大量ファイルを扱う場合、ファイル単位でメモリを解放し、マスターへの書き込みはバッファリングする。**一括実行**時は結果を内部メモリで組み立て、終了時にマスターへ一括出力する。
- **性能:** Excel アプリケーションを起動せず、OpenPyXL 等による直接ファイル操作を想定する（**§10.6**）。

## 7. 作成モジュール案

本プロジェクトの「機能ごとセパレート」に合わせ、以下のモジュールを新規作成する案とする。機能キーは **data_agg**（データ集約の略）を想定。

| 種別 | モジュール・ファイル | 役割 |
|------|----------------------|------|
| **設定** | config/ui_data_agg.json | メイン画面・進捗・完了・ワーニング・フォルダ選択等の文言・ウィンドウ設定。**シナリオ編集**は `SCREENS.SCENARIO_EDIT`（スプリッタ・`DETAIL_CELL` / `DETAIL_NAME` 等）。**キー説明の正本は本書 §12**。プロジェクトの JSON 機能一覧（**docs/共通仕様_JSON定義.md**、例: §7）への掲載は横断索引用であり、仕様の優先順位は本書。 |
| **サービス** | svc/svc_data_agg.py | フォルダ走査、抽出エンジン呼び出し、マスター書き込み、シナリオの保存・読込・**一括実行**のオーケストレーション（メイン本番は一括のみ。`step_run` 等の旧経路は廃止またはデバッグ専用へ寄せる）。進捗・完了は IPC で ui に依頼。**機能を一つの svc_data_agg に寄せるとモジュールが肥大化するため、フォルダ走査・抽出ロジック・シナリオ読込/検証などはサブモジュールまたは別モジュールに分離することを推奨する。** |
| **UI** | ui_qt/ui_data_agg.py | メイン画面（項目×シナリオマトリクス）、シナリオ編集ダイアログ本体、シナリオ保存/読込、一括実行・完了・**デバッグ起動**の create_dialog。設定は ui_data_agg.json から読込。 |
| **UI（デバッグ）** | ui_qt/ui_data_agg_debug.py | デバッグウィンドウ（§3.1.3）。文言・列見出しは JSON の **`SCREENS.DEBUG`**。メイン・シナリオ編集から起動。**内蔵デモデータは持たない**（本番コードパス外の補助スクリプトに依存しない）。 |
| **UI（シナリオ詳細レイアウト）** | ui_qt/ui_data_agg_scenario_layout.py | シナリオ編集右ペインの詳細フォーム（セル座標系／名前から取得系）の QWidget ツリー構築。`ui_data_agg.py` から import される。文言・幅等は JSON の `DETAIL_*` を参照。 |
| **エントリ** | hc_main.py, svc/svc_server.py | コールバック関数の追加、_ACTION_MAP に "data_agg" を追加、_ALLOWED_SVC_ACTIONS に追加。 |

**モジュール肥大化の防止（推奨）:** 機能を svc_data_agg に寄せすぎると単一ファイルが大きくなり保守性が下がる。以下を推奨する。

- **抽出エンジン:** 座標・メタデータ・フォルダ名・ファイル名からの抽出ロジックを **svc_data_agg 内のサブモジュール** または **core 配下の別モジュール** に分離する。
- **フォルダ走査:** 対象ファイル収集ロジックをサブモジュールまたは共通ユーティリティに分離する。
- **シナリオ形式・検証:** シナリオの保存形式（JSON 等）の定義と読込時検証を、svc_data_agg 内の専用クラス/関数または別モジュールに持たせる。

## 9. その他

### 9.1 用語（本要求定義書内）

| 用語 | 意味 |
|------|------|
| **項目** | マスターファイルの列に対応するデータの種類。ユーザーが定義する項目名と取得ルールの組。 |
| **シナリオ** | **項目（列）ごと**の「どのファイルから・どう取得し・マスターのその列にどう書くか」の一連の設定。1項目が複数ファイル（A, B, C 等）を参照する構成をとれる。対象ファイルはシナリオで設定した内容に従う。 |
| **ステップ（内部）** | **本番一括**の内部では、項目一覧の**上から下**が処理順（1項目＝論理ステップに相当）。**メインに「1項目ずつ書く」UIは置かない**。項目単位の段階確認は **デバッグ** で行う。 |
| **（廃止）本番ステップ実行** | メインからの「ステップ実行」は**要求しない**。マスタ項目の段階確認は **デバッグ（マスタ項目ステップモード）** で行い、本番マスタへは書き込まない。 |
| **本番一括実行** | **本番の既定モード**。全ステップを連続実行。内部メモリで組み立て、**終了時にマスターへ一括出力**。 |
| **デバッグ実行** | シナリオフェーズ文脈またはマスタ項目ステップ文脈で検証し、本番マスタに**書き込まない**。**起動元で文脈が決まり、モード切替はしない**（§3.1.3）。 |
| **マスター** | 抽出結果を統合・更新する対象の Excel/CSV ファイル。 |
| **取得ソース** | セル座標、メタデータ（パス・フォルダ名・ファイル名）、またはフォルダ名・ファイル名に含まれる文字列。 |
| **照合キー** | マスターの既存行と突き合わせるために使う、抽出データの**1つ以上の項目（列）**。**定義済み項目の中からユーザーが選択**する（直接入力ではない）。キー一致した行は更新、一致しない行は追加またはスキップの対象とする。実体は **結合キー（AND）** と同一視する（§2.4）。 |
| **結合キー（UI・シナリオ編集）** | **中間表の JOIN・行一意の照合に用いる AND キー成分**。セル座標系では詳細ペインの **結合キー取得** ブロックで指定（詳細動作 **§3.1.6**）。ユーザー向けには **「照合キー」ではなく「結合キー」** 表記。種別直下の一括チェックは置かない。**連携キーとは別ブロック**である。 |
| **連携キー（UI・シナリオ編集）** | **結合キーとは別**。セル系では **主キーと連動した補助セル取得**（詳細動作 **§3.1.5**）。名前系では **フルパス一致による行関連付け**（**連携キー（フルパスで結合）**、**§3.2.3**）。 |
| **連携項目** | 連携キー設定で参照する**マスタ項目名**の選択。セル系では詳細動作 §3.1.5 に従い、選ばれた項目の登録・実行スキップと一覧グレイアウトの対象となり得る。 |
| **結合項目** | **結合キー**ブロックで、取得セル値と突き合わせる**マスタ項目名**の選択（詳細動作 **§3.1.6**）。 |
| **結合パス項目（内部・本書 §2.0）** | 名前由来データをどの**パス情報列**と行対応させるかの指定。詳細動作の **連携キー（フルパスで結合）・連携項目** のデータ概念に対応（§2.0 補足・§10.3.4）。 |

### 9.2 シナリオの保存形式（案）

- シナリオは **JSON** で保存することを推奨する。項目一覧、シナリオごとの取得ソース・抽出ルール・書き込みモード、**連携キー**・**結合キー**・走査条件（起点・再帰・拡張子・キーワード）を格納する（フィールド名は実装に従う）。
- 拡張子は .json または .scenario 等、プロジェクトで統一する。

### 9.3 制約・前提

## 10. 詳細仕様（内部ロジック・抽出・書込・パイプライン）

### 10.1 本節の位置づけ

散在する Excel/CSV から規則に従って抽出しマスタへ統合する**内部ロジック**を定義する。§2〜§3 の要求と矛盾する場合は **§2〜§3 を優先**し、本節は実装・設計の参照用とする。

### 10.2 検索・ファイル特定（走査）

- **ディレクトリ指定:** 絶対/相対パスによる起点フォルダ。
- **再帰走査:** ON 時はサブフォルダ全階層を探索。
- **フィルタ:** 拡張子 .xlsx / .xls / .csv（大小無視）、キーワード（ファイル名部分一致）、一時ファイル（`~$` 開始等）自動除外。

### 10.3 データ抽出詳細（抽出エンジン）

#### 10.3.1 座標による取得

- **絶対位置:** `[シート名]![セル]`（例 Sheet1!B5）。
- **相対（オフセット）:** 同一ファイル内の他項目セルを Anchor とし、±行・±列移動。
- **多重取得:** 「空白まで」等で縦/横に連続取得し、レコード分割。

#### 10.3.2 メタデータによる取得

- **ソース:** Full Path / Directory Name / File Name。
- **ルール:** 範囲指定、デリミタ分割（第 n 要素）、正規表現。

#### 10.3.3 セル座標系シナリオ（ファイル種別・シート・終了区切り）

- 同一マスタ項目は §2.3 に従いセル系と名前系のどちらか一方のみ。
- **ファイル種別（エンジン・走査）:** .xlsx / .xls / **.csv** を対象に含め得る。**シナリオ編集 UI（§3.1.2）**のセル系詳細では **.xls / .xlsx のみ**（CSV はメインの走査タブ等と組み合わせて扱う想定）。
- **ファイル名判定（シナリオ編集・セル系）:** **完全一致**／**含む**／**含まない**をコンボで選択し、**ファイル名**入力と組み合わせて対象ファイルを絞る。**ファイル名が空欄のときはフィルタなし**（全候補が対象）とする。**カンマ `,` 区切りで複数指定可**（先頭・末尾・連続カンマや空白のみの要素は無視。例: `,光特性,紐づけ,` → `光特性` / `紐づけ`）。**含む／完全一致**はいずれかのトークンに該当（OR）、**含まない**はいずれのトークンも含まない。照合は拡張子を除くファイル名（stem）、大小文字は区別しない。結合プール／出力行判定も抽出と同じルールで評価する。保存時は、**各取得ソース（セル座標系）の保存ブロック**（§9.2・実装ではキー `ui_scenario_source_v1`。既存ファイルの旧キーは読込のみ互換）に **`file_name_rule`**（表示文言）および **`file_pattern`**（生文字列）を格納する。抽出エンジンでの適用は **§10.9** の実装に従う。
- **ファイル名判定の適用順（推奨・実装指針）:** 走査（`scan` の起点・再帰・拡張子・キーワード）で候補一覧を得た**後**、各取得ソース（シナリオ）ごとに `file_name_rule` / `file_pattern` を**追加の AND 条件**として適用する。`file_pattern` が空（トークンなし）のときは当該ソースのファイル名追加フィルタは**適用しない**（走査条件のみ）。ファイル名の大小文字は**区別しない**（Windows 実装に合わせる）。
- **シート名判定:** **左端シート** / 完全一致 / 含む / 含まない。左端シート時はシート名入力は不要（pattern 無視）。**完全一致／含む／含まない**ではシート名を**カンマ区切りで複数指定可**（パース規則はファイル名と同じ）。**含む／完全一致**は OR、**含まない**はいずれも含まない。**空欄（トークンなし）**は該当なし。シート名の大小文字は既定で区別する。シート名自体に `,` を含む場合は区切れない（既知制限。ファイル名も同様）。
- **左端シートの定義明確化:** ここでいう「左端シート」は**ブックの物理先頭（左端タブ）シート**を指す。シート名のプレフィックス一致を意味しない。
- **主キー:** セル座標、行・列オフセット、終了区切り（N 件 / 空白まで）、チェック（トリム等）、**整形（DSL）**、**書込みモード**はシナリオ単位（§3.1.2・§10.4）。**UI に正規化・置換（正規表現）欄はない**（旧 JSON に残る `normalize` / `replace_cell` は抽出で**無視**）。
- **主キー値の加工パイプライン（抽出エンジン・2026）:** セル主値は **①チェック（トリム等）→②整形（`value_shape_script`）** の順で適用する。整形 DSL は **`core.core_value_shape`**。スクリプトの**先頭レベル**トークン区切りは **カンマ `,` またはセミコロン `;`**（同等。詳細は `docs/データ集約_整形DSL_コマンドリファレンス.md`）。`rep` は部分文字列の**すべて**を置換。リテラルは **CSV 方式の二重引用符**（内側の `"` は `""`）。`mid` / `cut` / `ins` は **1 始まり**。メタデータ／ファイル名由来の主値も同様。`validate_scenario` は `value_shape_script` の構文を簡易検証する。
- **連携キー取得（セル座標系）:** **主キーと別ブロック**（詳細動作 **§3.1.5**）。主キーと連動した別セル（または固定値）からの取得。各行に **加工（チェック）** と **`link_defs[].value_shape_script`（整形 DSL）** を指定できる。適用順は **チェック → 整形**。旧 `normalize` / `replace` は**無視**。**連携項目**・**＋連携キー追加** による複数定義。参照先マスタ項目のグレイアウト・実行スキップは §2.4・詳細動作に従う。
- **結合キー取得（セル座標系）:** **連携キーとは独立**（詳細動作 **§3.1.6**）。マスタ間の **AND** 照合成分。セル座標、行・列オフセット、**結合項目**、**＋結合キー追加** による複数定義（UI に加工・整形欄はないが、実装上は連携と同じ後処理関数を通り、JSON にキーがなければ実質無変更）。複数定義時は **AND** で 1 組のキー列を構成する。
- **連携/結合の反復規約（確定）:** セル座標系では、主キーの繰返し方向（縦/横）に応じて基準セルを `iter_index` 分だけ進め、そこへ連携/結合の独自 row/col オフセットを加算して取得する。これにより各キーは主キー N 反復と同じ回数で評価される。
- **CSV のシート:** シート概念なし。シート名は無視し単一ブロックとして読む。

#### 10.3.4 パス・名前文字列系

- 検索対象・条件、取得開始（先頭/位置/区切り）、取得長さ、正規表現・置換・正規化、チェック（トリム等）、**整形（`value_shape_script`）**、書込みモード。
- **名前から取得の主値加工順:** 文字列抽出および **`extract_from_name` 内の正規表現・置換**の後、**チェック**、最後に **`value_shape_script`**（セル主キーと同じ DSL・`core.core_value_shape`）。`rep` は**すべて置換**。
- **連携キー（フルパスで結合）:** 詳細動作 **§3.2.3**。当該シナリオの**フルパス**と、**連携項目**で指定したマスタ項目の列集合体内のフルパスが一致する行の、本シナリオのマスタ項目位置へ値を関連付ける。**結合キー（AND）とは別**である。
- **結合パス項目（内部呼称）:** §2.0 補足のとおり、**パス情報列との行対応**を指す。実装・旧 UI 文言では **結合パス／関連付け** と表す場合があるが、詳細動作上の **連携キー（フルパスで結合）・連携項目** と同一データ概念に対応する。既定は主キー（項目一覧先頭）。フォルダ名由来→フォルダ名を含むパス一致行、ファイル名由来→ファイル名を含むパス一致行へ書込（§2.0 補足）。
- **由来パス列（`join_path_item_id`）:** シナリオ JSON の `items[].join_path_item_id` で、**正規化フルパス**を格納するマスタ列を `items[].id` または `name` で指定する。**省略時は項目一覧先頭列**。シナリオ編集画面では種別コンボの下にコンボを置き、全マスタ項目から選択する（文言キーは `SCENARIO_EDIT`）。
- **パス正規化（実装単一入口）:** `pathlib.Path.resolve()` 相当で絶対パス化し、内部比較用の文字列は **POSIX 区切り（`/`）** に統一する。**Windows では大文字小文字を区別しない**（`casefold`）。実装は **`svc.data_agg_path_norm.normalize_source_path`**。フルパス文字列の生成・行照合はこの結果を用いる。
- **セル座標系でも由来パス列を埋める:** セル取得のみの項目でも、走査中ファイルについて **由来パス列**に上記正規化フルパスを主キー反復ごとに付与する（一括・デバッグの `extract_item_bundle` 経路で統一）。
- **名前から取得（`name_extract` のみの項目）の行割当（確定）:** **ファイル名モード**では、内部の由来パス（正規化）が **当該走査ファイルの正規化フルパスと一致する行**のみ当該項目列へ抽出値を書く。**フォルダ名モード**では、由来パスが **当該ファイルの親ディレクトリの正規化フルパス配下**（ディレクトリ自身と一致も含む）にある **すべての行**へ同一抽出値を書く（`iter_index` をまたぐ）。詳細動作 **§3.4**。
- **同一項目内の系統混在:** §2.3 のとおり **不可**。`validate_scenario` でエラーとし、シナリオ編集では種別変更時に **ダイアログで拒否**する。
- **取得ソースの順序:** シナリオ一覧の **▲／▼** で `sources[]` の順を入れ替える。`extract_item_values` は定義順にソースを評価する（§3.1.1・`SCENARIO_EDIT` の `BTN_SOURCE_UP` / `BTN_SOURCE_DOWN`）。

### 10.4 データ書き込み・統合

- **シナリオ単位の書込みモード（確定・2026 改訂）:** **Fill-in（空き上書き）**と **Overwrite（強制上書き）**の **2種のみ**。**Append（行追加）・Duplicate append（複製追加）は本ツールでは採用しない**（名前取得を含む用途は「既に集約された行」のセル補完が主であり、シナリオ側で新規行を増やすモードは不要とする。§2.3・詳細動作 §3.2 と整合）。
- **Overwrite / Fill-in** のセル単位の意味は §2.4 と同趣旨。**照合キー（結合キー）**により既存マスタ行と突き合わせる処理や、**キー不一致時にメイン画面で選ぶ「行追加／スキップ」**（`match_no_key_action` 等）は、**シナリオ書込みモードとは別レイヤーのオプション**として §2.4 に従う（必要に応じ本節で整理する）。
- **適用範囲:** シナリオ単位の書込みモードは各シナリオの中間列のセル単位に適用。全体結合後のマスタ出力は §10.7 のパイプラインで確定した行に対し、**本番一括実行**のルールに従う。
- **連携キー・結合キーと競合:** **連携キー**（セル系の補助取得、名前系のフルパス行対応）と **結合キー（AND）** は役割が異なる（§2.4）。同一代入先で設定が競合する場合は、**最終的な採否・上書き可否は主値シナリオの書込みモードを優先**する。複数の連携・結合指定が同一代入先を指して競合した場合も同様とする。
- **連携項目指定時の実行制御:** **連携項目**（セル系・名前系）で参照元に選ばれたマスタ項目は、詳細動作 **§3.1.5** に従い、当該シナリオの登録・実行から除外する。循環参照・重複実行を避ける。UI では該当行をグレイアウトして編集不可状態を示す（詳細条件は実装で固定）。

#### 10.4.3 複製追加（duplicate_append）— **廃止（旧版記録）**

**方針変更（確定）:** シナリオの書込みモードは **§10.4 冒頭**のとおり **空き上書き・強制上書きの2種のみ**とする。**`duplicate_append` およびシナリオ単位の行追加モードは本ツールでは提供しない。**

### 10.5 実行制御と例外

- **終了条件:** 走査リストの全ファイル完了、または繰り返し取得で Null / 終了判定に達した時。
- **例外:** ファイルロック（スキップ/リトライ）、型不一致、シート不在（先頭シート代替/エラー）等。

### 10.6 パフォーマンス（非機能・詳細）

- ファイル単位のメモリ解放、マスタへのバッファ書込。
- Excel アプリ非介在で OpenPyXL 等の直接操作を推奨。

### 10.7 中間表現と結合パイプライン（Polars 想定）

1. **列生成:** 項目ごとに値列とパス情報列（**連携キー（セル系）** 等で得た補助列があれば列集合体に含め得る。詳細動作 §1.1・§3.1.5）。同一項目の複数シナリオは縦結合。
2. **キー付与:** **結合キー（AND）** 列を定義済み項目から付与（**連携キー**列はここでの AND キー定義とは別。§2.4）。
3. **全体結合:** 結合キー **AND** で **JOIN**（Polars 優先、未導入時は pandas 等）。
4. **書込:** アクティブシート（または指定）へヘッダ付き出力。
5. **イベントログ:** §10.8 該当行を別シートまたは一覧へ。

**テーブル概念:** 各項目に value と path/source_ref。**結合キー**は指定マスタ項目列の複合（AND）。

**I/O 境界:** 読込は OpenPyXL/csv、中間は Polars、書込は openpyxl または xlwings（既存方針）。

#### 10.7.1 全体結合・実行順・実装指針（推奨案の確定）

以下は §2.0・§10.7 の解釈を実装で一意にするための**推奨案**として本書に反映する。

| # | 論点 | 推奨（確定） |
|---|------|----------------|
| 1 | **全体結合の JOIN 種別** | 既定は **left**（左を項目一覧の**先頭項目**に相当する中間表とし、以降の項目を順に left join）。キー欠損で片側のみの行は残し、欠損列は null とする。厳密な inner のみにしたい場合は将来オプション化してよい。 |
| 2 | **結合の順序** | **項目一覧の上から下**（メイン画面の実行順）に、中間表を **1 本の累積結果へ順次 join** する。 |
| 3 | **結合キー列** | メインで指定する **照合キー（`match_keys`）＝結合キー AND** の列。シナリオ編集の **結合キー取得** で得た値がこれらの列に入る前提とする。 |
| 4 | **複数ファイル・複数ステップ** | 中間表生成段階でファイル単位の行が複数あってよい。全体結合後にマスタ書込みモードを適用する。同一キーでファイルが分かれてくる場合の扱いは、書込みモード（**§10.4 の2種**）に従う。 |
| 5 | **対象ファイル一覧（別画面）** | 当面は **メインのタブ2「検出ファイル一覧」** を正とし、**並び替え・別ウィンドウ・実行中ハイライト**は後続フェーズで拡張してよい（§3.2・画面一覧 No.2 の完全準拠は段階的で可）。 |

**本番一括実行（実装対応・確定）:** `svc_data_agg._run_batch` は次の2段とする。（1）**同一ファイル内**では、抽出・連携キー・結合キー取得（`join_defs` 由来の列＝`join_targets`）により得た行を、結合キー列で統合する（既存の `_merge_rows_by_join_keys`。抽出ロジックは変更しない）。（2）シナリオの **`match_keys` が1件以上** ある場合、各項目の中間行は **照合キー列（`match_keys` を `items[].id` または項目表示名からマスタ列名へ解決した列）＋当該項目の値列** からなり、**項目一覧の上から下**の **項目 id 順**で `frames_by_item` を組み、`svc_data_agg_pipeline.join_on_match_keys` を **how=left** で呼び出して横結合する。**`match_keys` が空**のときは `join_on_match_keys` を呼ばず、（1）の結果のみをマスタ行とする（従来挙動の維持）。

**項目の上下移動と操作者責務（確定）:** マスタ項目の**上から下**が実行順・結合における優先の基準とする。**結合に必要なデータが揃わない**場合の結果（スキップ・欠損・部分結合など）は、**現行結合エンジンの定義に従う**ものとし、**データ整備は操作者責務**とする。事後確認は **§2.4.1・§10.8** のイベントログおよび **結合エラー件数のサマリ表示**で行う。

### 10.8 イベントログ（結合失敗・あふれ）

**記録対象:** キー未取得、JOIN 片側のみ、パス不一致、対象 0 件、シート不在、**照合不一致で既存行へ反映できなかった**等、本番で行確定不可または意図した結合ができなかった場合。

**推奨列:** 時刻、理由コード（例 `NO_KEY`, `JOIN_MISS`, `JOIN_FAIL`, `PATH_MISMATCH`, `NO_FILE`, `NO_SHEET`, `NO_MATCH`）、シナリオID、マスタ項目名、参照パス、キー値。

**ポリシー:** ログのみ、または将来マスタに空行＋フラグ（オプション）。

**完了時の可視化（確定）:** 本番一括実行の**完了通知**（例: `SCREENS.DONE`）またはメイン側の実行結果表示に、**結合エラー（イベントに記録した件数の総数）**を表示する。表示文言・プレースホルダは `config/ui_data_agg.json` で管理する。マスタシートに「結合エラー」専用列を**常設する**必要はない（ログ＋サマリで足りる）。

**デバッグ実行との役割分担:** **本番一括実行**で発生したイベント行の**既定の永続先**は Q1 のとおり **Excel 別シート**（`DataAgg_EventLog`）とする。**デバッグウィンドウ**（§3.1.3）では、同一意味の行を **ログタブ** に **ステップ単位**で追記する（Excel シートへの自動追記は必須としない）。

### 10.9 実装との対応

- **走査:** `svc_data_agg_scan` — 起点・再帰・拡張子・キーワード・一時ファイル除外。
- **シナリオ:** `svc_data_agg_scenario` — JSON 読込・検証・保存、系統排他・**連携キー**・**結合キー**・結合パス（フルパス連携）等。
- **抽出:** `svc_data_agg_extract` — 座標・メタデータ・ファイル名抽出、OpenPyXL/csv。主値・連携・結合の加工は `svc.data_agg_value_post`（チェック・`value_shape_script`）と **`core.core_value_shape`**。名前/パス系と Polars 中間は拡張。
- **結合パイプライン:** `svc_data_agg_pipeline` — `join_on_match_keys`。**Polars 利用時・非利用時（辞書リストフォールバック）の双方**で `how=left` / `inner` を解釈する。本番一括は §10.7.1 に従い **left** を用いる。戻り値のイベント行は **§10.8** に従い本番一括で `DataAgg_EventLog` 等へ出力し、デバッグでは **§3.1.3 ログタブ**へ反映する。
- **一括実行:** `svc_data_agg._run_batch` — 走査・抽出バンドル・ファイル内 `join_targets` 統合の後、`match_keys` があれば `join_on_match_keys` で項目横断結合。`match_keys` の **id／表示名** はマスタ列名へ解決して照合インデックスと結合列を揃える。
- **書込:** `svc_data_agg_write` — **空き上書き・強制上書き**（§10.4）・照合キー行マッチ。キー不一致時の行追加／スキップはメインオプション。イベントログは拡張。
- **終了・例外:** 一括は全ファイル完了で終了。ロック・シート不在等は今後拡張。

### 10.10 実装方針の確定（Q1〜Q4・凍結）

本節の Q1〜Q4 は **プロジェクト方針として確定済み**とする。実装はこの表に従い、解釈の揺れを起こさないこと。

| # | 論点 | **確定方針** |
|---|------|----------------|
| Q1 | **イベントログの出力先** | **本番一括:** アクティブブック内別シート（`DataAgg_EventLog`、重複時は番号付与）。**デバッグ:** **ログタブ**を主表示（`svc_data_agg_write.format_join_events_for_event_log` 互換の EVENT 行）。シートへの複写は任意。 |

| Q3 | **デバッグのログ追記単位** | **ステップ（フェーズ／マスタステップ）ごと**にテキスト追記。結合イベントは **該当処理で発生した分**を EVENT 行で追記。マスタモードの **項目横断ドライラン**は **全項目ステップ完了時に一括**でログへ（§3.1.3.3）。本番の件数サマリは **一括完了通知**（§2.4.1・`MESSAGES`）。 |
| Q4 | ~~**`duplicate_append` のテンプレ列範囲**~~ | **廃止**（§10.4.3）。シナリオ書込みは空き上書き／強制上書きのみ。 |

## 11. 操作手順・画面・ボタン（マニュアル）

### 11.1 全体の流れ

項目読込 → 項目一覧 → 各項目の「編集」でシナリオ編集 → OK（登録）で要約反映 → タブ2でフォルダ/拡張子と検索実行 → **一括実行**（本番）。動作確認は **デバッグ**。出力先は **アクティブシート**（メイン UI の表示に従う）。

### 11.2 メイン画面（項目読込・一覧）

- **アクティブシート1行目 / CSVファイル** で項目定義し、「**取得**」で一覧へ反映（文言キーは §12 `BTN_LOAD_ITEMS` 等）。
- **タブ1「項目・シナリオ」:** 項目名、**編集**（シナリオ編集）、シナリオ要約、**▲上へ / ▼下へ**（実行順は上から下）。
- **シナリオ要約列:** 表示幅で省略され得るため、**ホバーでツールチップに全文を表示する**（シナリオ編集の一覧要約と同趣旨。§3.1 冒頭・§3.1.1）。
- **マスタ周り:** **キー不一致時**（行追加/スキップ）、**指定行で上書き**（0 始まり、空で未使用）。表示ラベルは §12 `MAIN.UI`。
- **制御ボタン:** **シナリオ読込**、**シナリオ保存**、**デバッグ**（§3.1.3・§11.7）、**一括実行**、**キャンセル**。**メインに「ステップ実行」ボタンは置かない**（段階確認はデバッグ）。
- **編集起動時の検索連動:** 項目行の「編集」でシナリオ編集を開く際、タブ2で指定済みの検索条件（基準フォルダ・再帰・拡張子・キーワード）で対象ファイル検索を実施し、得られた一覧をシナリオ編集の候補情報として引き渡す。

### 11.3 シナリオ編集画面（操作）

- **左:** シナリオ一覧表。**追加** / **削除**。行選択で右ペインを編集。
- **要約表示:** シナリオ一覧の要約は必要に応じて省略表示し、全文はツールチップで確認可能とする。
- **右:** **種別**（セル座標から取得 / 名前から取得）、識別（自動）ラベル、詳細ペイン。**登録** / **キャンセル**（文言は JSON の `BTN_OK` 等で変更可）。
- **書込みモード:** 種別直下の一括コンボは**置かない**（§3.1.2）。**各ソースの詳細ブロック内**の書込みモードで設定。
- **連携キー:** **結合キーとは別ブロック**。**セル系**では **主キーと連動した連携キー**（詳細動作 **§3.1.5**）。**名前系**では **連携キー（フルパスで結合）**（**§3.2.3**）。いずれも **連携項目** を含み得る。
- **結合キー:** 画面上は **結合キー** 表記。**セル系**のみ詳細の **結合キー取得** ブロックで設定（詳細動作 **§3.1.6**、AND）。種別直下の「この項目を照合キーに含める」は**廃止**（§3.1.2）。
- **連携項目指定時の表示制御:** **連携項目**で参照元に選ばれたマスタ項目は、詳細動作 §3.1.5 に従い登録・実行から除外し、一覧上で**グレイアウト**する。シナリオ編集と実行対象選択を不可にできるものとする。
- **セル系:** **ファイル名判定**→ファイル名テキスト、ファイル種別（UI は .xls/.xlsx のみ）、シート名判定→シート名テキスト、**主キー**、**連携キー**、**結合キー**、正規化・書込みモード（主キーブロック内）など（§3.1.2・詳細動作 §3.1）。
- **名前系:** 検索条件、文字列抽出、**連携キー（フルパスで結合）**（§3.1.2・詳細動作 §3.2）。JSON 上 **結合パス（関連付け）** とラベルされたブロックはこれに対応し得る。

### 11.4 タブ2（フォルダ/ファイル・検出一覧）

- **基準フォルダ**、**フォルダ選択**、**サブフォルダ含む**、**拡張子**（.xls/.xlsx/.csv）、**キーワード**、**検索実行**。
- **初期フォルダ:** 起動時は `last_folder.txt` の記録値を既定表示とし、フォルダ選択で変更した場合は同ファイルを更新する。
- **検出ファイル一覧:** 走査結果。**一括実行**はメインのボタンから。**デバッグ**はメインまたはシナリオ編集から。

### 11.5 シナリオの保存・読込

- **シナリオ保存:** 現在設定を JSON で保存。
- **シナリオ読込:** 保存ファイルを選択しメインへ反映。必要に応じシナリオ編集で修正。

### 11.6 実行モード（ユーザー向け要約）

- **一括実行（本番）:** 全項目連続処理し、終了時にアクティブシートへ一括出力。
- **デバッグ:** 本番マスタへ書き込まず、**シナリオ編集から開く**場合はシナリオフェーズ文脈、**メインから開く**場合はマスタ項目ステップ文脈（§3.1.3）。モード切替はしない。
- **詳細設計の扱い:** デバッグ内の**表示項目キー名・画面詳細は別フェーズで確定**し得る。本書では実行モードの要件レベル（§3.2）を正とする。

### 11.7 デバッグウィンドウ（§3.1.3）

- **文言・列見出し:** `config/ui_data_agg.json` の **`SCREENS.DEBUG`** を正とする（§12.4 参照）。
- **メイン画面:** 制御ボタン行の **デバッグ** でウィンドウを開く（キー `BTN_DEBUG`）。**既定モードはマスタ項目ステップモード**（§3.1.3 起動表）。
- **シナリオ編集:** 左ペインの **デバッグ** ボタンで同一デバッグウィンドウを開く（実装キーは `BTN_STEP_SCENARIO` 等であり得るが、**ラベル・ツールチップは「デバッグ」に統一**する §12）。**モードはシナリオフェーズに固定**（§3.1.3 起動表）。`live_items` 等で当該項目の実シナリオを引き渡す（§3.1.3.2）。
- **操作:** §3.1.3 のとおり。**モードのユーザー切替は行わない**。結果／ログのクリア規則・シナリオスナップショットに従う。デバッグでは **Excel マスタへ書き込まない**。

### 11.8 操作例

1. **複数ファイルの同一セルを1列に:** 項目追加 → 編集 → ソース追加 → セル座標でシート/セル指定 → 詳細内の書込みモード設定 → 登録 → タブ2で走査 → 一括実行。
2. **ファイル名から日付抽出:** 項目追加 → 編集 → 名前から取得 → 検索・抽出条件設定 → 登録。
3. **キーで既存行更新:** メインで **キー不一致時** を行追加/スキップに設定する。どのマスタ項目を照合／**結合キー（AND）** に含めるかは**マスタ側の既定 UI（項目の複数選択）**で指定する。セル系シナリオでは **結合キー取得** でセル由来のキー成分を定義できる（§2.4）。**連携キー**は **結合キーとは別**（§2.4）。※旧手順の「シナリオ編集画面の照合キーチェック」は廃止（§3.1.2）。
