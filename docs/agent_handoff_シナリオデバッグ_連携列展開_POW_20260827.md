# シナリオデバッグ: 連携キーが項目列に分かれない（POW）

## 事象

| 画面 | 結果 |
|------|------|
| シナリオデバッグ・機器番号_POW | 「連携キー」**1列**に `#1[製品コード]…` `#2[出荷番号]…` が縦積み |
| シナリオデバッグ・機器番号_OPT | 製品コード・出荷番号…と**横に項目列** |
| マスタデバッグ | 項目別に分かれる（期待どおり） |

左ペインの「4. 連携キー」はフェーズ名であり、両シナリオとも正常。問題は**結果一覧の列展開**。

## 原因

### 表示経路の違い

- **マスタデバッグ**: 最初からマスタ項目名が列見出し（別経路）。`#n[項目]` 展開を使わない → POW でも項目別になる。
- **シナリオデバッグ**: フェーズ列（ファイル／シート／主キー／**連携キー**）のあと、連携列の値がすべて `#番号[項目名] 値` なら項目列へ展開する。

### バグの本質（展開の「全件一致」）

`ui_data_agg_debug._rebuild_value_grid_impl` 旧実装:

- 連携列の **1行でも** `#n[名前] …` に合わないと、`groups` を捨てて展開中止
- 結果、見出しが「連携キー」のまま、値が縦に並ぶ（POWの見え方）

同じファイル内の `_parse_hash_bracket_column_values` は形式外を **skip** しており、基準が食い違っていた。

形式外になりやすい例:

- 件数上限の省略行 `…（以降省略・上限N件）`（`#n[名前]` 無し）
- 空行・プレースホルダ混入
- 先頭の想定外文字

OPTは全行が形式どおり → 展開成功。POWは1行以上の形式外（または同等条件）→ 展開失敗、という説明と整合する。

### 連携項目の選択について

製品コード・出荷番号は連携項目名として正しく使われている。未選択が原因ではない。

## 対策

### 実施済み（推奨・本修正）

形式に合う行だけ展開する（形式外は無視してログ）。  
`expand_hash_bracket_value_groups` を追加し、結果グリッド再構築で使用。

- 回帰: `tests/test_data_agg_debug_link_expand.py`
- 省略行が混ざっても製品コード／出荷番号列に分かれることを確認

### 追加で取り得る案（任意）

| 案 | 内容 |
|----|------|
| A | 省略行も常に `#n[項目] …` 形式で出す（生成側の統一） |
| B | 文字列タグではなく `{item: values[]}` の構造化データを UI に渡す（根本） |
| C | 展開失敗時にログ／ヒントで「形式外行あり」を明示 |

## 確認手順

1. シナリオデバッグで機器番号_POWをシナリオ実行（または連携フェーズまで）
2. 結果一覧が OPT と同様、製品コード・出荷番号…の横列になること
3. 主キー行数と各連携列の行が揃うこと（縦に N×件数ぶん伸びないこと）
