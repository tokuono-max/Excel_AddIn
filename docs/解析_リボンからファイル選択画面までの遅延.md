## 遅延の内訳

### 遅延A: 約 3.2 秒（48.179 → 51.341）

**VBA が Python を起動してから、hc_main 側で最初のログが出るまで。**

- 含まれる処理の想定:
  - xlwings 経由の **Python インタプリタのコールドスタート**
  - **import hc_main** およびその依存（core_log, svc_host 等）の初回ロード
- ここが「リボンを押してから何も反応しない」と感じる最大要因の一つ。

**改善の方向性:**
- Python プロセスを**あらかじめ 1 本だけ起動しておき**、VBA からはそのプロセスに依頼だけ送る方式（常駐 Python + ソケット/パイプ等）にすると、2 回目以降はこの 3 秒がほぼゼロになる。
- 現状の「毎回 pythonw を spawn」を変えずに軽くするなら、hc_main の import チェーンを減らす（遅延 import の活用）はあるが、効果は 3 秒全体の一部に限られる。

---

### 遅延B: 約 0.7 秒（51.430 → 52.125）

**svc_server を spawn してから、子プロセスが [BOOT] を出すまで。**

- 子プロセス側の Python 起動 + svc_server の import。
- 1 回目のみ発生。2 回目以降は svc_server が既に動いていれば発生しない。

---

### 遅延C: 約 3.0 秒（52.851 → 55.869）

**svc_server が「exec start action=csv_ld」を出してから、load_csv 内の [START] が出るまで。**

- この間にやっているのは、**ハンドラ取得〜svc_csv_ld の初回 import** とその依存（ui_qt.ipc_file, svc_host, core_* 等）のロード。
- 「handler cached」は 52.849 の時点で出ているので、**実際の遅延は「load_csv を呼ぶ直前までの import 処理」**と考えられる。

**改善の方向性:**
- svc_server 起動時（または最初の req 受信時）に、**csv_ld 用モジュールを先に import しておく**（ウォームアップ）と、2 回目以降の csv_ld 呼び出しではこの 3 秒がほぼゼロになる。
- あるいは、**ui_server を先に起動しておき**、csv_ld の 1 回目は「ファイル選択だけ先に出し、バックグラウンドで load_csv の import を続ける」ような分割は、体感の短縮にはなるが設計変更は大きい。

---

### 遅延D: 約 1.3 秒（55.905 → 57.167）

**ui_server を spawn してから、UI プロセスが [MODULE_LOAD] を出すまで。**

- UI プロセス側の Python 起動 + **Qt / ui_server / ui_csv_ld 等の import**。
- Qt の初期化が重いため、1 秒前後はよくある。

**改善の方向性:**
- **ui_server を 1 本常駐させておく**（ensure_ui_server で「既に起動済みなら spawn しない」は既にあるが、初回は必ずこの 1.3 秒がかかる）。
- アドイン起動時や、最初のリボン操作時に**バックグラウンドで ui_server だけ先に起動**しておくウォームアップを入れると、2 回目以降の「リボン→ファイル選択」が 1 秒以上短くなる。

---

## まとめ

| 遅延 | 秒 | 主な要因 | 改善の方向性 |
|------|-----|----------|----------------|
| A | 約 3.2s | VBA→Python 起動 + hc_main 等の import | Python 常駐化、またはウォームアップ |
| B | 約 0.7s | svc_server 子プロセス起動 | 既存の「1 本起動で使い回し」で 2 回目以降はゼロ |
| C | 約 3.0s | svc_server 内での svc_csv_ld 等の初回 import | 事前に csv_ld 用 import を実行するウォームアップ |
| D | 約 1.3s | ui_server 起動 + Qt 初期化 | ui_server の事前起動（ウォームアップ） |

**体感の「3 秒以上」は、主に遅延A（VBA→Python の 3.2 秒）と遅延C（csv_ld 初回 import の 3 秒）の合算によるもの。**

- **即効で効く対策:**  
  - svc_server 側で、**起動直後に csv_ld / ui 系のモジュールを 1 回 import する**ウォームアップを入れる（遅延Cの解消）。  
  - **ui_server をアドイン起動時などに 1 回だけ先に起動**しておく（遅延Dの解消）。
- **根本対策:**  
  - VBA から「毎回 pythonw を立ち上げる」のをやめ、**常駐 Python プロセス 1 本 + 通信**にすると、遅延A が 2 回目以降ほぼゼロになる。

## Workbook_Open でのウォームアップ（遅延B・D の軽減）

アドイン起動と同時に **svc_server** と **ui_server** を 1 回だけ起動しておくと、**初回のリボン操作**でも遅延B・遅延D（合計約 2 秒）がかからず、体感が良くなる。  
（※遅延A は「リボンを押すたびに新しい Python が起動する」ため、このウォームアップでは解消されない。）

### ThisWorkbook の Workbook_Open() に入れる最適コード（bas は変更不要・コピー用）

モジュール名は **`svc.svc_host`** を使用する（`hc_csv_mg` / `hc_host` は誤り）。

```vba
' アドイン起動時に svc_server と ui_server を事前起動（遅延B・D の軽減）
Private Sub Workbook_Open()
    ' ... 既存の処理 ...

    Dim warmUp As String
    warmUp = "from svc.svc_host import ensure_svc_server, ensure_ui_server; ensure_svc_server(); ensure_ui_server()"
    Call HC_Log.Info("ThisWorkbook", "warmup: " & warmUp)
    On Error Resume Next
    RunPython warmUp
    On Error GoTo 0
End Sub
```

- **1 行で書く場合（RunPython に渡す文字列だけ必要なとき）:**
  ```text
  from svc.svc_host import ensure_svc_server, ensure_ui_server; ensure_svc_server(); ensure_ui_server()
  ```
- これで **svc_server** と **ui_server** が 1 本ずつ起動し、最初のリボン操作時に「子プロセス spawn 待ち」がなくなる。

## 遅延C: 機能別の初回 import とウォームアップ方針

遅延C は **機能（action）ごと**に発生する。  
csv_ld の初回だけが重いのではなく、**各 action の初回**でそのハンドラ（svc_csv_ld / svc_csv_mg / svc_csv_sv …）の import が走る。

- **csv_ld** を初めて使う → svc_csv_ld の初回 import（約 3 秒）
- **csv_mg** を初めて使う → svc_csv_mg の初回 import（同程度）
- **csv_sv / csv_sp / hd_nr / undo** なども同様に、その action の**初回のみ**重い。

### 方針: 全量 import は避け、必要な action だけウォームアップ

- **全てのハンドラを一括 import** すると、svc_server の起動が重くなり**メモリが増え続ける**ため推奨しない。
- **よく使う action だけ**を、svc_server 起動直後に 1 回だけ `_load_handler(action)` する（**ウォームアップリスト方式**）にすると、その機能の初回利用が速くなり、かつメモリは「リストで指定した分だけ」に抑えられる。

### ウォームアップリストを動的にする（運用で変更できるようにする）

リストをコードに直書きせず、**運用時に変更できる**ようにする方法。

| 方法 | 内容 | メリット |
|------|------|----------|
| **JSON 設定（推奨）** | `config/svc_warmup.json` の `warmup_actions` に配列で指定。 | バージョン管理しやすい。コード変更不要で運用変更可能。 |
| **環境変数（フォールバック）** | `HC_SVC_WARMUP_ACTIONS=csv_ld,csv_mg,...`。JSON が無い・不正なときのみ参照。 | JSON を置けない環境で使用。 |
| **利用履歴ベース（将来案）** | 実際に使った action をファイルに記録し、次回起動時にその一覧をウォームアップする。 | 「本当に使う機能だけ」がメモリに乗り、完全に動的。 |

- **実装済み**: svc_server は起動時に **`config/svc_warmup.json`** を読み、`warmup_actions` 配列があればその action だけ順に `_load_handler(a)` を実行する。ファイルが無い・キーが無い・不正な場合は **環境変数 `HC_SVC_WARMUP_ACTIONS`** にフォールバック。どちらも無ければウォームアップなし。

### 結論（「あまり目に見えて早くならない」理由）

| 要因 | 1 回目 | 2 回目 | 備考 |
|------|--------|--------|------|
| 遅延A（VBA→Python 起動） | 約 2.06s | 約 2.03s | **毎回発生。ウォームアップでは減らない。** |
| exec start → [START] load_csv | 約 2.45s | **約 0.03s** | 2 回目はウォームアップで解消。1 回目は _attach_book 初回と推測。 |
| 遅延B・D | 0 | 0 | 事前起動で解消。 |

- **ウォームアップは効いている**: 2 回目は exec start から [START] load_csv が 26 ms になっており、遅延C と「1 回目の _attach_book」は解消されている。
- **体感が変わらない主因**: リボンを押すたびに **新しい Python プロセス**（hc_main）が起動するため、**遅延A（約 2 秒）が毎回必ず残る**。これがクリック〜画面表示の大半を占めている。
- **根本的に短くするには**: VBA から「毎回 pythonw を起動」するのをやめ、**常駐 Python プロセス 1 本に依頼を送る**構成にしない限り、遅延A の約 2 秒は残る。
