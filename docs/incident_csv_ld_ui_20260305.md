# 不具合事例記録：CSV読込(svc_csv_ld) UI 周り

**対象機能**: CSV読込（Qt UI サーバ方式）  
**記録日**: 2026-03-05  
**目的**: 複数発生した不具合の事象・メカニズム・修正方法を記録し、今後の開発に活用する。

---

## 工程3の処理内容（参考）

**工程3** は **列幅調整（オートフィット）** である。

- **処理内容**: CSV で書き込んだ各シートについて、Excel の列幅を自動調整する。
- **実行タイミング**: 工程2（Excelへ書き込み）完了後、工程4（完了）の前に実行される。
- **処理の流れ**:
  1. 書き込み対象シートごとに `_autofit_used_range()` を呼ぶ。
  2. セル数が上限（AUTOFIT_MAX_CELLS）以内なら書き込み範囲全体で `Columns.AutoFit`。
  3. 大範囲の場合は対象シートを Activate し、`ActiveWindow.VisibleRange.Columns.AutoFit` で表示範囲のみオートフィット。取得できない場合は先頭行のみオートフィット（フォールバック）。
- **進捗表示**: 画面には「列幅調整中」または「列幅調整中 (n/m シート)」と表示し、pct は 99% を維持（100% は DONE 時のみ）。

## 不具合事例一覧

### 事例1：進捗画面が枠だけ表示される

| 項目 | 内容 |
|------|------|
| **１．不具合事象** | 進捗画面を表示した際、ウィンドウの枠（タイトルバー・境界）だけが表示され、ラベル（「ファイル解析中」等）や進捗バーが描画されない。1回目の CSV 読込で発生し、2回目以降は正常に表示されるケースや、進捗が消えた直後に枠だけが完了通知と同時に現れるケースがあった。 |
| **２．不具合のメカニズム** | (1) **WA_NativeWindow による描画不全**: `ProgressDialog` で `setAttribute(Qt.WA_NativeWindow, True)` と `winId()` によりネイティブウィンドウ化している。一部環境では、この設定により子ウィジェット（QLabel, QProgressBar）が正しく描画されず、クライアント領域が空白のままになる。(2) **閉じたダイアログの残存**: 進捗を閉じたあと、Qt オブジェクトが破棄されずネイティブウィンドウの枠だけが残り、完了通知表示タイミングで目立つ。 |
| **３．不具合修正方法** | (1) csv_ld の進捗リクエストに `no_native_window: True` を付与し、`ProgressDialog` の `__init__` でこのときは WA_NativeWindow を付けないようにした。Qt の通常描画でラベル・バーを表示。(2) `_close_after_done()` および `closeEvent()` の最後で `self.deleteLater()` を呼び、閉じたダイアログを確実に破棄し、枠だけ残らないようにした。 |

### 事例2：進捗画面が閉じられない／閉じたあと枠だけ残る

| 項目 | 内容 |
|------|------|
| **１．不具合事象** | ユーザーが進捗画面の「×」を押しても閉じられない。または閉じたつもりが、完了通知が表示されるタイミングで枠だけの進捗ウィンドウが再び現れる。 |
| **２．不具合のメカニズム** | (1) **closeEvent の扱い**: 閉じる操作が `event.ignore()` 相当の扱いになっている、または後続処理でダイアログが再表示される可能性。(2) **オブジェクトの未破棄**: 閉じたあとも QWidget が生きており、ネイティブウィンドウハンドルだけが残り、Z オーダーや表示タイミングの影響で「枠だけ」が目立つ。 |
| **３．不具合修正方法** | (1) `closeEvent()` の先頭で `event.accept()` を明示し、閉じるを必ず受理。(2) `_close_after_done()` でタイマー停止 → Excel ロック解除 → `_remove_from_modeless()` → `hide()` → 親の `close()` → `self.close()` の順で実行したあと、`self.deleteLater()` を呼び、オブジェクトを破棄。`closeEvent()` 内でも `_remove_from_modeless()` のあとに `deleteLater()` を追加。 |

### 事例3：オートフィットが効かない

| 項目 | 内容 |
|------|------|
| **１．不具合事象** | CSV 読込後に Excel シートへ出力したが、列幅が自動調整されず、セル内容が切れて見える。 |
| **２．不具合のメカニズム** | (1) **表示範囲限定ロジック**: 当初「アクティブウィンドウの表示範囲のみ」オートフィットする実装だったが、処理直後は対象シートがアクティブでない、または VisibleRange が取得できずスキップされていた。(2) **セル数上限によるスキップ**: 大範囲では AUTOFIT_MAX_CELLS を超えるためオートフィットを丸ごとスキップしており、代替処理がなかった。(3) **先頭行のみの効果不足**: フォールバックで先頭行のみオートフィットしても、表示シートや範囲の取り方によってはユーザーから見て「効いていない」と感じられた。 |
| **３．不具合修正方法** | (1) 大範囲時は対象シートを `sht.activate()` してから `ActiveWindow.VisibleRange` を取得し、その列に対して `Columns.AutoFit` を実行。(2) 小範囲は従来どおり書き込み範囲全体でオートフィット。xlwings の `columns.autofit()` に加え、COM の `rng.api.Columns.AutoFit` をフォールバックで試す。(3) VisibleRange が取れない場合は先頭行のみオートフィット。経路ごとに INFO ログを出し、原因切り分けしやすくした。 |

### 事例4：進捗バーが 99% から 95% に戻る

| 項目 | 内容 |
|------|------|
| **１．不具合事象** | Excel 書き込み中に進捗バーが 99% 付近まで進んだあと、列幅調整（工程3）に移ったタイミングで 95% に戻って見える。 |
| **２．不具合のメカニズム** | 工程2では `pct = int((val_accum_total / val_total) * 100)` で進捗を更新しており、書き込み完了時点で 99% 前後になる。一方、工程3の先頭で「列幅調整中」を出す際に **固定で `pct: 95`** を書き込んでいた。そのため、進捗ファイルを読んだ UI が 99% の直後に 95% を表示し、バーが戻って見えていた。 |
| **３．不具合修正方法** | 工程3の進捗書き込みで、`pct` を 95 から **99** に変更。複数シート時の「列幅調整中 (n/m シート)」の pct も 99 に統一し、工程3中は 99% を維持。100% は DONE 時のみにした。 |

### 事例5：ファイル選択画面で Excel 操作が無効になっていない

| 項目 | 内容 |
|------|------|
| **１．不具合事象** | ファイル選択ダイアログを表示しているあいだ、Excel の操作（セル編集・クリック等）が無効になっていない。また、キャンセルした場合に Excel 操作を有効に戻す必要がある。 |
| **２．不具合のメカニズム** | ファイル選択はネイティブの `QFileDialog.getOpenFileName()` のみを使用しており、表示中に Excel の子ウィンドウを `EnableWindow(False)` する処理が入っていなかった。csv_mg の結合画面では `enable_excel_window` でロックしているが、csv_ld のファイル選択では未実施だった。 |
| **３．不具合修正方法** | ファイル選択を表示する直前に `enable_excel_window(ph, False)` を呼び、Excel 操作を無効化。`getOpenFileName()` を `try` で囲み、`finally` 内で `enable_excel_window(ph, True)` を呼ぶようにした。OK でもキャンセルでも必ず有効化される。 |

### 事例6：ファイル選択で Qt 描画が使われている（Qt を使わない方針との不整合）

| 項目 | 内容 |
|------|------|
| **１．不具合事象** | 「ファイル選択は Qt を使わない」としていたにもかかわらず、WINDOW.DEFAULT_WIDTH/HEIGHT を指定した場合に Qt 描画のファイルダイアログ（DontUseNativeDialog）が使われ、Qt のウィンドウが表示されていた。 |
| **２．不具合のメカニズム** | 表示サイズを JSON で変えられるようにするため、DEFAULT_WIDTH/HEIGHT が両方 > 0 のときに Qt の QFileDialog を生成し、resize して表示する分岐を入れていた。その結果、設定次第でネイティブではなく Qt 描画になり、方針と矛盾していた。 |
| **３．不具合修正方法** | ファイル選択は常にネイティブのみに統一。DEFAULT_WIDTH/HEIGHT による Qt 描画分岐を削除し、`getOpenFileName(parent_widget, ...)` のみを使用。Excel を親にした QWidget を渡すことで、親子関係・アイコンはネイティブのままで維持。config の WINDOW 説明に「csv_ld ではファイル選択に Qt を使わずネイティブのみのため DEFAULT_WIDTH/HEIGHT は未使用」と記載。 |

### 事例7：進捗画面が Excel の中央から右にずれて表示される

| 項目 | 内容 |
|------|------|
| **１．不具合事象** | 進捗画面が Excel ウィンドウの中央ではなく、右にずれた位置に表示される。以前は中央に表示されていた。また、表示後に中央へ移動する様子が目立ち、気になる。 |
| **２．不具合のメカニズム** | (1) **座標系の混在**: Excel の矩形は Win32 `GetWindowRect`（物理ピクセル）、Qt の `move()` は論理ピクセル。マルチモニタや DPI スケールで解釈が異なり右にずれる。(2) **プロセス間の DPI 認識差**: Excel と自プロセスで DPI 認識が異なると、`GetWindowRect` と `SetWindowPos` の座標解釈が揃わない。(3) **枠サイズ**: トップレベルでは `move()` が枠の左上基準なのに、中央計算で `width()`/`height()`（クライアント）を使っていたためずれが生じた。(4) **×ボタン非表示**: SHOW_CLOSE_BUTTON: false で枠の見た目が変わり、ずれが目立った可能性。 |
| **３．不具合修正方法** | (1) **物理ピクセル統一**: `center_on_rect` でダイアログの HWND が取れるときは、`GetWindowRect` で実サイズを取得し、`SetWindowPos` で配置。Qt の `move()` は使わず Win32 のみで座標を統一。(2) **DPI コンテキスト**: `center_on_excel` 実行時に `SetThreadDpiAwarenessContext(PER_MONITOR_AWARE_V2)` でスレッドを物理ピクセルに合わせ、Excel 矩形取得・配置をその中で実行。マルチモニタ＋混在 DPI でずれ防止。(3) **移動が見えないように**: CENTER_ON_EXCEL が true の進捗は、初回 `setWindowOpacity(0)` で透明表示→表示後 150ms で `center_on_excel`→`setWindowOpacity(1)` で不透明化。ユーザーには中央にいきなり表示されたように見える。 |

### 事例8：CSV分割(svc_csv_sp) ワーニング画面を OK で閉じると枠だけ残り Excel 操作が無効のまま

| 項目 | 内容 |
|------|------|
| **１．不具合事象** | ワーニング画面で OK ボタンを押すと一度は閉じるが、枠だけのウィンドウが残り Excel 操作も無効のまま。その枠は × で数回連続クリックしないと閉じられない。× で閉じた場合はきれいに閉じて Excel 操作は有効に戻る。 |
| **２．不具合のメカニズム** | 事例1・2と同様。OK 押下で `accept()` のみだと Qt のモーダルは終了するが、ネイティブウィンドウの破棄が遅れ枠が残る。`closeEvent` 内の `deleteLater()` だけでは、ボタン経由で閉じる経路で hide が走らず枠が一瞬でも残り得る。 |
| **３．不具合修正方法** | (1) **OK 押下時**: `_on_ok()` で先に `hide()` を呼び、そのあと Excel 有効化・`accept()` の順で実行。枠を先に非表示にしてから閉じる。(2) **closeEvent**: 先頭で `event.accept()`、Excel 有効化のあと `hide()` を明示し、続けて `deleteLater()`、最後に `super().closeEvent()`。(3) **破棄の確実化**: `__init__` で `setAttribute(Qt.WA_DeleteOnClose, True)` を設定し、close 時に Qt がオブジェクトを削除するようにする。 |

## 今後の開発への活用ポイント

- **進捗・モーダル系 UI**: WA_NativeWindow は環境によって子ウィジェットの描画を損なう場合がある。不具合時は `no_native_window` のようなオプションで Qt 描画に切り替えられるようにしておく。
- **モデルレスダイアログの破棄**: 閉じたあとも枠が残る場合は、`close()` に加えて `deleteLater()` でオブジェクトを破棄する。
- **進捗の pct の単調増加**: 工程を切り替えるとき、前工程の最後の pct より小さい値を書かないよう、工程ごとの初期 pct を「前工程の終わり」に合わせる（例: 工程3 は 99% から開始）。
- **Excel ロック**: ファイル選択など Excel の前面で別ダイアログを出す場合は、表示中は `enable_excel_window(False)`、終了時（OK/キャンセル両方）は `finally` で `enable_excel_window(True)` とする。
- **オートフィット**: 大範囲では VisibleRange を使う場合、対象シートを先に Activate してから取得する。小範囲・フォールバック・COM 直接呼び出しを組み合わせ、ログで経路を残すと原因切り分けがしやすい。
- **進捗の Excel 中央表示**: マルチモニタ・DPI 混在では Win32 の座標と Qt の論理ピクセルがずれる。`SetThreadDpiAwarenessContext(PER_MONITOR_AWARE_V2)` で物理ピクセルに揃え、`GetWindowRect`＋`SetWindowPos` で配置。中央へ「移動する瞬間」が気になる場合は、初回は opacity 0 で表示し、配置後に opacity 1 にすると見え方でごまかせる。
- **モーダル系の枠残り（OK で閉じる場合）**: 事例8（csv_sp ワーニング）と同様の事象では、ボタン経由で閉じる前に `hide()` を呼び、`WA_DeleteOnClose` と `closeEvent` 内の `hide()`＋`deleteLater()` を組み合わせる。
