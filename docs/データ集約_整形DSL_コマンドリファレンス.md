# データ集約：整形（DSL）コマンドリファレンス

データ集約のシナリオ編集で使う **整形（DSL）** は、取得値に対する**テキスト変換のパイプライン**です。記述は **先頭レベルでカンマ `,` またはセミコロン `;` 区切り**（いずれもトークン境界として同等）で、**左から順に**1コマンドずつ適用されます。

- **実装モジュール:** `core.core_value_shape`
- **JSON 上のキー例:** 主キー・名前取得などは `ui_scenario_source_v1.value_shape_script`、連携キーは `link_defs[].value_shape_script`

役割分担（加工チェックとの関係）は [データ集約_シナリオ編集_正規化と置換.md](データ集約_シナリオ編集_正規化と置換.md) を参照。

---

## 概要

| 項目 | 内容 |
|------|------|
| 適用順 | トークンを左から読み、**コマンド → 引数（あれば）**の単位で逐次適用 |
| 区切り | **先頭レベル**のみカンマ `,` またはセミコロン `;` で分割（入れ子の関数構文はない）。コマンドとコマンドの間を `;` で書き分け可能 |
| クォート | **CSV 方式**。`"` で囲んだ区間は1トークン（区切りの `,` / `;` は無効）。内側の `"` は `""` でエスケープ |
| 検証 | `compile_shape_script` … シナリオの検証・シナリオ編集の登録時など |
| 実行時 | `apply_value_shape` … トークン化・適用で例外が出た場合はログ出力のうえ**元の文字列に近い形で返す**（無言失敗に近い挙動。検証通過を推奨） |
| 長さ上限 | スクリプト全体 **20000 文字**（超過は検証エラー） |

---

## 構文ルール（トークン化）

`tokenize_shape_script` の仕様に従います。

1. 前後の空白・タブ・改行はトークン境界として無視される（クォート内は除く）。
2. 連続する `,` や `;` の間は**空トークン**になり、パース側でスキップされる場合がある。
3. ダブルクォート `"..."` 内のカンマ・セミコロンは**区切りにならない**。
4. `""` はエスケープされた1文字の `"` としてクォート内に含める。

---

## コマンド一覧

コマンド名は **大文字小文字を区別しません**（内部で小文字化して解釈）。

### 表: コマンド・引数・動作

| コマンド | 別名（エイリアス） | 引数 | 動作（要約） |
|----------|-------------------|------|----------------|
| `trim` | なし | なし | 前後の空白を除去（`str.strip`） |
| `split` | なし | `line_1` | **1 始まり**の行番号で、その**行の内容だけ**を返す。区切りは `str.splitlines` と同様（`\n` / `\r\n` / `\r` など）。**返却値に `\n` や `\r` は含めない**（改行は区切りのみ）。行が存在しなければ `""` |
| `rep` | なし | `old`, `new` | `str.replace(old, new)`。**部分一致のすべて**を置換。`old` が空文字のときは置換しない |
| `mid` | なし | `start_1`, `length` | **1 始まり**の開始位置から `length` 文字を抽出。`start_1 < 1` または `length < 0` のときは結果は空に近い扱い。開始位置が文字列長を超えると `""` |
| `cut` | なし | `start_1`, `length` | **1 始まり**位置から `length` 文字を**削除**した文字列を返す |
| `ins` | なし | `pos_1`, `insert` | **1 始まり**の**文字位置の直前**に `insert` を挿入。`pos_1` が長さ+1 を超える場合は末尾に寄せる |
| `padr` | `pad_r`, `padright` | `width`, `pad` | 幅 `width` になるよう **右側** を `pad` の**先頭1文字**で埋める（`str.ljust` 相当＝左寄せ表示用） |
| `padl` | `pad_l`, `padleft` | `width`, `pad` | 幅 `width` になるよう **左側** を埋める（`str.rjust` 相当＝右寄せ表示用） |
| `case` | なし | `mode` | `mode` が `upper` / `lower`（大文字小文字無視）のときのみ変換。それ以外は**変更なし** |
| `wide` | なし | なし | Unicode **NFKC** 正規化（全角・半角などの互換文字の統一） |
| `date` | なし | なし | 日付として解釈できれば **YYYY/MM/DD** に整形。**時刻付き**は日付部に落とし時刻は捨てる。解釈できなければ**入力をそのまま**返す |

### `pad` / `width` の注意

- `width` は0以下のときパッド処理は実質スキップ（元文字列を返す）。
- `pad` が空のときパディング文字は半角スペース1文字として扱われる。

### `date` の解釈順（実装概要）

1. `pandas` が使える場合は `pd.to_datetime` を試す。
2. 失敗時は `datetime.strptime` で次の形式を順に試す:  
   `%Y/%m/%d`, `%Y-%m-%d`, `%Y.%m.%d`, `%Y%m%d`, `%m/%d/%Y`, `%d/%m/%Y`

## 記述例

### プレースホルダ相当（`config/ui_data_agg.json` と同趣旨）

```text
trim,rep,"旧","新",case,upper
```

コマンド境界を読みやすくする例（`,` と `;` は先頭レベルでは同等）:

```text
trim; rep,"旧","新"; case,upper
split;1
```

### クォート内にカンマやダブルクォートを含める

- カンマを含む置換元: `rep,"a,b","x"`
- セミコロンを含む文字列はクォート内にそのまま書ける: `rep,"a;b","x"`
- ダブルクォートを含む文字列: `rep,"He said ""Hi""","X"`（`""` が1つの `"`）

### 数値引数（`split` / `mid` / `cut` / `ins` / `pad*`）

トークンは文字列として渡り、コマンド側で整数解析します。数値でないトークンは `split` / `mid` / `cut` 等では**変換をスキップ**（元の文字列がその段では維持）されます。

### 先頭行だけ取り出す例（`split`）

```text
split,1
```

2 行目: `split,2`。改行の種類が混在していても、区切りとして解釈したあとの行テキストのみが返ります。

## 検証エラー（`compile_shape_script`）

シナリオ保存・読込・登録時など、検証に通すと次のようなメッセージで弾かれることがあります。

| 状況 | メッセージの例（趣旨） |
|------|-------------------------|
| スクリプトが長すぎる | 整形スクリプトが長すぎます（上限 20000 文字） |
| クォート不整合など | トークン化エラー: … |
| 定義にないコマンド | 未知のコマンド: … |
| コマンド位置に整数だけのトークン | 不正なトークン: … |
| `rep` / `split` / `mid` / `cut` / `ins` / `pad*` / `case` の引数不足 | `rep` の引数が不足しています、`split の引数が不足しています` など |
| （空または空白のみ） | エラーなし（適用されない） |

検証は**コマンド名と引数個数のざっくり確認**であり、実行時と100%同じ結果になる保証のためのものではありません。意図どおり動かない場合は実行ログ（`[VALUE_SHAPE]`）も参照してください。
