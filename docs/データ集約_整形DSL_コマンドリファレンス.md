# データ集約：整形（DSL）コマンドリファレンス

データ集約のシナリオ編集で使う **整形（DSL）** は、取得値に対する**テキスト変換のパイプライン**です。記述は **先頭レベルでカンマ `,` またはセミコロン `;` 区切り**（いずれもトークン境界として同等）で、**左から順に**1コマンドずつ適用されます。

- **実装モジュール:** `core.core_value_shape`
- **JSON 上のキー例:** 主キー・名前取得などは `ui_scenario_source_v1.value_shape_script`、連携キーは `link_defs[].value_shape_script`

役割分担（加工チェックとの関係）は [データ集約_シナリオ編集_正規化と置換.md](データ集約_シナリオ編集_正規化と置換.md) を参照。

**セル抽出の適用順（主キー／連携／結合／メタ）:** 文字列化（改行保持）→ 加工チェック → 整形 DSL → **残ったセル内改行を除去** → Excel 文字固定。  
そのため `split(N)`（旧形 `split,N`）でセル内改行の N 行目を採用できる。改行除去は最終正規化であり、整形より前には行わない。結合・照合キー比較（`join_compare_display_key`）は従来どおり除去付き文字列化のまま。

---

## 概要

| 項目 | 内容 |
|------|------|
| 適用順 | トークンを左から読み、**コマンド → 引数（あれば）**の単位で逐次適用 |
| 区切り | **先頭レベル**のみカンマ `,` またはセミコロン `;` で分割。**()` 内およびクォート内では区切らない**。コマンド間を `;` で書き分け可能 |
| コマンド形 | 記述は **() 形を推奨**（`trim()` / `left(3)` / `rep("旧","新")`）。**旧形も可**（`trim` / `left,3` / `rep,"旧","新"`）。混在可 |
| 入れ子 | **() 形の引数内のみ**、既知コマンドを入れ子できる（例: `join(me,"-",left(3))`）。深さ上限あり |
| `me` | () 形の**パラメータのみ**。パイプライン現在値（先頭＝入力、以降＝直前コマンド結果。同一コマンド内の引数同士では不変） |
| クォート | **CSV 方式**。`"` で囲んだ区間は1トークン（区切りの `,` / `;` は無効）。内側の `"` は `""` でエスケープ |
| 検証 | `compile_shape_script` … シナリオの検証・シナリオ編集の登録時など |
| 実行時 | `apply_value_shape` … トークン化・適用で例外が出た場合はログ出力のうえ**元の文字列に近い形で返す**（無言失敗に近い挙動。検証通過を推奨） |
| 長さ上限 | スクリプト全体 **20000 文字**（超過は検証エラー） |

## 構文ルール（トークン化）

`tokenize_shape_script` の仕様に従います。

1. 前後の空白・タブ・改行はトークン境界として無視される（クォート内は除く）。
2. 連続する `,` や `;` の間は**空トークン**になり、パース側でスキップされる場合がある。
3. ダブルクォート `"..."` 内のカンマ・セミコロンは**区切りにならない**。
4. `""` はエスケープされた1文字の `"` としてクォート内に含める。
5. `cmd(...)` のように括弧が付いたトークンは、括弧の対応が取れるまで**1トークン**（内側の `,` / `;` は先頭レベルの区切りにならない）。

## コマンド一覧

コマンド名は **大文字小文字を区別しません**（内部で小文字化して解釈）。

### 表: コマンド・引数・動作

| コマンド | 別名（エイリアス） | 引数 | 動作（要約） |
|----------|-------------------|------|----------------|
| `trim` | なし | なし | 前後の空白を除去（`str.strip`） |
| `split` | なし | `line_1` | **1 始まり**の行番号で、その**行の内容だけ**を返す。区切りは `str.splitlines` と同様（`\n` / `\r\n` / `\r` など）。**返却値に `\n` や `\r` は含めない**（改行は区切りのみ）。行が存在しなければ `""` |
| `left` | なし | `n` または式 | 先頭から `n` 文字（VBA `Left` 相当）。`n < 0` または式評価失敗は変更なし。`n == 0` は `""`。`n` が長さ超えなら全体 |
| `right` | なし | `n` または式 | 末尾から `n` 文字（VBA `Right` 相当）。`n < 0` または式評価失敗は変更なし。`n == 0` は `""`。`n` が長さ超えなら全体 |
| `rep` | なし | `old`, `new` または `N`, `old`, `new` | 2 引数は部分一致の**すべて**を置換。3 引数のとき `N` は**先頭から最大 N 回**（回数）。`old` が空のときは置換しない |
| `mid` | なし | `start_1`, `length`（式可） | **1 始まり**の開始位置から `length` 文字を抽出。式評価失敗は変更なし。`start_1 < 1` または `length < 0` のときは結果は空に近い扱い。開始位置が文字列長を超えると `""` |
| `cut` | なし | `start_1`, `length`（式可） | **1 始まり**位置から `length` 文字を**削除**した文字列を返す。式評価失敗は変更なし |
| `ins` | なし | `pos_1`（式可）, `insert` | **1 始まり**の**文字位置の直前**に `insert` を挿入。式評価失敗は変更なし。`pos_1` が長さ+1 を超える場合は末尾に寄せる |
| `padr` | `pad_r`, `padright` | `width`, `pad` | 幅 `width` になるよう **右側** を `pad` の**先頭1文字**で埋める（`str.ljust` 相当＝左寄せ表示用） |
| `padl` | `pad_l`, `padleft` | `width`, `pad` | 幅 `width` になるよう **左側** を埋める（`str.rjust` 相当＝右寄せ表示用） |
| `upr` | なし | なし、または 1（`me`／入れ子／リテラル） | 大文字化。引数なしは現在値。`upr(me)` / `upr(left(3))` 可（旧 `case(upper)` は廃止） |
| `low` | なし | なし、または 1（同上） | 小文字化。`low(me)` / 入れ子可（旧 `case(lower)` は廃止） |
| `tok` | なし | `sep`, `N` | `sep` で分割し **1 始まり** `N` 番目。範囲外は `""`。`sep` が空（`""`）のときは**分割せず現在値のまま** |
| `lenstr` | なし | なし、または 1（同上） | 文字長を**文字列**で返す（例 `"5"`）。`lenstr(left(3))` 可。数値式の `len()` / `len("…")` とは別 |
| `wide` | なし | なし | Unicode **NFKC** 正規化（全角・半角などの互換文字の統一） |
| `date` | なし | なし | 日付として解釈できれば **YYYY/MM/DD** に整形。**時刻付き**は日付部に落とし時刻は捨てる。解釈できなければ**入力をそのまま**返す |
| `join` | なし | 可変（0個以上） | 引数を順に文字列連結して**その結果を新しい現在値にする**。**現在値は自動では混入しない**（必要なら `me` を引数に書く）。`join()` は `""`。各引数は **join 開始時点の同じ現在値** を見る（引数の結果で次引数の現在値は変わらない）。旧形 `join,a,b,…`（次の裸コマンド手前まで）も正式サポート。推奨は `join(...)` |

### `()` 形・`me`・入れ子

- 例: `trim()` / `split(1)` / `left(pos("G")-1)` / `rep("旧","新")` / `upr()` / `tok("_",2)` / `lenstr()`
- **`me`:** **() 形のパラメータ（引数）のみ**。意味はパイプラインの**現在値**  
  - DSL 先頭コマンドの引数では **入力**（チェック直後）  
  - 以降は **直前コマンドの結果**  
  - **同一コマンド内**の引数同士では現在値は進まない（すべてそのコマンド開始時の値）
- 先頭レベルの裸 `me` は**未知のコマンド**（検証エラー）。実行時は適用されず値は維持
- **入れ子:** () 引数内の既知コマンド。入力は外側開始時の現在値（＝その場の `me` と同じ）。結果は引数の文字列になるだけ
- 入れ子例: `join(me,"-",left(3))` … 現在値 + `-` + 現在値の左3文字（`me` も `left(3)` も同一の現在値）
- 同一現在値の例: `join(trim(),"|",me)` on `"  ab  "` → `"ab|  ab  "`（`me` は trim 後ではない）
- 数値引数の `pos(...)` / `len(...)` は**式**であり、整形コマンドの入れ子ではない（長さを結果に出すのは `lenstr`）

### 引数個数（検証）

- **不足**（例: `split()` / `left`）→ 検証エラー
- **0 引数コマンドへの余分**（例: `trim("x")` / `wide(1)`）→ 検証は通し、実行時は余分を**無視**
- 可変長の `join` は 0 個以上（不足という概念なし）

### `pad` / `width` の注意

- `width` は0以下のときパッド処理は実質スキップ（元文字列を返す）。
- `pad` が空のときパディング文字は半角スペース1文字として扱われる。

### `date` の解釈順（実装概要）

1. `pandas` が使える場合は `pd.to_datetime` を試す。
2. 失敗時は `datetime.strptime` で次の形式を順に試す:  
   `%Y/%m/%d`, `%Y-%m-%d`, `%Y.%m.%d`, `%Y%m%d`, `%m/%d/%Y`, `%d/%m/%Y`

## 記述例

### プレースホルダ相当（`config/ui_data_agg.json` と同趣旨）

```text
trim();rep("旧","新");upr()
```

旧形も可（混在例）:

```text
trim; split(1); join(me,"-",left(3))
```

コマンド境界を読みやすくする例（`,` と `;` は先頭レベルでは同等）:

```text
trim(); rep("旧","新"); upr()
split(1)
```

旧形での同等例:

```text
trim; rep,"旧","新"; upr
split;1
```

### クォート内にカンマやダブルクォートを含める

- カンマを含む置換元: `rep("a,b","x")`（旧形: `rep,"a,b","x"`）
- セミコロンを含む文字列はクォート内にそのまま書ける: `rep("a;b","x")`
- ダブルクォートを含む文字列: `rep("He said ""Hi""","X")`（`""` が1つの `"`）

### 数値引数と式（`left` / `right` / `mid` / `cut` / `ins`）

第1引数（および `mid` / `cut` の第2引数）は **整数リテラル** または **式** を取れます。

| 式 | 意味 |
|----|------|
| `pos("…")` | マーカーの**先頭一致・左端位置（1 始まり）**。大文字小文字区別。見つからなければ**そのコマンドをスキップ** |
| `len()` | 現在の文字列の長さ |
| `len("…")` | クォート内リテラルの文字数 |
| `＋` / `－` / `( )` | 式内の算術（足し算・引き算・括弧） |

- 式の上限: **200 文字**、括弧の深さ **8**
- 式の構文エラー・`pos` 未検出時も **そのコマンドだけスキップ**（値は維持）
- `split` / `pad*` は従来どおり整数リテラルのみ

記述例（文字列 `ABCDEFGHIJK`）:

```text
left(pos("GH"))        → ABCDEFG
left(pos("GH")-1)      → ABCDEF
left(len()-pos("I"))   → AB
ins(pos("G"),"123")    → ABCDEF123GHIJK（G の直前）
ins(pos("G")+1,"123")  → ABCDEFG123HIJK（G の直後）
```

旧形でも同等（例: `left,pos("GH")-1`）。

### その他の数値引数（`split` / `pad*`）

トークンは文字列として渡り、コマンド側で整数解析します。数値でないトークンは **変換をスキップ**（元の文字列がその段では維持）されます。

### 先頭行だけ取り出す例（`split`）

```text
split(1)
```

旧形: `split,1`。2 行目: `split(2)`。改行の種類が混在していても、区切りとして解釈したあとの行テキストのみが返ります。

シナリオ編集の **DSLテスト** 画面では、テスト用文字列・結果の**表示高さは 2 行固定**（Enter／貼り付け／カーソルで複数行可。はみ出しはスクロール）。右ペインのコマンド説明は縦いっぱい。`split` の確認に用いる。

## 検証エラー（`compile_shape_script`）

シナリオ保存・読込・登録時など、検証に通すと次のようなメッセージで弾かれることがあります。

| 状況 | メッセージの例（趣旨） |
|------|-------------------------|
| スクリプトが長すぎる | 整形スクリプトが長すぎます（上限 20000 文字） |
| クォート不整合など | トークン化エラー: … |
| 定義にないコマンド | 未知のコマンド: … |
| コマンド位置に整数だけのトークン | 不正なトークン: … |
| `rep` / `split` / `left` / `right` / `mid` / `cut` / `ins` / `pad*` / `tok` の引数不足 | `rep` の引数が不足しています、`split の引数が不足しています` など |
| `left` / `right` / `mid` / `cut` / `ins` の式が不正 | `left の引数が不正です: …` など |
| （空または空白のみ） | エラーなし（適用されない） |

検証は**コマンド名と引数個数のざっくり確認**であり、実行時と100%同じ結果になる保証のためのものではありません。意図どおり動かない場合は実行ログ（`[VALUE_SHAPE]`）も参照してください。
