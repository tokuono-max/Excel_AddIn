# 配布: 薄いインストーラ（メール）と共有フォルダ正本

本書は、**メール等で容量の小さいセットアップのみ配布**し、**本体は社内共有フォルダ（UNC）に置く**方式と、**更新の自動検知と「今／後で」の操作者判断**を整理する。

**インストール先のディレクトリ構成・EXE 配置・環境変数**は `docs\hc_mainのEXE化.md`（同書セクション 5・6・7 等）を正とする。**開発PC**で Excel 起動時に `HC_*` を切り替えるバッチは同書 **セクション 2.6**（`tools\dev\`）。本書は **配布経路と更新 UX** に焦点を当てる。

**Inno Setup の `Files` ソース** … **`docs\Exe化（開発者向け）.md`** の **セクション 3.5.1・5** に従い、一括ビルド後の **`dist\CSV_Tool\`** は **`app\bin\` 集約**のステージングである。`config\`・`addin\`・**`xlwings.conf`** は配布正本／インストール工程で補い、**`xlwings.conf`** はインストーラで **`{app}` 基準に再生成**する（同書 **セクション 3.8・7.1**）。

## 0. 製品方針（決定・2026-04-18）

`docs\UpDate.md` のたたき台と突き合わせ、**第1版の前提**として次を決定した。

| 項目 | 決定内容 |
|------|-----------|
| **インストールの優先** | **薄いインストーラ**を **第1版で優先**（メール配布・共有の `current` 等からローカル `{app}` へ取り込む。早期検証）。**`installer\CSV_Tool.iss`** のように **ステージングを丸ごと `{app}` へ展開する形**は **後続または併用**（ビルド検証・別経路の配布用）。 |
| **ユーザー環境（配布既定）** | インストール完了時に **`HKCU\Environment`** へ **`HC_INSTALL_ROOT`**（**ユーザーが確定した `{app}` の絶対パス**。既定パスから変更されても追従。§1.3）と **`HC_PACKAGED_DEPLOYMENT=1`** を書く。通常起動の Excel で **環境変数経由の配布モード**が既定になる（§1.4）。 |
| **アンインストール** | インストール時に書き込んだ **`HC_INSTALL_ROOT` / `HC_PACKAGED_DEPLOYMENT` を `HKCU\Environment` から削除**する（Inno の **`[Registry]`** で `uninsdeletevalue` 等。値の除去＝当該レジストリエントリの削除。§1.3）。 |
| **更新カタログ（第1版）** | 共有側の案内ファイルは **`catalog.json` のみ**を正とする（§4）。`version.txt` 単体のみの最小運用は第1版では採用しない。 |
| **ローカル版（いま入っている版）** | **`{app}\VERSION.txt` を第一**とする。無い・読めないとき **Inno が登録するアンインストール情報の `DisplayVersion` 等（レジストリ）をフォールバック**する。優先順位は実装で固定し、ブレないようにする。 |
| **「後で」（通知のスヌーズ）** | **永続スヌーズは行わない**（日時・回数をレジストリや `%AppData%` に保存しない）。「後で」は **当該セッションでダイアログを閉じる**程度とし、**次回アドイン起動時やリボンからの手動チェック**で再度 `catalog.json` と比較する。 |
| **版チェックの実装** | **Python（`hc_main`）中心**。`catalog.json` の取得・版比較・通知判定は **同一モジュール／関数**に寄せ、**アドイン起動時**と**リボンからの明示実行**の両方から呼ぶ（`docs\UpDate.md` F-2 と整合）。 |
| **更新適用の分離** | **初回は `bin + config` をインストーラで一括導入**。以後は **`config` をサイレント更新（失敗時のみ通知）**、**`bin` は UI で「今すぐ／後で」**を選ばせる。`bin` の「今すぐ」は **Excel 終了後に適用**。 |
| **正本の管理単位** | 配置先 `{app}` は 1 本のままにしつつ、**共有正本と更新パッケージは `bin` / `config` を分離管理**する（§2・§4.2）。 |

### 0.1 インストール・版情報の要約（運用イメージ）

**薄いインストーラの目標形** … **（フォルダまたは URL から）本体アーカイブを取得 → インストール先 `{app}` に展開 → `HKCU\Environment` の `HC_*` と `xlwings.conf` 等**、という流れで問題ない。

**現状の実装（`installer\CSV_Tool_Setup.iss`）** … コンパイル時に固定した **`SHAREPAYLOAD` パス上のフォルダ**を **`robocopy` で `{app}` へコピー**する。**`HKCU\Environment` に `HC_DEPLOY_ROOT`（`SHAREPAYLOAD` の親）も書く**（§1.5）。**zip 展開・URL からの取得は未実装**（zip／URL に寄せる場合はスクリプト拡張が必要）。

**バージョンアップ通知** … **`core.packaged_update`** が **アドイン起動時**（配布モード時）と **リボン「更新確認」**（`RunPython`）で **`catalog.json` と `{app}\VERSION.txt` を照合**し、**新しい版があれば通知**する（実ファイルの上書きは **Excel 終了後**のインストーラ再実行・zip 展開等。§1.5・§3・§5）。

**版情報の置き場（通知を成立させるために）**

| 側 | 内容 |
|----|------|
| **配布側（インストール元）** | **`catalog.json` の `latest_version`** 等。zip 運用なら **zip 内のツリーに `VERSION.txt` を含める**など、**「最新がいくつか」が分かる**こと。 |
| **インストール先** | **`{app}\VERSION.txt` を第一**、無ければ **Inno `DisplayVersion` 等（レジストリ）**（§0 表）。**両側そろわないと**「最新と比較して通知」ができない。 |

**バージョンが「決まる」タイミング**

- **`VERSION.txt`** … **そのリリースのステージング／zip 内容が固まったとき**（現在は `dist\CSV_Tool\app\bin` 集約を前提）。正本を共有に出す作業と同じタイミングでよい。
- **`catalog.json` の `latest_version`** … **共有に載せる／更新するとき**に、上記と**同じ製品版**へ揃える。
- **Inno の `AppVersion`** … **インストーラをコンパイルするとき**（`#define MyAppVersion`）。

**運用の一文** … **リリース作業で製品版を 1 本決め、`VERSION.txt`・`catalog.json`・Inno を同じ SemVer に揃える**（将来はリポジトリに **単一の正本**を置きビルドで伝播させるとズレが減る）。

## 1. 薄いインストーラと共有上の正本

**目的**: メールでは **容量の小さいブートストラップ（Inno Setup 等のセットアップ EXE）** だけを配り、**数百 MB 級の本体**は社内 **共有フォルダ（UNC）** に置いてインストール時に取り込む。

| 役割 | 典型の置き場所 | 内容 |
|------|----------------|------|
| **正本（大きい）** | `\\fileserver\releases\CSV_Tool\...` 等 | 現在は **`app\bin\` 集約**を中心に配布。必要に応じて `config\`・`addin\`・`VERSION.txt` を同梱し、`xlwings.conf` はインストール先で再生成。 |
| **薄いインストーラ** | メール添付・社内ポータル | 共有パスを読み、ローカル（例: `C:\Program Files\Excel_Addin\CSV_Tool`）へコピー、`HC_INSTALL_ROOT` / `HC_PACKAGED_DEPLOYMENT`、`xlwings.conf` 生成、アンインストール登録 |

### 1.1 Inno Setup 側で行うこと（概念）

- **薄いインストーラ（テンプレート）** … リポジトリの **`installer\CSV_Tool_Setup.iss`**。共有の **`current`**（等）から **`robocopy`** で `{app}` へ取り込み、**`HKCU\Environment`** の **`HC_INSTALL_ROOT`** / **`HC_PACKAGED_DEPLOYMENT`**、**`xlwings.conf` の `{app}` 向け再生成**、アンインストール時の **`{app}` 削除**（`[UninstallDelete]`）まで含む。**コンパイル**: Inno の **ISCC**（**`/DSHAREPAYLOAD=\\server\share\...\current`** で既定 UNC を上書き可）。**管理者＋HKCU** 時の注意は Inno の **UsedUserAreasWarning**（`.iss` 先頭コメント参照）。
- 共有上のファイルを **`{app}` 以下へ再帰コピー**（または共有に **単一 zip** を置き、インストーラが展開してから配置）。
- ハードリンク化済みの正本を配る場合は、**コピー先のボリューム内でのみリンク関係が維持**される点に注意する（別ボリュームへ移すと通常コピーになる）。
- **`HC_INSTALL_ROOT`** を **確定後の `{app}`**（ウィザードでユーザーが選んだルート）に、**`HC_PACKAGED_DEPLOYMENT=1`** を **`HKCU\Environment`** に書く（**§0**・**§1.3**）。マシン全体（HKLM）は本製品の既定では使わない。詳細は `docs\environment_variables.md`。
- **アンインストール時**に、上記 **`HC_*` を `HKCU\Environment` から削除**する（§0・§1.3）。
- ルートの **`config\*.json`**（`ui_*.json`、`svc_warmup.json` 等）は **`HC_INSTALL_ROOT\config\`** に置けば **`core_cst.resolve_config_file_path`** により **最優先で読まれる**（各 `app\...\config\` はフォールバック。`hc_mainのEXE化.md` **セクション 2.7**）。
- **`xlwings.conf`** を **`{app}` 基準の絶対パス**で生成（短寿命ランナーの `INTERPRETER_WIN` 等。`hc_mainのEXE化.md` **セクション 7.1**）。
- **`AppId` を固定**し、同一製品として **再実行＝上書き更新**できるようにする。
- 共有にアクセスできない場合は **明示的なエラー**（VPN・ドライブ割当・権限の案内）。

### 1.1.1 インストーラ作成手順（Step by Step）

以下は **`installer\CSV_Tool_Setup.iss`** を使った、配布用インストーラ作成の実施手順。

1. **正本を準備する**
   - 共有またはローカル検証用に `current` を用意（現行前提: `app\bin\...`、必要なら `config\`・`addin\`・`VERSION.txt` を同梱）。
   - `app\bin\hc_main.exe` が存在することを確認する。
2. **版情報を揃える**
   - `VERSION.txt`、`catalog.json.latest_version`、`CSV_Tool_Setup.iss` の `MyAppVersion` を同じ SemVer に合わせる。
3. **Inno Setup スクリプトを確認する**
   - `installer\CSV_Tool_Setup.iss` の `DefaultDirName`（既定: `C:\Program Files\Excel_Addin\CSV_Tool`）を確認。
   - 権限方針（`PrivilegesRequired` / `PrivilegesRequiredOverridesAllowed`）を運用に合わせる。
4. **`SHAREPAYLOAD` を決める**
   - 本番は UNC（例: `\\fileserver\releases\CSV_Tool\current`）を使用。
   - ローカル検証は `C:\...\current` を使ってよい。
5. **ISCC でコンパイルする**
   - 既定の `SHAREPAYLOAD` を使う場合:
     - `ISCC.exe installer\CSV_Tool_Setup.iss`
   - コンパイル時に上書きする場合:
     - `ISCC.exe /DSHAREPAYLOAD=\\server\share\CSV_Tool\current installer\CSV_Tool_Setup.iss`
6. **生成物を確認する**
   - `dist\` 配下にセットアップ EXE が生成されること。
   - 実行前に SmartScreen／署名ポリシーに抵触しないか確認する。
7. **スモークテストを実施する**
   - 生成 EXE を実行し、インストール先を既定／変更の両方で確認する。
   - 展開後に `app\bin\hc_main.exe` があること、`xlwings.conf` が `{app}` 基準で再生成されることを確認する。
8. **環境変数と更新導線を確認する**
   - `HKCU\Environment` に `HC_INSTALL_ROOT` / `HC_PACKAGED_DEPLOYMENT` / `HC_DEPLOY_ROOT` が設定されること。
   - `catalog.json` 参照・更新通知（起動時／リボン）の基本動作を確認する。
9. **アンインストール検証を実施する**
   - アンインストール後に `HC_*` が削除されること、`{app}` の残置がないことを確認する。

**配布前チェック（最終）**

- 共有 `current` の内容と、実際に生成したインストーラの想定が一致している。
- `catalog.json` の `latest_version` と同じ版を配布している。
- エラー時の案内（VPN/UNC/権限）とログ確認先（`{app}\logs\hc_update.log`）を手順書へ明記している。

### 1.2 権限とアクセス文脈（重要）

- セットアップを **管理者として実行**すると、**昇格したプロセスからはユーザーの mapped drive が見えない**ことがある。UNC（`\\server\share\...`）を使うか、**管理者不要の per-user インストール**にして共有と同じユーザー文脈で読む、のいずれかを運用で決める。

#### 1.2.1 「管理者権限を使うか」をユーザーに選ばせる場合

- Inno Setup では、`[Setup]` の **`PrivilegesRequiredOverridesAllowed=dialog`** を使うと、ウィザードで **インストールモード（all users / current user）** を選ばせる構成にできる。
- これは **UAC ダイアログそのもの**ではない。UAC は Windows 側の昇格確認であり、必要になったタイミングで OS が表示する。
- つまり体験としては、**(1) Inno のモード選択** → **(2) 必要時のみ Windows の UAC 確認**、の 2 段階になる。
- 既定を `C:\Program Files\...` にする運用では、通常は **管理者権限が必要**になりやすい。`current user` を選べる設計にする場合は、インストール先既定値や書き込み先（`HKCU` / `HKLM`）を併せて整合させる。
- 1 本のインストーラで両モードを許可する場合、`{app}` と `HC_INSTALL_ROOT` の一致、アンインストール時の `HC_*` 削除、共有アクセス経路（UNC）をモード別に確認する。

### 1.3 インストール先の既定値とユーザー変更（`{app}` 連動）

**ウィザードで既定パスを示し、ユーザーが変更できるか**

- **できる。** Inno Setup では **`[Setup]` の `DefaultDirName`** で **初期のインストール先**を定め、**ディレクトリ選択ページ**でユーザーが別フォルダに変えられる（**`DisableDirPage=yes`** にしない限り）。
- パスを **固定したい**運用だけ、ディレクトリページを無効化する等で制限する。

**ユーザーがインストール先を変えたときに連動すべきもの**

最終的なインストールルートは Inno の **`{app}`**（ユーザーが確定したパス）である。**ビルドマシン上の絶対パスをそのまま残さない**こと。

| 対象 | 方針 |
|------|------|
| **`[Files]` の `DestDir: "{app}"`** | 追加対応は不要。**ファイルは常に確定後の `{app}` 配下**へ展開される。 |
| **`HKCU\Environment` の `HC_INSTALL_ROOT`** | **`{app}` を展開した絶対パス**を書く（`[Registry]` で `ExpandConstant('{app}')` 等）。ユーザーがパスを変えれば **書き込まれる値もそのパスに一致**する。 |
| **`xlwings.conf`** | **`INTERPRETER_WIN` 等、`{app}` 配下の EXE を指す行はすべて**、インストール時に **`{app}` 基準で生成または置換**する（`[INI]`、`[Code]`、またはテンプレ＋後処理）。ステージングからコピーする場合も **インストール完了時の `{app}`** で上書きする。 |
| **その他 `{app}` 依存の絶対パス** | ショートカット・カスタムコマンド等も **`{app}` 定数**で統一し、**手作業の固定パスを混ぜない**。 |

**運用上の注意**

- **`HC_INSTALL_ROOT` を常に実際の `{app}` と一致**させれば、`core_cst.resolve_config_file_path`（`config\` の正本）とも齟齬が出にくい。
- **`HKCU\Environment` を更新した直後**、**起動済みの Excel** は古い環境のままのことがある。**インストール完了後に Excel を一度終了してから**使い始める案内があるとよい（§1.4 の環境ブロックの話と同趣旨）。
- **アンインストール**では、**当該インストールで書いた `HC_*` だけ**を削除し、別パスへ再インストールしたときに **古い `HC_INSTALL_ROOT` が残る**事故を防ぐ（Inno の `uninsdeletevalue` 等）。

### 1.4 環境変数・レジストリと配布／開発の切替

**仕組み（Windows）**

- **永続のユーザー環境変数**（コントロールパネルや `setx`、PowerShell の `SetEnvironmentVariable(..., "User")` で設定したもの）は、多くの場合 **レジストリ `HKCU\Environment`** に保存される。
- ログオン後、エクスプローラーなど **ユーザーのシェルから起動するプロセス**は、その情報を含んだ **環境ブロック**を引き継ぐ（厳密にはプロセス生成時に親からマージされるが、**「ユーザー環境がプロセスの環境変数として載る」**と理解すればよい）。
- **Excel や xlwings／Python はレジストリのキーを直接読んでモードを切り替えているわけではない。** 参照するのは **そのプロセスに渡っている環境変数**（`HC_INSTALL_ROOT`、`HC_PACKAGED_DEPLOYMENT` 等。VBA の `Environ`、Python の **`os.environ`** と同じ源）。

**インストーラでできること**

- Inno Setup の **`[Registry]`** 等で **`HKCU\Environment`**（または方針に応じてマシン環境）に **`HC_INSTALL_ROOT`** / **`HC_PACKAGED_DEPLOYMENT`** を書く、というのが **配布先で「特別なバッチなしで配布モード」にする一般的なやり方**のひとつ。
- **環境変数を恒久的にユーザーへ付けたい**とき、Windows 標準の保存先は上記のとおり **レジストリとセット**になることが多い（「環境変数だけ触り、レジストリは触らない」は **セッション限定の `set`** なら可能だが、**ログオフ後も残す**なら通常は HKCU\Environment 等を経由する）。

**現状のリポジトリ**

- **`installer\CSV_Tool.iss`**（フルパッケージを `{app}` に展開）は、**現時点では `HKCU\Environment` への `HC_*` 書き込み・アンインストール時の削除を含まない**。**§0** の方針に合わせ、**薄いインストーラの Inno スクリプト**および **`CSV_Tool.iss` の両方**で、順次 **`[Registry]`** 等による追記・削除を入れる想定（本節は挙動の説明）。

**一覧: 永続設定 × Excel の起動方法 → 実質どちらのモードか**

以下では **配布モード**を「`HC_PACKAGED_DEPLOYMENT` が真として解釈され、かつ `HC_INSTALL_ROOT` がインストール先ルートを指す」とし、**開発モード**を「上記が効かない、または開発用バッチでセッション上クリアされリポジトリ／venv 側が使われる」とざっくり呼ぶ（`xlwings.conf` も絡む。詳細は `hc_mainのEXE化.md`）。

| 永続のユーザー環境（例: インストーラが `HKCU\Environment` に書いたか） | Excel の起動方法 | 実質のイメージ |
|------------------------------------------------------------------------|------------------|----------------|
| **書いていない**（`HC_*` なし） | スタートメニュー等、**環境をいじらない**経路 | **開発／既定寄り**（配布用 `HC_*` が無いため EXE 常駐経路に乗りにくい） |
| **書いていない** | **`tools\dev\start_excel_dev.bat`** 等で `HC_*` をクリアした **同じ CMD から** Excel | **開発** |
| **書いていない** | **`start_excel_packaged_test.bat`** 等で `HC_*` をセットした **同じ CMD から** Excel | **配布（試験）**（ルートはバッチの指定次第） |
| **配布用 `HC_*` を書いた** | スタートメニュー等、**環境をいじらない**経路 | **配布** |
| **配布用 `HC_*` を書いた** | **開発用バッチ**でクリアした **同じ CMD から** Excel | **開発**（**その起動だけ**親プロセスの環境が優先される） |
| **配布用 `HC_*` を書いた** | **配布試験用バッチ**で再度セットした **同じ CMD から** Excel | **配布**（試験用パスを明示できる） |

**補足**

- 切替の本体は **「CMD であること」ではなく「Excel を起動する親プロセスの環境ブロック」**である。PowerShell で `$env:HC_...` を整えてから Excel を起動しても同じ考え方。
- **レジストリでユーザー環境を変えた直後**は、**すでに起動中の Excel** は古い環境のまま。**Excel をいったん終了してから**開き直すと新しい値が反映されやすい。
- **開発PCでインストーラを試す**場合: インストーラが `HKCU\Environment` に配布用を書けば **通常起動は配布**、**`start_excel_dev.bat` 経由**なら **そのセッションは開発**に戻せる。

### 1.5 配布ルート `HC_DEPLOY_ROOT` と `catalog.json`（実装済み・2026-04-17）

## 3. 更新の自動検知と操作者への通知（「今／後で」）

**方針**: 専用の常駐アップデータを最初から作らず、**アドイン起動時およびリボンからの手動**で共有の **`catalog.json`** を読み、ローカル版と比較する（**§0**）。比較・判定は **Python（`hc_main`）に集約**する。

| 項目 | 第1版の前提（§0 と整合） |
|------|---------------------------|
| **カタログ** | 共有ルートの **`catalog.json` のみ**（§4） |
| **ローカル版** | **`installed_bin_version` / `installed_config_version` を分離管理**（実体は `{app}` 配下の版情報ファイル、または既存 `VERSION.txt` + 補助情報） |
| **初回導入** | **UI ありインストーラで `bin + config` を一括導入** |
| **config 更新** | **サイレント適用**（原則通知なし）。**失敗時のみ通知 + ログ** |
| **bin 更新** | **UI で「今すぐ／後で」**を提示。「今すぐ」は **Excel 終了後**に更新処理を実行 |
| **「後で」** | **永続スヌーズは行わない**（§0）。ダイアログを閉じるのみで、**次回起動／手動チェックで再判定** |

### 3.1 実装の置き場所

- **版チェックの本体**は **Python（`hc_main`）**。`catalog.json` 取得・版比較・分岐は **同一コード**とする。
- **呼び出し経路**は **アドイン読み込み時（起動時）に一度**、および **リボンからの明示操作**（**§0**）。
- **ユーザーへの通知**は **VBA `MsgBox`**、**Qt／`ui_server` のダイアログ**等、既存 UI に合わせてよいが、**判定ロジックは VBA に複製しない**（Python 結果を表示する形を推奨）。
- **共有にアクセスできない**とき: **起動時の自動チェック**は **メッセージなし**でスキップ（ログのみ）。**リボンからの手動**では **一言メッセージ＋ログ**（§1.5）。

### 3.2 注意（ファイルロック）

- `CSV_Tool.xlam` や EXE が実行中のまま上書きすると失敗しうる。**「今」更新は Excel 終了後**を必須にする。

### 3.3 運用ルール（初回 / config / bin）

| 区分 | 更新方式 | ユーザー体験 | 失敗時 |
|------|----------|--------------|--------|
| **初回** | 薄いインストーラで `bin + config` 導入 | ウィザード操作（保存先選択可） | エラー表示して中断 |
| **config VerUp** | `catalog.json` 判定後にサイレント上書き | 通知なし（成功時） | 通知あり + ログ (`{app}\logs\hc_update.log`) |
| **bin VerUp** | `catalog.json` 判定後に UI で選択 | 「今すぐ / 後で」選択 | 通知あり + ログ |

**判定順（推奨）**

1. `catalog.json` を取得  
2. `config` の互換性を確認（例: `min_bin_version`）  
3. `config` 更新が必要ならサイレント適用  
4. `bin` 更新が必要なら「今すぐ / 後で」を表示  
5. 「今すぐ」選択時は Excel 終了を確認してから `bin` 更新を実行

### 3.4 運用決定事項（2026-05-09）

更新運用に関する追加合意を以下で固定する。実装・運用・サポートで解釈を揃えること。

| 項目 | 決定内容 |
|------|-----------|
| **更新時のモード** | **初回インストールで確定したモード（Current user / All users）を継承**する。更新処理中にモード変更は行わない。 |
| **モード識別の保存先** | Uninstall キー（`{AppId}_is1`）配下の独自値 **`InstallScope`**（`current` / `all`）を参照する。**書き込みは通常側のみ**（`Software\Microsoft\Windows\CurrentVersion\Uninstall\{AppId}_is1`）。**`Software\WOW6432Node\...` 配下には書き込まない**。書き込みタイミングは Inno の Uninstall キー再生成の後（インストーラ `[Code]` の `ssPostInstall` で `WriteInstallScopeToUninstallKey` が実行）。新規レジストリキーは追加しない。 |
| **DisplayName（プログラムと機能）** | インストールモードで切替: Current user → **`CSV Tool (User)`**、All users → **`CSV Tool (All User)`**。 |
| **再インストール時の残骸掃除** | インストーラ起動時（`[Code]` の `ssInstall`）に反対モードの `_is1` キーと `HC_*` 環境変数を削除（`CleanupCrossModeRemnants`）。Current user 起動時の HKLM 残骸は権限不足のため警告ログのみ。 |
| **モード変更の手段** | モード変更が必要な場合は **再インストールのみ**。アップグレード経路での切替は対象外。 |
| **操作者の操作量** | **最小化方針**とし、必要情報のみ通知する。通常は自動判定・自動適用（config）を優先し、判断が必要な場面（bin 適用可否、UAC 等）のみ操作を求める。 |
| **`config.min_bin_version` の扱い** | 互換下限として使用する。**ローカル bin 版が下限未満なら config 更新を適用しない**（bin 更新を優先）。 |
| **旧版バックアップ** | **作成しない**（速度優先）。適用前の `full_prev_*.zip` は廃止。 |
| **旧版ロールバック** | **行わない**。失敗時は再試行または再インストールを案内する。 |
| **bin 適用経路** | **差分（patch）→ 失敗・不適格時はフル（full）へフォールバック**。 |
| **更新成功の定義** | **`bin + bootstrap` の双方成功**を更新成功とみなす。 |
| **UAC 拒否時の扱い** | 昇格を拒否した場合は **今回の適用を defer** し、次回起動時に再確認する（非昇格継続はしない）。 |
| **起動時チェックの排他** | 起動時に `pending` がある場合は **予約適用のみ実行**し、同一起動内で通常バージョンチェックは実行しない。`defer` 時も同様に通常チェックは再開しない。 |

補足:

- `catalog.json` 解決順（`HC_CATALOG_PATH` → `config\catalog_path.txt` → `HC_DEPLOY_ROOT\catalog.json`）は変更しない。
- 詳細な実装ハンドオフは **`docs\agent_handoff_更新運用方針_20260509.md`** を参照（バックアップ／半自動復旧の記述は本節の現行方針を優先）。
- 受け入れテスト最小セットは **uac-strict-7**（Current/All、`min_bin_version`、Program Files+UAC、patch→full、起動時排他/defer 抑止）。

## 4. `catalog.json` のフィールド例（参考）

実際のキー名は実装に合わせてよい。例:

| フィールド | 意味 |
|------------|------|
| `latest_version` | 例: `"1.4.2"` |
| `min_supported` | 任意。互換破壊時に **強制更新**や**起動ブロック**の判定に使う |
| `payload_unc` または `current_relative` | 正本の UNC または `catalog` からの相対パス（例: `current`） |
| `release_notes_url` | 任意。社内 Wiki 等（本リポジトリの更新確認では **未参照**。変更内容は `config/ui_help.json` の `VER_HISTORY`。正は **`インストールと運用` §4.0**） |
| `files_sha256` | 任意。**改ざん・取り違え対策**にファイルごとのハッシュ |

### 4.1 初回（フル）と更新（差分 zip）の分岐

**方針**: **初回インストール**は **フル**（セクション 5 相当のツリー全体）。**更新**は原則 **差分 zip**（変更・追加ファイルのみ）を `{app}` に上書き展開し、**転送量と共有 I/O を抑える**。条件不成立時は **フルにフォールバック**する。

#### 分岐表（実装の優先順位イメージ）

| 順 | 条件 | 採用する成果物 | 備考 |
|----|------|----------------|------|
| 1 | **`{app}` が無い／`hc_main.exe` が無い／`VERSION.txt` も読めず版不明** | **フル** | **初回**扱い。フォルダ `robocopy`（現行 `CSV_Tool_Setup.iss`）または **フル zip 展開**（将来実装）。 |
| 2 | **インストール済み** かつ **`latest_version` > installed** かつ **`catalog.patch`（差分 zip）あり** かつ **installed が `patch.from_min_version` 以上**（任意で **`patch.from_max_version` 以下**） | **差分 zip** | `{app}` へ **上書き展開**。**Excel 終了後**に実行（§3.2）。**削除ファイル**は zip 差分に含めない限り残る（後述）。 |
| 3 | 上記以外で **`latest_version` > installed**（例: installed が差分の下限未満、`min_supported` 未満、**差分エントリなし**） | **フル** | **丸ごと差し替え**推奨（既存 `{app}` バックアップは運用で検討）。 |
| 4 | **`catalog` が読めない／オフライン** | **なし**（スキップ） | §3 のとおり黙ってスキップまたはメッセージのみ。 |

**補足ルール（推奨）**

- **差分 zip の中身**は **`{app}` ルートからの相対パス**（例: `app\bin\hc_main.exe`）と一致させ、**zip 内に余計な親フォルダを挟まない**。
- **ファイル削除**が必要なリリースは **差分ではなくフル**にするか、**別途「削除リスト」**をマニフェストで渡す（未実装ならフルへ）。
- **リンク構造（ジャンクション／ハードリンク）を大きく変える**リリースは **フル**を推奨。
- **SHA256**: `patch` / `full` の各 **`sha256`** に **期待ハッシュ**を載せ、展開前に検証する（§5 と整合）。

#### `catalog.json` 拡張例（フル zip／差分 zip 併用）

既存の `latest_version` 等に加え、**共有ルートからの相対パス**で **zip を指す**（UNC ルートはコードまたは別設定で固定でもよい）。

```json
{
  "schema_version": 2,
  "latest_version": "1.5.0",
  "min_supported_version": "1.4.0",
  "release_notes_url": "https://intranet.example/releases/1.5.0",
  "full": {
    "relative_path": "releases/CSV_Tool_1.5.0_full.zip",
    "sha256": "<64桁hex>"
  },
  "patch": {
    "relative_path": "releases/CSV_Tool_1.4.x_to_1.5.0_delta.zip",
    "sha256": "<64桁hex>",
    "from_min_version": "1.4.0",
    "from_max_version": "1.4.99"
  },
  "folder_current_relative": "current"
}
```

| フィールド | 意味 |
|------------|------|
| `full` | **フル**成果物（**zip 推奨**。フォルダ運用なら `folder_current_relative` のみでよい）。 |
| `full.relative_path` | `catalog.json` の親フォルダからの相対パス。 |
| `patch` | **差分 zip**。**`from_min_version` ≤ installed ≤ `from_max_version`**（`from_max_version` 省略時は上限なし）のときのみ採用。 |
| `folder_current_relative` | **初回／フルでフォルダ robocopy** する場合の `current` 相当（現行インストーラと整合）。zip フルに移行後は **`full` のみ**でもよい。 |

### 4.2 `bin` / `config` 分離運用の `catalog.json` 例

`catalog.json` は 1 本のまま、**更新対象を `bin` と `config` に分けて定義**する。  
運用の意図は次のとおり。

- **`config`**: サイレント適用（失敗時のみ通知）
- **`bin`**: 「今すぐ / 後で」UI を出し、今すぐ時は Excel 終了後に適用

```json
{
  "schema_version": 3,
  "bin": {
    "latest_version": "1.6.0",
    "full": {
      "relative_path": "releases/bin_1.6.0_full.zip",
      "sha256": "<64hex>"
    },
    "patch": {
      "relative_path": "releases/bin_1.5.x_to_1.6.0_delta.zip",
      "sha256": "<64hex>",
      "from_min_version": "1.5.0",
      "from_max_version": "1.5.99"
    }
  },
  "config": {
    "latest_version": "2026.04.20",
    "payload": {
      "relative_path": "releases/config_2026.04.20.zip",
      "sha256": "<64hex>"
    },
    "min_bin_version": "1.5.0"
  }
}
```

**補足**

- `config.min_bin_version` を満たさない場合は、`config` の自動適用を行わず `bin` 更新を優先する。
- `config` は差分でもフルでもよいが、途中破損回避のため **一時ファイル→置換（atomic）** を推奨する。
- 配置先は `{app}` のままでよく、**分離するのは正本管理と更新判定**である。

**zip の形式**: **汎用の zip でよい**（エクスプローラーの「送る」→圧縮、7-Zip、PowerShell の `Compress-Archive` 等）。専用フォーマットや自己解凍は不要。

**zip 作成時の注意**:

- **ルート構造**: zip を展開したあと、**インストール先（`HC_INSTALL_ROOT`）直下**に期待どおりのツリーが並ぶようにする。実装（フル zip の展開先）と **`catalog.json` の `relative_path`** が矛盾すると、二重フォルダや欠落の原因になる。
- **ジャンクション／リパースポイント**: 共有正本・成果物 zip では **原則使わない**。含める場合、展開環境によっては追従しない・壊れることがある。
- **パス長**: 深い階層では **MAX_PATH（約 260 文字）** に抵触しやすい。長いパス前提で運用する場合は、展開・コピー側の対応と合わせて設計する。
- **文字コード**: **`catalog.json` は UTF-8（BOM なし推奨）**。zip 内のパスに、環境によって問題になりうる文字が混ざっていないか確認する。

**実装メモ**: 現行 **`CSV_Tool_Setup.iss`** は **フォルダ `robocopy` のみ**。**zip 展開**は **更新処理**（Python／補助スクリプト／別 Inno）で行う想定。分岐判定は **`hc_main` 側の共通関数**に集約する（`docs\UpDate.md` §0）。
